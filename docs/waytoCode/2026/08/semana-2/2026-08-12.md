### Ejercicio 2 — `GET /tareas` (ruta + controller) — ✅ Completado (1 fallo)

!!! failure "❌ Código de Pau (primer intento)"

    ```php
    public function index(TareaRepository $tarea): Response
    {
        $lista = $tarea->findAll();
        return $this->render('tareas/index.html.twig', ['lista' => $lista]);
    }
    ```

!!! success "✅ Versión corregida (nombre semántico)"

    ```php
    public function index(TareaRepository $tareaRepository): Response
    {
        $lista = $tareaRepository->findAll();
        return $this->render('tareas/index.html.twig', ['lista' => $lista]);
    }
    ```

🧠 **Lección:** el parámetro no era una `Tarea`, era el `TareaRepository` completo — `$tarea` (singular) sugería una entidad cuando en realidad daba acceso a todas. Primer instinto fue `$em` (convención de `EntityManagerInterface`, tipo y responsabilidad distintos), después `$repository` (pierde de qué entidad es). El nombre correcto cuenta la misma historia que el tipo declarado. Detalle: Fallo 18 en `GOTCHAS.md`.

### Ejercicio 3 — `GET /tareas/{id}` con ParamConverter — ✅ Completado (3 fallos en una línea)

!!! failure "❌ Código de Pau (primer intento)"

    ```php
    #[Route('/tareas{id}', name: 'app_tareas')]
    public function buscar(TareaRepository $tareaRepository, $id): Response
    {
        $lista = $tareaRepository->find($id);
        return $this->render('tareas/index.html.twig', ['lista' => $lista]);
    }
    ```

!!! success "✅ Versión corregida (ParamConverter)"

    ```php
    #[Route('/tareas/{id}', name: 'tarea_id')]
    public function buscar(Tarea $tarea): Response
    {
        return $this->render('tareas/show.html.twig', ['tarea' => $tarea]);
    }
    ```

🧠 **Lección:** (1) `name` repetido con la ruta del Ejercicio 2 — Symfony no arranca con dos rutas del mismo nombre. (2) `/tareas{id}` sin barra matchea `/tareas5`, no `/tareas/5`. (3) El wildcard `{id}` activa el ParamConverter/`EntityValueResolver`: declarar `Tarea $tarea` directo hace que Symfony resuelva el `find($id)` y el 404 solo — el patrón manual ya no hace falta. Detalle: Fallo 19 en `GOTCHAS.md`.

### Ejercicio 4 — `tareas/index.html.twig` — ✅ Completado (3 fallos en una línea)

!!! failure "❌ Código de Pau (primer intento)"

    ```twig
    {% for tareas in tarea %}
        <li>{{tarea}}</li>
    {% else %}
        <p>No hay productos a mostrar</p>
    {%endfor%}
    ```

!!! success "✅ Versión corregida"

    ```twig
    {% for tarea in lista %}
        <li>{{tarea.title}}</li>
    {% else %}
        <p>No hay tareas a mostrar</p>
    {%endfor%}
    ```

🧠 **Lección:** (1) `tarea` no existía en el contexto — el controller pasa `lista`. (2) El `for` estaba invertido: `tareas` (plural) como variable de vuelta y `tarea` (singular) como colección, al revés de `for item in coleccion`. (3) `{{ tarea }}` imprime el objeto entero, sin `__toString()` — hace falta `tarea.title`. Detalle: Fallo 20 en `GOTCHAS.md`.

### Ejercicio 6 — `POST /tareas` — crear con EntityManager — ✅ Completado (varios fallos acumulados)

!!! failure "❌ Código de Pau (primer intento)"

    ```php
    public function crear(Request $request, EntityManagerInterface $em, Tarea $tarea): Response
    {
        $titulo = $request->get('title');
        $tarea = new Tarea();
        $tarea->setTitle($titulo);
        $tarea->setDone(false);
        $tarea->setCreatedAt(new \DateTimeInmutable());
        $em->persist($tarea);
        $em->flush();
        return "tarea creada!";
    }
    ```
    Ruta: `#[Route('/tareas/crear', name: 'tarea_crear', method: 'POST')]`

!!! success "✅ Versión corregida"

    ```php
    #[Route('/tareas/crear', name: 'tarea_crear', methods: 'POST')]
    public function crear(Request $request, EntityManagerInterface $em): Response
    {
        $titulo = $request->query->get('title');
        $tarea = new Tarea();
        $tarea->setTitle($titulo);
        $tarea->setDone(false);
        $tarea->setCreatedAt(new \DateTimeImmutable());
        $em->persist($tarea);
        $em->flush();
        return $this->redirectToRoute('app_tareas');
    }
    ```

🧠 **Lección:** primer uso del EntityManager en el proyecto, y salió todo junto: faltaban los `use` de `Tarea`/`Request`; un `Tarea $tarea` de más como parámetro (sin `{id}` en la ruta, ParamConverter no tiene de dónde resolverlo — 500 antes de ejecutar nada); `DateTimeInmutable` en vez de `DateTimeImmutable` (nombre de clase en inglés); `return` de un `string` suelto con el método tipado `: Response`; y `method` en vez de `methods` en el atributo `#[Route]`. Detalle: Fallo 22 en `GOTCHAS.md`.

### Ejercicio 7 — `POST /tareas/{id}/completar` — ✅ Completado (2 fallos)

!!! failure "❌ Código de Pau (primer intento)"

    ```php
    #[Route('/tareas/{id}/completar}', name: 'tarea_completada', methods: 'POST')]
    public function tareaCompletada(Tarea $tarea): Response
    {
        $tarea->setDone(true);
        flush();
        return $this->redirectToRoute('app_tareas');
    }
    ```

!!! success "✅ Versión corregida"

    ```php
    #[Route('/tareas/{id}/completar', name: 'tarea_completada', methods: 'POST')]
    public function tareaCompletada(Tarea $tarea, EntityManagerInterface $em): Response
    {
        $tarea->setDone(true);
        $em->flush();
        return $this->redirectToRoute('app_tareas');
    }
    ```

🧠 **Lección:** llave de más en la ruta (`completar}`). Y un fallo silencioso: `flush()` sin `$em->` es una función real de PHP (buffer de salida) — no tira error, pero tampoco guarda nada. El `setDone(true)` cambiaba el objeto en memoria y se perdía porque nunca se llamaba al `flush()` de Doctrine (faltaba inyectar `EntityManagerInterface`). Detalle: Fallo 23 en `GOTCHAS.md`.

### Ejercicio 9 — QueryBuilder — `findPendientes()` — ✅ Completado (varios fallos acumulados)

!!! failure "❌ Código de Pau (intentos sucesivos)"

    ```php
    ->andWhere('n.done = :valor')
    ->setParameter('n.done')              // falta el valor, y el nombre no es el del placeholder

    ->orderBy('t.id', 'ASC')              // alias "t" no existe (el alias es "n")
    ->setMaxResults(10)                   // no lo pedía el enunciado

    ->orderBy('n.createdAt', 'DES')       // typo, falta la C
    ```

!!! success "✅ Versión corregida"

    ```php
    public function findPendientes(): array
    {
        return $this->createQueryBuilder('n')
            ->andWhere('n.done = :valor')
            ->setParameter('valor', false)
            ->orderBy('n.createdAt', 'DESC')
            ->getQuery()
            ->getResult();
    }
    ```

🧠 **Lección:** el nombre del placeholder (`:valor`) es arbitrario, no tiene relación con la propiedad comparada (`n.done`) — `setParameter` lo rellena por ese nombre, con el valor que pide la lógica del método (`findPendientes` → `false`, no `true`). El alias de `orderBy` tiene que coincidir con el definido en `createQueryBuilder('n')`. Detalle: Fallo 24 en `GOTCHAS.md`.

### Ejercicio 10 — Twig `include` — ✅ Completado (3 fallos)

!!! failure "❌ Código de Pau (primer intento)"

    ```twig
    {# _item.html.twig #}
    {% extends 'index.html.twig' %}
        <li>{{tarea.title}}</li>
        {% if tarea.done %}...{% endif %}
    ```
    ```twig
    {# index.html.twig #}
    {% include 'templates/tareas/_item.html.twig' with {tarea} %}
    ```

!!! success "✅ Versión corregida"

    ```twig
    {# _item.html.twig — sin extends #}
    <li>{{tarea.title}}</li>
    {% if tarea.done %}...{% endif %}
    ```
    ```twig
    {% include 'tareas/_item.html.twig' with {tarea: tarea} %}
    ```

🧠 **Lección:** un parcial pensado para `include` no lleva `extends` — `extends` hereda una estructura entera (páginas completas), `include` inserta un fragmento chico. Tal como estaba, además, hubiera sido circular (`index` incluye a `_item`, `_item` extiende a `index`). Las rutas de Twig son relativas a `templates/`, no hay que repetir ese prefijo. Y Twig no tiene shorthand de objetos como JS (`{tarea}`) — siempre `clave: valor` explícito. Detalle: Fallo 25 en `GOTCHAS.md`.

## 🔎 Por qué fallaron — resumen del día

- **Ejercicio 2:** naming — nombró el parámetro como si fuera una entidad, cuando era el repositorio completo.
- **Ejercicio 3:** tres detalles de sintaxis/routing juntos (nombre duplicado, barra faltante, no usar ParamConverter) — no un vacío conceptual, se resolvió a la primera al ver el ejemplo.
- **Ejercicios 4 y 5:** el mismo error conceptual dos veces — confundir cuándo una plantilla Twig recibe una colección (`for`) y cuándo recibe un objeto único (sin `for`). Costó una explicación completa (analogía "lista de la compra vs. un producto ya elegido") para que se fijara, y aun así reapareció al copiar la plantilla siguiente sin repensar el caso.
- **Ejercicio 6:** primer uso del EntityManager — acumuló varios detalles nuevos de una vez (imports, ParamConverter mal aplicado, typo de clase, tipo de retorno, nombre del parámetro de rutas).
- **Ejercicio 7:** fallo silencioso — `flush()` sin `$em->` no tira error pero tampoco guarda nada.
- **Ejercicio 8:** sin fallos — la lección del Ejercicio 7 se aplicó directo.
- **Ejercicio 9:** confundir el nombre del placeholder de QueryBuilder con el de la propiedad comparada, más un alias inventado y un límite no pedido.
- **Ejercicio 10:** confundir `extends` con `include` — mismo tipo de error conceptual que el de Twig for/objeto único (Ejercicios 4-5), pero en un concepto distinto.

**Patrón general:** los fallos de PHP/routing fueron mecánicos (naming, sintaxis, imports) y se corrigieron con un solo aviso. Los fallos conceptuales de Twig (colección vs. objeto único, `extends` vs. `include`) necesitaron explicación completa — y el primero de los dos reincidió. El fallo silencioso del `flush()` es el más importante a interiorizar: no tirar error no significa que funcione.
