### E1 — `ejecutarSiPositivo(numero, callback)` — ✅ Completado (1 fallo)

!!! failure "❌ Código de Pau (primer intento)"

    ```js
    function ejecutarSiPositivo(numero, callback) {
       if(numero > 0) return numero * 2;    // ❌ ignora "callback", hardcodea *2
       return null;
    }
    ```

!!! success "✅ Versión corregida (usa el callback de verdad)"

    ```js
    function ejecutarSiPositivo(numero, callback) {
      if (numero <= 0) return null;
      return callback(numero);
    }
    ```

🧠 **Lección:** el parámetro `callback` estaba en la firma pero nunca se usaba dentro de la función — se hardcodeó `numero * 2` en su lugar. Pasaba el test de casualidad, porque el único callback de prueba era justo `n => n * 2`; con otro callback (`n => n + 100`) hubiera fallado. Mismo patrón de "condición que acierta por casualidad" que E1/E5/P3 del Día 10 (`GOTCHAS.md`).

---

### E2 — `repetir(n, callback)` — ✅ Completado (1 fallo)

!!! failure "❌ Código de Pau (primer intento)"

    ```js
    function repetir(n, callback) {
        let array = [];
        for (let i = 0; i < n - 1; i++) {   // ❌ off-by-one: corta un paso antes
            array.push(callback(i));
        }
        return array;
    }
    ```

!!! success "✅ Versión corregida (sin el -1 extra)"

    ```js
    function repetir(n, callback) {
        let array = [];
        for (let i = 0; i < n; i++) {
            array.push(callback(i));
        }
        return array;
    }
    ```

🧠 **Lección:** off-by-one. `i < n` ya excluye `n` por sí solo (por el `<`), así que ya se detiene exactamente en `n - 1`. Restar `-1` manualmente excluye el límite dos veces y corta el loop un paso antes de tiempo. El enunciado ("desde 0 hasta n-1") describe el ÚLTIMO VALOR que toma `i`, no algo que haya que restar en la condición. Teoría #off-by-one ya anotada en `GOTCHAS.md`.

## 🔎 Por qué fallaron — resumen del día

- **E1:** el parámetro `callback` estaba en la firma pero nunca se llamaba — hardcodeó `numero * 2` a mano. Pasaba el test por casualidad (el callback de prueba era justo `*2`).
- **E2:** off-by-one clásico — restó `-1` en la condición del loop cuando `i < n` ya excluye `n` por sí solo.
- **E3, E4, E6:** closures resueltos sin fallos — el patrón "variable afuera + función que la recuerda" ya quedó claro desde la teoría.
- **E5:** sin fallos de código, pero necesitó aclarar en el momento que un closure tiene DOS parámetros de DOS funciones distintas (uno fijo al crear, otro nuevo en cada llamada).

**Patrón general:** los fallos de hoy fueron mecánicos (no usar un parámetro, off-by-one), no conceptuales — los closures en sí (la parte nueva de la teoría) se entendieron bien desde el primer intento.
