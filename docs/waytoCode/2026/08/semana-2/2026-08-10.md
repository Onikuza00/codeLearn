### E1 — `contarPropiedades(objeto)` — ✅ Completado (2 fallos)

!!! failure "❌ Código de Pau (primer intento)"

    ```js
    function contarPropiedades(objeto) {
      let propiedades = Object.keys.objeto;                              // ❌ acceso por punto, no invoca la función
      return propiedades.length !== 0 ? propiedades.length : null;       // ❌ ternario redundante (ambas ramas dan lo mismo)
    }
    ```

!!! success "✅ Versión corregida (invocar la función + sin ternario redundante)"

    ```js
    function contarPropiedades(objeto) {
      let propiedades = Object.keys(objeto);
      return propiedades.length;
    }
    ```

🧠 **Lección:** `Object.keys` es una función, se invoca con paréntesis y el argumento adentro (`Object.keys(objeto)`) — no se accede como propiedad con punto. Y un ternario donde las dos ramas terminan devolviendo lo mismo es redundante (mismo patrón que "V1 al menos uno", `cond ? true : false`): si `propiedades.length` ya es `0` cuando está vacío, `propiedades.length !== 0 ? propiedades.length : 0` es literalmente `propiedades.length`.

### E3 — `clavesConValor(objeto, valorBuscado)` — ✅ Completado (con guía, le costó — Fallo 14)

!!! failure "❌ Código de Pau (intentos sucesivos)"

    ```js
    // Intento 1 — filter necesita una función, no un valor
    return lista.filter(valorBuscado);

    // Intento 2 — los pares no tienen propiedad .values
    return lista.filter(n => n.values === valorBuscado);

    // Intento 3 — Object.keys sobre un array da sus índices (0,1...), no las claves de adentro
    let buscados = lista.filter(n => n[1] === valorBuscado);
    return Object.keys(buscados);
    ```

!!! success "✅ Versión corregida (destructuring en filter + map para extraer la clave)"

    ```js
    function clavesConValor(objeto, valorBuscado) {
      let lista = Object.entries(objeto);
      let buscados = lista.filter(([clave, valor]) => valor === valorBuscado);
      return buscados.map(([clave, valor]) => clave);
    }
    ```

🧠 **Lección:** los pares de `Object.entries()` son arrays `[clave, valor]` — se acceden por índice (`par[0]`/`par[1]`) o destructuring (`([clave, valor]) => ...`), nunca con notación de punto tipo `.values`. Y `Object.keys/values/entries` siempre operan sobre el objeto que les pasás directamente: si ya tenés un array intermedio (filtrado, mapeado) y necesitás algo de adentro de cada elemento, la herramienta es `map`/`filter`, no volver a llamar `Object.keys` sobre ese array. Detalle también en **Fallo 14** de `GOTCHAS.md`.

### E5 — `ciudadSegura(persona)` — ✅ Completado (1 detalle: ternario redundante)

!!! failure "❌ Código de Pau (funcionaba, pero repetía la expresión)"

    ```js
    function ciudadSegura(persona) {
      return persona.direccion?.ciudad ? persona.direccion?.ciudad : "Desconocida";   // ❌ expresión repetida + falta ?. en "persona"
    }
    ```

!!! success "✅ Versión corregida (?. en toda la cadena + ??)"

    ```js
    function ciudadSegura(persona) {
      return persona?.direccion?.ciudad ?? "Desconocida";
    }
    ```

🧠 **Lección:** cuando un ternario repite la misma expresión en ambos lados solo para chequear "¿existe?", es la señal de usar `??` (nullish coalescing) en su lugar — una sola expresión, sin repetir nada. Documentado en [Optional chaining](/js/03-objetos/04-optional-chaining/) junto con el gotcha `??` vs `||` (mismo tipo de trampa que arrays truthy: `||` cae ante cualquier falsy, `??` solo ante `null`/`undefined`).

## 🧩 Proyecto — Sistema de puntuación con objetos

> 💡 **Apunte:**

> - **Con fallos:** P1 `sumarPuntos`, P2 `jugadorGanador`, P3 `promedioPuntos` — detalle abajo.

### P1 — `sumarPuntos(sistema, jugador, puntos)` — ✅ Completado (con guía, varios intentos)

!!! failure "❌ Código de Pau (intentos sucesivos)"

    ```js
    // Intento 1 — SyntaxError: redeclara "puntos" + sintaxis de objeto inválida
    let puntos = {...sistema, jugador, puntos = 0}

    // Intento 2 — [jugador] crea un array, no lee sistema[jugador]; y ?? se aplica DESPUÉS del +
    let points = [jugador]+puntos ?? 0;
    ```

!!! success "✅ Versión corregida (acceso correcto + paréntesis explícitos)"

    ```js
    function sumarPuntos(sistema, jugador, puntos) {
      let nuevoTotal = (sistema[jugador] ?? 0) + puntos;
      return { ...sistema, [jugador]: nuevoTotal };
    }
    ```

🧠 **Lección:** `sistema[jugador]` lee la propiedad; `[jugador]` solo (sin el objeto delante) crea un array nuevo. Y con `??` + operaciones aritméticas, los paréntesis no son opcionales: `(sistema[jugador] ?? 0) + puntos` fuerza a resolver el "existe o no" ANTES de sumar — sin paréntesis, `??` actúa después de la suma y el resultado puede dar `NaN` en vez de `0` para jugadores nuevos. Mismo gotcha de precedencia que la teoría #7 de `GOTCHAS.md`: en caso de duda, paréntesis.

### P2 — `jugadorGanador(sistema)` — ✅ Completado (con guía, le costó — Fallo 15)

!!! failure "❌ Código de Pau (el reduce explota antes de llegar al chequeo)"

    ```js
    function jugadorGanador(sistema) {
      let players = Object.entries(sistema);
      let ganador = players.reduce((mejor, i) => i[1] > mejor[1] ? i : mejor);   // ❌ explota si players=[] (sin valor inicial)
      return ganador ? ganador[0] : null;                                        // ❌ este chequeo nunca se alcanza en ese caso
    }
    ```

!!! success "✅ Versión corregida (chequeo de vacío ANTES del reduce)"

    ```js
    function jugadorGanador(sistema) {
      let players = Object.entries(sistema);
      if (players.length === 0) return null;
      let ganador = players.reduce((mejor, i) => i[1] > mejor[1] ? i : mejor);
      return ganador[0];
    }
    ```

🧠 **Lección:** `reduce` recibe una función callback como argumento — `acumulador` y `elementoActual` son los parámetros de esa función, no dos argumentos sueltos de `reduce`. Y "acumular" no es sinónimo de sumar: el acumulador también sirve para comparar y elegir uno solo. Sin valor inicial, el chequeo de array vacío va SIEMPRE antes de llamar `reduce`, nunca como condición sobre el resultado — ver Fallo 15 en `GOTCHAS.md` y la sección nueva ["Acumular no es sinónimo de sumar"](/js/02-arrays/04-transformacion/) en la teoría de `reduce`.

### P3 — `promedioPuntos(sistema)` — ✅ Completado (mismo patrón que E1/E5, sin Fallo nuevo)

!!! failure "❌ Código de Pau"

    ```js
    function promedioPuntos(sistema) {
      let puntos = Object.values(sistema);
      let puntuacion = puntos.reduce((acum, i) => acum += i, 0);
      return puntuacion ? puntuacion / puntos.length : 0;   // ❌ chequea la suma, no si el array está vacío
    }
    ```

!!! success "✅ Versión corregida (chequeo correcto + early return sin else)"

    ```js
    function promedioPuntos(sistema) {
      let puntos = Object.values(sistema);
      if (puntos.length === 0) return 0;

      let puntuacion = puntos.reduce((acum, i) => acum + i, 0);
      return puntuacion / puntos.length;
    }
    ```

🧠 **Lección:** mismo patrón de "chequear lo que no corresponde" que E1 y E5 — funcionaba de casualidad porque `puntuacion` solo da `0` cuando el array está vacío (con `reduce(..., 0)`), pero no es la pregunta real que hace falta responder. Y el `else` sobra después de un `return` — ya es un early return, no necesita bloque alternativo.

## 🔎 Por qué fallaron — resumen del día

- **E1:** confundió llamar una función con acceder a una propiedad (`Object.keys.objeto` vs `Object.keys(objeto)`).
- **E3:** creyó que un par `[clave, valor]` de `Object.entries` era un objeto con propiedad `.values`.
- **E5:** no fue error real, repetía la misma expresión en un ternario en vez de usar `??`.
- **P1:** el más grave — errores de sintaxis (variable redeclarada, objeto mal armado) y `??` sin paréntesis explícitos.
- **P2:** pensó que `reduce` recibía `acu`/`item` como argumentos sueltos, y que solo servía para sumar (no para comparar y elegir).
- **P3:** chequeó la suma en vez de `.length` para saber si el array estaba vacío — daba bien de casualidad.

**Patrón general:** más "condición que acierta por casualidad" (E1, E5, P3) y "modelo mental incompleto de una herramienta" (E3, P2) que errores de sintaxis puros (solo P1).
