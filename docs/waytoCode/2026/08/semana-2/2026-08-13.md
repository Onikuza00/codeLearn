!!! failure "❌ Código de Pau (primer intento)"

    ```js
    function posicionDe(usuarios, id) {
      return usuarios.findIndex(e => e.id === id) ?? undefined;
    }
    ```

!!! success "✅ Versión corregida (sin el `?? undefined`)"

    ```js
    function posicionDe(usuarios, id) {
      return usuarios.findIndex(e => e.id === id);
    }
    ```

🧠 **Lección:** `findIndex()` nunca devuelve `null`/`undefined` — ni cuando no encuentra nada, ahí da `-1`. El `?? undefined` no hacía nada (código muerto), y además invertía el resultado que pedía el enunciado: `-1` como "no encontrado" (lo que `findIndex` ya da solo), no `undefined` (el sentinel de `find()`, un método distinto). Pasó el test igual, por casualidad. Detalle: Fallo 26 en `GOTCHAS.md`.

### `crearBoton(texto)` — ✅ Completado (1 fallo)

!!! failure "❌ Código de Pau (primer intento)"

    ```js
    function crearBoton(texto) {
      return {
        texto: texto,
        onClick = () => `Click en: ${texto}`
        }
      };
    ```

!!! success "✅ Versión corregida (`:` en vez de `=`)"

    ```js
    function crearBoton(texto) {
      return {
        texto: texto,
        onClick: () => `Click en: ${texto}`
        }
      };
    ```

🧠 **Lección:** en un objeto literal, clave y valor se separan con `:`, no con `=` — `onClick = ...` es un `SyntaxError`. Y como es un error de PARSEO (no de ejecución), rompe la carga de `dia-13-metodos-avanzados-soluciones.js` entero: por eso el runner mostraba "aún no escribiste `crearBoton()`" — la función ni llegaba a existir, no era un problema del runner. La solución en sí (arrow function que cierra sobre `texto` por closure, en vez de depender de `this`) ya estaba bien pensada desde el enunciado.

### `crearContadorConThis()` — ✅ Completado (varios intentos, 2 lecciones distintas)

!!! failure "❌ Código de Pau (intentos sucesivos)"

    ```js
    // Intento 1 — arrow function COMO el método: pierde el "this" del objeto
    incrementar: () => this.valor++

    // Intento 2 — invocación correcta (IIFE), pero this.valor++ es postfix
    return (() => this.valor++)();   // devuelve 0, 1, 2 — un paso atrás de lo pedido

    // Intento 3 — intentó compensar el postfix arrancando valor en 1 en vez de arreglar el operador
    valor: 1,
    incrementar: function() {
      return (() => this.valor)();   // ni siquiera incrementa ya
    }
    ```

!!! success "✅ Versión corregida (método normal + arrow interna + prefix)"

    ```js
    function crearContadorConThis() {
      return {
        valor: 0,
        incrementar: function() {
          return (() => ++this.valor)();
        }
      };
    }
    ```

🧠 **Lección (dos conceptos distintos, en el mismo ejercicio):**

1. **Arrow function como método pierde el `this` que necesitás:** un objeto literal no crea contexto de `this` — una arrow definida directo como propiedad hereda el `this` de donde se definió `crearContadorConThis` (no el objeto que devuelve). `incrementar` tiene que ser un `function` normal (para que `this` sí sea `c` al llamar `c.incrementar()`), y la arrow va ANIDADA adentro, heredando ese `this` correcto.
2. **Postfix (`this.valor++`) vs. prefix (`++this.valor`):** postfix devuelve el valor VIEJO, antes de sumar — por eso la primera llamada daba `0` en vez de `1`. `++this.valor` (prefix) devuelve el valor YA actualizado. Documentado ahora en [Operadores](/js/01-basico/02-operadores/) — sección nueva de la teoría, agregada hoy mismo a partir de este fallo. Intentar arreglarlo arrancando `valor` en `1` en vez de cambiar el operador es tratar el síntoma, no la causa: un contador recién creado que ya muestra `1` sin haber incrementado nunca no tiene sentido, aunque matemáticamente "funcionara" para la secuencia del test.

Detalle: Fallo 27 en `GOTCHAS.md`.

## 🔎 Por qué falló — resumen del día

- **`posicionDe`:** confundir el "no encontrado" de `find` (`undefined`) con el de `findIndex` (`-1`), y aplicar `??` sin comprobar antes si el método de la izquierda puede devolver algo nullish de verdad.
- **`crearBoton`:** `=` en vez de `:` en un objeto literal — error de sintaxis que rompe la carga del archivo entero, no solo ese ejercicio.
- **`crearContadorConThis`:** dos conceptos nuevos en cadena — arrow function como método pierde el `this` correcto (hay que anidarla dentro de un método normal), y postfix/prefix en incrementos devuelven valores distintos.

**Patrón general:** el Grupo 1 (buscar en arrays) y el Grupo 2 (valor/referencia) salieron casi perfectos — la mecánica de elegir el método correcto y de "no mutar, crear nuevo" ya están firmes. El Grupo 3 (`this`) fue el que más costó, esperable siendo la primera vez que se toca `this` a fondo — motivó una sección nueva en la documentación (`Operadores`) que no existía hasta hoy.
