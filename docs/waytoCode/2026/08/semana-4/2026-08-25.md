### E6 — `activarPanelLateral(botonAbrir, panel)` — ✅ Completado (3 fallos)

- **❌ Arquitectura:** el listener global de "clic fuera cierra" se enganchó en `botonAbrir` en vez de en `document` — los clics fuera del botón nunca llegaban a dispararlo.
- **❌ Reincidencia de los tres `contains()`:** `botonAbrir.classList.contains(e.target)` (espera un string de clase) en vez de `botonAbrir.contains(e.target)` (nodo).
- **❌ Guard invertido con nombre engañoso:** una variable llamada `estaAbierto` guardaba en realidad si el panel estaba OCULTO, y el `return` cortaba justo cuando el panel estaba abierto — el único caso que había que procesar.

!!! failure "❌ Código de Pau (evolución del intento)"
    ```js
    function activarPanelLateral(botonAbrir, panel) {
      botonAbrir.addEventListener('click', function(e){   // ❌ debía ser document
        let btn = botonAbrir.classList.contains(e.target)  // ❌ classList.contains() espera un string
        let estaAbierto = panel.classList.contains("hidden")  // ❌ el nombre dice lo contrario del valor
        if(!estaAbierto) return;   // ❌ corta cuando el panel está abierto
      });
    }
    ```

!!! success "✅ Versión corregida"
    ```js
    function activarPanelLateral(botonAbrir, panel) {
      document.addEventListener('click', function(e){
        let clickEnBoton = botonAbrir.contains(e.target)
        if(clickEnBoton) return panel.classList.toggle('hidden');

        const estaCerrado = panel.classList.contains('hidden')
        if(estaCerrado) return;

        if(panel.contains(e.target)) return;
        return panel.classList.add('hidden')
      });
    }
    ```

🧠 **Lección:** un listener pensado para capturar clics de toda la página va en `document`, no en un elemento puntual de la interfaz. Y el nombre de una variable tiene que coincidir con lo que realmente guarda — `estaAbierto` almacenando "está oculto" esconde una inversión de lógica que, de otra forma, sería obvia.

### E7 — `filtrarTareasPorEstadoYTexto(inputBusqueda, selectEstado, contenedorTareas)` — ✅ Completado (4 fallos)

- **❌ `dataset` mal escrito:** `e.data.titulo` en vez de `e.dataset.titulo`.
- **❌ Campo y operador equivocados:** comparaba el buscador contra `e.dataset.estado` con `===` en vez de comparar el título con `.includes()`.
- **❌ Falta la excepción `"todos"`:** comparaba `e.dataset.estado === "TODOS"` (nunca existe en ninguna tarea) en vez de `selectEstado.value === "todos"`.
- **❌ Negación de De Morgan mal aplicada:** `!titulo && (!todos || !estado)` no es la negación correcta de `titulo && (estado || todos)` — y antes de eso, un `addEventListener` quedó anidado DENTRO de `aplicarFiltros`, así que nunca se registraba.

!!! failure "❌ Código de Pau (evolución del intento)"
    ```js
    function filtrarTareasPorEstadoYTexto(inputBusqueda, selectEstado, contenedorTareas) {
    const aplicarFiltros = () => {
      contenedorTareas.querySelectorAll(".tarea").forEach(e => {
        const titulo = e.dataset.titulo.toUpperCase().includes(inputBusqueda.value.toUpperCase())
        const estado = e.dataset.estado.toUpperCase() === selectEstado.value.toUpperCase()
        const todos = selectEstado.value.toUpperCase() === "TODOS"
        e.classList.toggle("hidden", !todos && (!titulo || !estado))  // ❌ negación mal repartida
      })
      inputBusqueda.addEventListener("input", aplicarFiltros)   // ❌ nunca se ejecuta desde aquí dentro
      selectEstado.addEventListener("change", aplicarFiltros)
    }
    }
    ```

!!! success "✅ Versión corregida"
    ```js
    function filtrarTareasPorEstadoYTexto(inputBusqueda, selectEstado, contenedorTareas) {
      const aplicarFiltros = () => {
        contenedorTareas.querySelectorAll(".tarea").forEach(e => {
          const titulo = e.dataset.titulo.toUpperCase().includes(inputBusqueda.value.toUpperCase())
          const estado = e.dataset.estado.toUpperCase() === selectEstado.value.toUpperCase()
          const todos = selectEstado.value.toUpperCase() === "TODOS"
          const entra = titulo && (estado || todos)
          e.classList.toggle("hidden", !entra)
        })
      }
      inputBusqueda.addEventListener("input", aplicarFiltros)
      selectEstado.addEventListener("change", aplicarFiltros)
    }
    ```

🧠 **Lección:** negar una expresión con `&&`/`||` a mano, término por término, es fácil de errar — el operador que une los términos también hay que invertirlo (De Morgan). La forma segura: armar primero la versión en POSITIVO, calcada de la pregunta real en palabras, y negar el resultado completo una sola vez al final. Y un `addEventListener` escrito dentro de la función que se supone que dispara no se registra nunca solo — hay que sacarlo al nivel donde se define esa función, no dentro de su cuerpo.

### E8 — `moverAbajo(lista)` — ✅ Completado (3 fallos)

- **❌ `closest()` sin el punto:** `closest("btn-bajar")` busca una etiqueta `<btn-bajar>` inexistente en vez de la clase `.btn-bajar`.
- **❌ `insertBefore` con argumentos invertidos (regresión respecto al 23/08):** `lista.insertBefore(item, hermano)` es un no-op porque `item` ya está inmediatamente antes de `hermano`.
- **❌ Variable global implícita (reincidencia del Fallo 37):** `valor = item.dataset.tarea` sin `let`/`const`, además de un intercambio manual del atributo `data-tarea` en vez de mover el nodo real.

!!! failure "❌ Código de Pau (evolución del intento)"
    ```js
    function moverAbajo(lista) {
      lista.addEventListener("click", function(e){
        const btn = e.target.closest("btn-bajar")   // ❌ sin el punto
        if(!btn) return;
        const item = e.target.closest(".item-lista")
        const hermano = item.previousElementSibling  // ❌ debía ser nextElementSibling
        if(hermano){
          valor = item.dataset.tarea                 // ❌ sin let/const
          item.dataset.tarea = hermano.dataset.tarea  // ❌ swap manual del atributo
          hermano.dataset.tarea = valor
          lista.insertBefore(item, hermano)           // ❌ argumentos invertidos, no-op
        }
      })
    }
    ```

!!! success "✅ Versión corregida"
    ```js
    function moverAbajo(lista) {
      lista.addEventListener("click", function(e){
        const btn = e.target.closest(".btn-bajar")
        if(!btn) return;
        const item = e.target.closest(".item-lista")
        const hermano = item.nextElementSibling
        if(!hermano) return
        lista.insertBefore(hermano, item)
      })
    }
    ```

🧠 **Lección:** `closest()` recibe un selector CSS y siempre lleva el punto para una clase — sin él busca una etiqueta HTML literal. El orden de `insertBefore(nodoAMover, nodoDeReferencia)` ya estaba consolidado desde el 23/08 pero hoy volvió a fallar: para bajar un elemento hay que mover al SIGUIENTE antes que él, no al revés. Y mover el nodo real (en vez de intercambiar un atributo a mano) arrastra automáticamente todo su contenido — texto, botón, lo que sea — sin tener que copiar nada.

### E9 — `activarValoracionEstrellas(contenedor)` — ✅ Completado (2 fallos)

- **❌ Negación de más:** `x.classList.toggle("estrella--activa", !esActivo)` — `esActivo` ya significaba exactamente lo que `toggle` necesitaba, sin falta de invertirlo.
- **❌ `querySelector` sobre el propio contenedor:** `contenedor.querySelector("#valoracion-r9")` devuelve `null` porque `contenedor` YA es ese elemento — `querySelector` busca entre descendientes, nunca en el elemento mismo. Junto con eso, reasignación de una `const`.

!!! failure "❌ Código de Pau (evolución del intento)"
    ```js
    contenedor.querySelectorAll(".estrella").forEach(x => {
      const esActivo = x.dataset.valor <= valor
      x.classList.toggle("estrella--activa", !esActivo)   // ❌ negación innecesaria
    })
    const valoracion = contenedor.querySelector("#valoracion-r9").dataset.valoracion  // ❌ contenedor ya lo es
    valoracion = `${valor} de 5`   // ❌ reasignar un const
    ```

!!! success "✅ Versión corregida"
    ```js
    contenedor.querySelectorAll(".estrella").forEach(x => {
      const esActivo = x.dataset.valor <= valor
      x.classList.toggle("estrella--activa", esActivo)
    })
    contenedor.dataset.valoracion = valor
    contenedor.querySelector("#texto-valoracion-r9").textContent = `${valor} de 5`
    ```

🧠 **Lección:** antes de negar un booleano para un `toggle`, preguntarme si mi booleano y la clase apuntan en el mismo sentido o en sentidos opuestos — solo en el segundo caso hace falta `!`. Y `querySelector()` nunca se aplica sobre el elemento buscando su propio id: si ya tengo la referencia, la uso directo.

### E10 — `resumirCarrito(contenedor)` — ✅ Completado (1 fallo)

- **❌ Selector de clase compuesta mal escrito:** `.linea.carrito` (dos clases separadas) en vez de `.linea-carrito` (una sola clase con guion) — `querySelectorAll` no encontraba ninguna línea, y el total se quedaba en `0` siempre.

!!! failure "❌ Código de Pau (intento 1)"
    ```js
    contenedor.querySelectorAll(".linea.carrito").forEach(x => { ... })
    ```

!!! success "✅ Versión corregida"
    ```js
    contenedor.querySelectorAll(".linea-carrito").forEach(x => { ... })
    ```

🧠 **Lección:** `.a.b` pide un elemento con las clases `a` Y `b` a la vez — selector distinto de `.a-b`, una sola clase cuyo nombre incluye un guion. El guion es parte del nombre, no un separador. El resto del ejercicio (acumulador fuera del `forEach`, `Number()` sobre el `dataset`, `.toFixed(2)`) salió bien planteado desde el primer intento.
