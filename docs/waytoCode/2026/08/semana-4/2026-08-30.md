#### A1 — `symfony new` + base de datos — ✅ Completado (1 fallo)

- **❌ `DATABASE_URL` editado directamente en `.env`** además de en `.env.local` → el mismo valor duplicado en los dos archivos.

!!! failure "❌ Intento"
    ```env
    # .env  (versionado, es la plantilla)
    DATABASE_URL="mysql://root:@127.0.0.1:3306/gestor_tareas?serverVersion=10.4.32-MariaDB&charset=utf8mb4"

    # .env.local  (mismo valor otra vez)
    DATABASE_URL="mysql://root:@127.0.0.1:3306/gestor_tareas?serverVersion=10.4.32-MariaDB&charset=utf8mb4"
    ```

!!! success "✅ Corregido"
    ```env
    # .env  → tal como lo dejó el recipe de Doctrine, sin tocar

    # .env.local  (el único sitio con el valor real)
    DATABASE_URL="mysql://root:@127.0.0.1:3306/gestor_tareas?serverVersion=10.4.32-MariaDB&charset=utf8mb4"
    ```

🧠 **Lección:** `.env` es la **plantilla versionada** (defaults compartidos del equipo); `.env.local` es el **override por máquina** que Git ignora. Credenciales y URLs reales solo en `.env.local`. Duplicar el valor en los dos es ruido y fuente de desincronización.

#### A2 — Entidad `Task` con `make:entity` — ✅ Completado (1 fallo)

- **❌ `length: 255` en la columna `TEXT`** de `description` — reincidencia directa del fallo P1 del 29/08.

!!! failure "❌ Intento"
    ```php
    #[ORM\Column(type: Types::TEXT, length: 255)]   // ❌ TEXT no lleva length
    private ?string $description = null;
    ```

!!! success "✅ Corregido"
    ```php
    #[ORM\Column(type: Types::TEXT)]
    private ?string $description = null;
    ```

🧠 **Lección:** `length` solo aplica a `VARCHAR` (`string`); `TEXT` es ilimitado. Cambiar el `type` a `TEXT` y dejar el `length` de la versión `string` es media corrección — mismo hilo que "copiar la forma correcta a medias" de `GOTCHAS.md`.

#### A3 — `createdAt` en el constructor — ✅ Completado (1 fallo)

- **❌ `$this->$createdAt`** — el `$` de más lo convierte en acceso por *variable variable*; la propiedad `createdAt` nunca se asigna.

!!! failure "❌ Intento"
    ```php
    public function __construct()
    {
        $this->$createdAt = new \DateTimeImmutable();   // ❌ $this->$createdAt ≠ $this->createdAt
    }
    ```

!!! success "✅ Corregido"
    ```php
    public function __construct()
    {
        $this->createdAt = new \DateTimeImmutable();
    }
    ```

🧠 **Lección:** tras `->`, el nombre de propiedad va **pelado**. Con `$` (`$this->$createdAt`) PHP lee la variable `$createdAt` — que no existe en el constructor — y usa su valor como *nombre* de propiedad. Resultado: `createdAt` queda `null` y el `persist()` peta por NOT NULL.

#### A4 — Enums PHP `TaskStatus` / `TaskPriority` — ✅ Completado (1 fallo)

- **❌ Enum puro** cuando `#[ORM\Column(enumType:)]` exige uno *backed*.

!!! failure "❌ Intento"
    ```php
    // src/Enum/TaskStatus.php
    enum TaskStatus              // ❌ puro: sin ": string" no hay ->value que guardar
    {
        case Todo;
        case Doing;
        case Done;
    }
    ```

!!! success "✅ Corregido"
    ```php
    enum TaskStatus: string
    {
        case Todo  = 'todo';
        case Doing = 'doing';
        case Done  = 'done';
    }
    ```

🧠 **Lección:** un enum que va a una columna vía `enumType:` tiene que ser **backed** (`: string`): la columna guarda el `->value`, y sin escalar detrás no hay qué persistir. Un enum puro solo sirve para lógica en memoria.

### Bloque B — Controladores

| ✅ Sin fallos | ❌ Con fallos |
|:---:|:---:|
| 4 | 2 |

B2, B3, B4 (`findVencidas`) y B5 sin fallo conceptual. B1 y B6 con fallos.

#### B1 — `TaskController` + `index()` + plantillas — ✅ Completado (1 fallo)

- **❌ `<ul>` dentro del `{% for %}`** → un `<ul>` nuevo por cada tarea, cada uno con un solo `<li>`.

!!! failure "❌ Intento"
    ```twig
    {% for task in tasks %}
    <ul>
        <li>{{ task.title }}</li>
    </ul>
    {% else %}
        ...
    {% endfor %}
    ```

!!! success "✅ Corregido"
    ```twig
    <ul>
    {% for task in tasks %}
        <li>{{ task.title }}</li>
    {% else %}
        <li>No hay tareas.</li>
    {% endfor %}
    </ul>
    ```

🧠 **Lección:** lo que hay **una** vez (el `<ul>`, un `<div class="grid">`, un `<table>`) va **fuera** del bucle; lo que se repite (el `<li>`, la card, el `<tr>`) va dentro. El `{% else %}` de Twig va entre el cuerpo y el `{% endfor %}`. Tercera vez con este patrón (P7 del 29/08 y el repaso de ayer).

#### B6 — Filtro por query string (`?status=&q=`) — ✅ Completado (2 fallos)

- **❌ `search()` escrito como cadena fija**, con las dos condiciones siempre y `=` en vez de `LIKE`. El sentido de B6 es añadir cada `andWhere` **dentro de un `if`**.
- **❌ Media corrección en el controlador:** añadió `$tasks = $repository->search(...)` pero dejó el `$lista = $repository->findAll()` viejo, y renderizaba `$lista`.

!!! failure "❌ Intento"
    ```php
    // controlador — search() calculado y descartado
    $tasks = $repository->search($status, $q);
    $lista = $repository->findAll();                 // ❌ sobrescribe
    return $this->render('task/index.html.twig', ['tasks' => $lista]);

    // repo — cadena fija, sin if
    return $this->createQueryBuilder('x')
        ->where('x.status = :val AND x.title = :title')   // ❌ siempre las dos; '=' no LIKE
        ->setParameter('val', $status)
        ->setParameter('title', $q)
        ->getQuery()->getResult();
    ```

!!! success "✅ Corregido"
    ```php
    // controlador
    $tasks = $repository->search($status, $q);
    return $this->render('task/index.html.twig', ['tasks' => $tasks]);

    // repo — builder en variable, andWhere condicional
    $qb = $this->createQueryBuilder('t');
    if ($status) {
        $qb->andWhere('t.status = :status')->setParameter('status', $status);
    }
    if ($q) {
        $qb->andWhere('t.title LIKE :q')->setParameter('q', '%' . $q . '%');
    }
    return $qb->orderBy('t.dueDate', 'ASC')->getQuery()->getResult();
    ```

🧠 **Lección:** cuando qué condiciones se aplican depende de un `if`, no se puede la cadena de un tirón: guardás el builder en `$qb`, le añadís `andWhere` en sentencias sueltas (es el mismo objeto), y ejecutás al final. Un QB sin ningún `andWhere` ya es "trae todo" — la rama "sin filtros → findAll()" sale sola.

2. **Media corrección: añadir lo nuevo sin quitar lo viejo** (B6 controlador; también en A). Antídoto de siempre: releer el bloque entero.
3. **Patrón nuevo — QueryBuilder condicional** (B6): lo escribió como cadena fija (como B3/B4); lo hizo bien tras ver el esqueleto.

#### C1 — `TaskType` con `make:form` — ✅ Completado (2 fallos)

- **❌ `->add('dueDate', DateType::class, null, [...])`** — cuatro argumentos. `->add()` acepta tres (`nombre`, `tipo`, `array $options`); el `null` cae en el hueco de `$options` → `TypeError`.
- **❌ `createdAt` como campo del formulario** — un timestamp de sistema que pone el constructor no se edita desde el form.

!!! failure "❌ Intento"
    ```php
    $builder
        ->add('dueDate', DateType::class, null, [   // ❌ 4 args: DateType::class metido sin quitar el null del maker
            'widget' => 'single_text',
        ])
        ->add('createdAt', null, ['widget' => 'single_text'])   // ❌ no va en el form
    ;
    ```

!!! success "✅ Corregido"
    ```php
    $builder
        ->add('dueDate', DateType::class, ['widget' => 'single_text'])
        // createdAt fuera: lo asigna __construct()
    ;
    ```

🧠 **Lección:** al insertar `DateType::class` como 2º argumento hay que **quitar** el `null` que el maker dejó de 3º — si no, el array de opciones pasa a ser el 4º y `$options` recibe `null`. Mismo patrón "añado lo nuevo, dejo lo viejo" de A2 (`length` en `TEXT`) y B6 (`findAll()` que quedó). El form es capa de presentación: no gestiona estado inicial (`createdAt`, `status` por defecto) — eso vive en la entidad.

#### C2 — `new()` — el flujo entero — ✅ Completado (1 fallo)

- **❌ `#[Route('/tasks/new')]` declarada después de `#[Route('/tasks/{id}')]`** → `/tasks/new` nunca se alcanza: `{id}` captura `"new"` y el `EntityValueResolver` hace `find("new")` → 404.

!!! failure "❌ Intento"
    ```php
    #[Route('/tasks/{id}', name: 'task_show')]     // captura /tasks/new con id="new"
    public function show(Task $task): Response { /* ... */ }

    // ...más abajo...
    #[Route('/tasks/new', name: 'task_new')]        // ❌ inalcanzable
    public function new(...): Response { /* ... */ }
    ```

!!! success "✅ Corregido"
    ```php
    #[Route('/tasks/new', name: 'task_new', methods: ['GET', 'POST'])]   // estática primero
    public function new(...): Response { /* ... */ }

    #[Route('/tasks/{id}', name: 'task_show')]                            // dinámica después
    public function show(Task $task): Response { /* ... */ }
    ```

🧠 **Lección:** Symfony evalúa las rutas **en orden de declaración**. Una ruta estática (`/tasks/new`) tiene que ir antes que una dinámica del mismo nivel (`/tasks/{id}`), o el comodín se la come. `/tasks/{id}/delete` no sufre esto porque tiene dos segmentos y `methods: ['POST']`.

#### C6 — `TaskSearchType` sin `data_class`, por GET — ✅ Completado (1 fallo)

- **❌ `search()` no ajustó el contrato de tipos al cambiar la fuente del filtro.** En B6 el `status` llegaba como `string` (query param crudo); con `TaskSearchType` el `EnumType` entrega una **instancia `TaskStatus`**. La firma seguía en `?string $status` → `TypeError` al elegir un estado. Y al corregirla, la dejó **no nullable** (`TaskStatus $status`), que rompe con el `null` de "sin filtro".

!!! failure "❌ Intento"
    ```php
    public function search(?string $status, ?string $q): array   // ❌ EnumType da TaskStatus, no string
    // ...tras el primer arreglo:
    public function search(TaskStatus $status, ?string $q): array // ❌ sin '?', el null de "sin filtro" peta
    ```

!!! success "✅ Corregido"
    ```php
    public function search(?TaskStatus $status, ?string $q): array
    ```

🧠 **Lección:** cuando cambia **de dónde** sale un dato (query param crudo → campo de un form tipado), cambia su **tipo** — hay que revisar el contrato de quien lo recibe (`search()`), no solo el sitio donde se lee.

## 🔎 Por qué fallaron — resumen del bloque C

1. **Media corrección — editar una línea sin releerla entera** (C1 `dueDate`: `DateType::class` metido sin quitar el `null`; C6 `search()`: `?string` → `TaskStatus` sin el `?`). Cuarta y quinta repetición del patrón en el día (A2, B6, y aquí dos veces). **Antídoto:** tras tocar una línea, leerla completa antes de pasar.
2. **Confundir capas** (C1 `createdAt` en el form; C6 tipo del `status`): la capa de presentación (form) no gestiona estado inicial ni asume el tipo de la capa de dominio (repo).
3. **Orden de declaración de las rutas** (C2): una ruta estática tiene que ir antes que una dinámica del mismo nivel, o el comodín se la come.

**Lo que salió bien:** C3, C4 y C5 a la primera; el mecanismo de `is_edit` (opción propia + `if` en `buildForm`); entendió `data_class` (con → hidrata entidad, sin → array plano) y por qué un buscador va por GET; el flujo de `new()` de memoria, sin la card delante.

### Bloque D — Servicios (parcial: D1–D4)

| ✅ Sin fallos | ❌ Con fallos |
|:---:|:---:|

D3 (escalar `#[Autowire]` desde `.env`) sin fallo conceptual. D5 (Twig Extension) y D6 (`TaskSorter`) quedan pendientes — la sesión se cortó antes.

#### D1 — `ReferenceGenerator` — ✅ Completado (1 fallo)

- **❌ Concatenar un objeto `\DateTimeImmutable` dentro de un string** sin formatearlo primero. `getCreatedAt()` devuelve un objeto, no texto; PHP intenta convertirlo y falla.

!!! failure "❌ Intento"
    ```php
    $fecha = "TSK -" . $task->getCreatedAt() . strtoupper(bin2hex(random_bytes(4)));
    //                 └─ ❌ objeto DateTimeImmutable pegado a un string
    ```

!!! success "✅ Corregido"
    ```php
    $reference = "TSK-"
        . $task->getCreatedAt()->format('Ymd')
        . "-" . strtoupper(bin2hex(random_bytes(2)));   // 2 bytes → 4 hex, no 4 bytes → 8
    ```

🧠 **Lección:** un `DateTime`/`DateTimeImmutable` no es un string — para meterlo en un texto se le pide el formato con `->format('Ymd')`. Y en `bin2hex`, cada byte son **2** caracteres hex: 4 caracteres = `random_bytes(2)`.

#### D2 — `TaskStats` + controlador del dashboard — ✅ Completado (1 fallo)

- **❌ `resumen()` no devuelve nada.** El método calcula `$total`, `$pendientes`, `$vencidas`... y termina. La firma es `: array`, pero sin `return` PHP devuelve `null` → `TypeError`.

!!! failure "❌ Intento"
    ```php
    public function resumen(): array
    {
        $total = $this->tasks->count([]);
        $vencidas = count($this->tasks->findVencidas());
        $porhacer = $this->tasks->count(['status' => TaskStatus::Todo]);
        $haciendo = $this->tasks->count(['status' => TaskStatus::Doing]);
        $pendientes = $porhacer + $haciendo;
        // ❌ falta el return
    }
    ```

!!! success "✅ Corregido"
    ```php
    return [
        'total' => $total,
        'pendientes' => $pendientes,
        'vencidas' => $vencidas,
    ];
    ```

🧠 **Lección:** si la firma promete `: array`, el método tiene que devolver un array por todos los caminos. Calcular valores en variables locales no es lo mismo que devolverlos. El planteamiento (constructor con `TaskRepository` promocionado, `Todo` + `Doing` para "pendientes", `findVencidas()` reutilizado) fue correcto — solo faltó el `return`.

#### D4 — `TaskNotifier` con `MailerInterface` + `LoggerInterface` — ✅ Completado (2 fallos)

- **❌ Argumentos del constructor sin `private`** → no se promocionan → son variables locales que mueren al acabar el constructor → `$this->mailer` / `$this->logger` no existen.
- **❌ En `new()`, `taskCreated($task->getTitle())`** — pasa un `string` (el título) donde el método pide `Task $task`. El servicio lee la entidad entera por dentro (`getReference()`, `getTitle()`).

!!! failure "❌ Intento"
    ```php
    // servicio
    public function __construct(
        #[Autowire('%env(ADMIN_EMAIL)%')] private string $adminEmail,
        MailerInterface $mail, LoggerInterface $logger   // ❌ sin private: no promocionados
    ) { }

    // controlador
    $notifier->taskCreated($task->getTitle());   // ❌ string, no Task
    ```

!!! success "✅ Corregido"
    ```php
    public function __construct(
        private MailerInterface $mailer,
        private LoggerInterface $logger,
        #[Autowire('%env(ADMIN_EMAIL)%')]
        private string $adminEmail,
    ) { }

    $notifier->taskCreated($task);
    ```

🧠 **Lección:** la promoción de propiedades es el `private`/`public` delante del argumento. Sin él, el argumento no se guarda en el objeto. Enésima vez del patrón "copié la forma a medias" (A2, B6, C1, C6). Y un método que declara `Task $task` quiere la **entidad**, no uno de sus campos — mismo criterio que en D1.

## 🔎 Por qué fallaron — resumen del bloque D

1. **Confundir un objeto con su representación / con un campo suyo** (D1: `DateTimeImmutable` en un string sin `->format()`; D4: pasar `getTitle()` donde va la entidad `Task`). El type-hint dice qué forma tiene que tener el dato — hay que dársela.
2. **El contrato de la firma** (D2: `: array` sin `return`; D4: `private` que falta para promocionar). Lo que promete la cabecera del método/constructor tiene que cumplirse en el cuerpo.
3. **`.env` es de sintaxis estricta** (D3): `ADMIN_EMAIL = "..."` con espacios alrededor del `=` rompió el arranque entero de la app (`FormatException`). En `.env` va `CLAVE="valor"`, pegado.

**Lo que salió bien:** entendió qué es la inyección por constructor y la diferencia D1 (servicio sin dependencias) vs D2 (servicio que usa el Repository); el patrón de `#[Autowire]` para un escalar de entorno; paró a tiempo cuando notó la saturación (9 h + las 12 del sábado) en vez de seguir arrastrando fallos.
