### E1 — `renderizarProductos(contenedor, productos)` — ✅ Completado (3 fallos)

- **❌ `classList.add()` con string de varias clases:** `contenedor.classList.add("flex flex-col gap-2")` — un token no puede tener espacios, tira `SyntaxError`.
- **❌ Elemento creado pero nunca insertado:** el `badge` se armaba pero le faltaba el `appendChild` a `card`.
- **❌ Condición sobre la propiedad equivocada:** `box.precio === 0` en vez de `box.stock === 0`.

!!! failure "❌ Código de Pau (intento 1)"
    ```js
    function renderizarProductos(contenedor, productos) {
      contenedor.classList.add("flex flex-col gap-2") // ❌ SyntaxError: token con espacios

      productos.forEach(box => {
        let card = document.createElement("article")
        contenedor.appendChild(card);
        card.classList.add("flex flex-col gap-2") // ❌ mismo error

        let esInferior = box.precio === 0 // ❌ compara el precio, no el stock
        let badge = document.createElement("span")
        badge.textContent = esInferior ? "Agotado" : "Disponible"
        badge.className = esInferior ? "p-3 bg-red text-white rounded-md" : "p-3 bg-green text-white rounded-md"
        // ❌ badge nunca se agrega a card
      })
    }
    ```

!!! success "✅ Versión corregida"
    ```js
    function renderizarProductos(contenedor, productos) {
      productos.forEach(box => {
        let card = document.createElement("article")
        contenedor.appendChild(card);
        card.className = "product-card"

        let titulo = document.createElement("h3")
        titulo.textContent = `${box.nombre}`
        titulo.className = "product-card-nombre"
        card.appendChild(titulo)

        let precio = document.createElement("span")
        precio.textContent = `${box.precio.toFixed(2)}€`
        precio.className = "product-card-precio"
        card.appendChild(precio)

        let esInferior = box.stock === 0
        let badge = document.createElement("span")
        badge.textContent = esInferior ? "Agotado" : "Disponible"
        badge.className = esInferior ? "stock-badge bg-red-100 text-red-700" : "stock-badge bg-green-100 text-green-700"
        card.appendChild(badge)
      })
    }
    ```

🧠 **Lección:** `classList.add()` recibe cada clase como argumento SEPARADO — un token no puede tener espacios; `className = '...'` sí acepta el string completo porque reemplaza el atributo entero. `document.createElement()` crea el nodo en memoria, invisible hasta el `appendChild()`. Y reincidencia de "condiciones que aciertan por casualidad" (10/08): comparar la propiedad a mano en vez de la que el enunciado señala.

### E2 — `activarSeleccionMasiva(contenedorTabla)` — ✅ Completado (4 fallos)

- **❌ `forEach` sobre un elemento, no una colección:** `contenedorTabla.forEach(...)` — la tabla es un único nodo, no iterable.
- **❌ Acumulador armado en el momento equivocado:** el bloque `let todos = true; ...forEach...; master.checked = todos;` vivía FUERA del listener, corría una sola vez al llamar la función, no en cada cambio.
- **❌ Comparación en vez de asignación:** `box.checked === todos` — `===` compara y descarta el resultado, no asigna nada.
- **❌ Variable fuera de su rama:** en el `if` del maestro se intentaba usar `todos` (declarada dentro del `else`, fuera de scope ahí).

!!! failure "❌ Código de Pau (intento 1)"
    ```js
    function activarSeleccionMasiva(contenedorTabla) {
      contenedorTabla.addEventListener("click", function(e){
        contenedorTabla.forEach(box => { // ❌ contenedorTabla no es iterable
          e.target.id === "check-todos" ? box.checked : !box.checked // ❌ ternario suelto, no asigna nada
          e.target.type === "checkboxes" ? e.target.checked : !e.target.checked // ❌ "checkboxes" no existe, es "checkbox"
        })
      })
    }
    ```

!!! success "✅ Versión corregida"
    ```js
    function activarSeleccionMasiva(contenedorTabla) {
      let inputs = contenedorTabla.querySelectorAll(".check-fila")
      let master = contenedorTabla.querySelector("#check-todos")

      contenedorTabla.addEventListener("change", function(e){
        let todos = true;
        if(e.target === master){
          inputs.forEach(box => box.checked = master.checked)
        }
        else{
          inputs.forEach(box => {
            if(!box.checked) todos = false;
          })
          master.checked = todos;
        }
      })
    }
    ```

🧠 **Lección:** un acumulador (la bandera `todos`) tiene que declararse ANTES del `forEach` que lo actualiza, y el bloque completo tiene que vivir DENTRO del listener para ser reactivo — declararlo afuera lo convierte en un cálculo de una sola vez, no en algo que reacciona a cada evento. Y un ternario o una comparación (`===`) que no se asigna a ningún lado no tiene ningún efecto — JS calcula el valor y lo descarta.

### E3 — `marcarPrimeraTarjetaAgotada(contenedor)` — ✅ Completado (2 fallos)

- **❌ `dataset` siempre es string:** `card.dataset.stock === 0` nunca es `true` porque `"0" === 0` es `false` (sin coerción).
- **❌ `className =` pisa las clases del fixture:** en vez de sumar `ring-2 ring-red-500`, reemplazaba TODO el atributo `class`, perdiendo el estilo que ya traía la tarjeta.

!!! failure "❌ Código de Pau (intento 1)"
    ```js
    function marcarPrimeraTarjetaAgotada(contenedor) {
      let unica = true;
      contenedor.querySelectorAll(".stock-card").forEach(card => {
        if(card.dataset.stock > 0 && unica){ // ❌ condición invertida (busca CON stock)
          card.className = "ring-2 ring-red-500"; // ❌ pisa bg-white/p-3/rounded/shadow del fixture
          unica = false;
        }
      })
    }
    ```

!!! success "✅ Versión corregida"
    ```js
    function marcarPrimeraTarjetaAgotada(contenedor) {
      let unica = true;
      contenedor.querySelectorAll(".stock-card").forEach(card => {
        if(card.dataset.stock == 0 && unica){
          card.classList.add("ring-2", "ring-red-500");
          unica = false;
        }
      })
    }
    ```

🧠 **Lección:** `element.dataset.X` devuelve SIEMPRE un string, sin importar que en el HTML parezca un número — comparar con `===` contra un número literal nunca coincide. Y `className =` reemplaza TODO el atributo `class` de una vez; para sumar clases sin destruir las que ya había, hace falta `classList.add()` con un argumento por clase.

### E5 — `validarLongitudUsuario(inputUsuario, spanAyuda)` — ✅ Completado (1 fallo)

- **❌ `&&` en vez de `||` para "fuera de rango":** `length < 4 && length > 12` nunca es `true` (ningún número es menor que 4 Y mayor que 12 a la vez).

!!! failure "❌ Código de Pau (intento 1)"
    ```js
    if(inputUsuario.value.length < 4 && inputUsuario.value.length > 12){
    ```

!!! success "✅ Versión corregida"
    ```js
    if(inputUsuario.value.length < 4 || inputUsuario.value.length > 12){
    ```

🧠 **Lección:** "está fuera de un rango" es una condición OR (menor que el mínimo, O mayor que el máximo) — nunca AND, porque ningún valor cumple las dos cosas a la vez. Trampa clásica al traducir "fuera de [4,12]" a código.

### E6 — `activarAcordeon(panel)` — ✅ Completado (2 fallos)

- **❌ Sin alternar — solo abría:** el primer intento nunca volvía a cerrar la respuesta en un segundo click.
- **❌ `aria-expanded` no reflejaba el resultado real del `toggle()`:** quedaba hardcodeado o invertido respecto al estado real de la clase `hidden`.

!!! failure "❌ Código de Pau (intento 2, tras arreglar el toggle)"
    ```js
    e.target.ariaExpanded = e.target.nextElementSibling.classList.toggle("hidden");
    // ❌ toggle() devuelve true si "hidden" quedó PRESENTE (cerrado) — justo lo contrario de "expandido"
    ```

!!! success "✅ Versión corregida"
    ```js
    function activarAcordeon(panel) {
      panel.addEventListener("click", function(e){
        if(e.target.classList.contains("faq-pregunta")){
          e.target.ariaExpanded = !e.target.nextElementSibling.classList.toggle("hidden");
        }
      })
    }
    ```

🧠 **Lección:** `classList.toggle()` devuelve `true` si la clase terminó PRESENTE — con una clase como `hidden`, ese resultado va al revés de "está visible/expandido". Cuando el nombre de la clase que alternás es la negación semántica de lo que necesitás comunicar, hay que invertir el resultado (`!`) antes de usarlo.

### E7 — `filtrarListaEnVivo(inputBusqueda, contenedorItems)` — ✅ Completado (3 fallos)

- **❌ Mismo bug de `forEach` sobre un elemento que en E2:** `contenedorItems.forEach(...)` antes de seleccionar `.item-lista`.
- **❌ El truco de `includes('')` aplicado en el lugar equivocado:** se lo aplicó al VALOR del buscador (`valor.includes("")`, siempre `true`, perdiendo el texto real) en vez de usarlo como argumento de la comparación contra cada nombre.
- **❌ `===` en vez de `.includes()`:** comparación exacta en vez de "contiene", nunca matcheaba una búsqueda parcial.

!!! failure "❌ Código de Pau (camino hasta la versión final)"
    ```js
    let valor = e.target.value.toLowerCase().includes(""); // ❌ valor termina siendo `true`, se pierde el texto
    contenedorItems.forEach(x => { // ❌ contenedorItems no es iterable directamente
      x.dataset.nombre.toLowerCase() === valor // ❌ === exige coincidencia exacta, además compara contra un booleano
        ? x.classList.remove("hidden") : x.classList.add("hidden")
    })
    ```

!!! success "✅ Versión corregida"
    ```js
    function filtrarListaEnVivo(inputBusqueda, contenedorItems) {
      inputBusqueda.addEventListener("input", function(e){
        let valor = e.target.value.toLowerCase();
        contenedorItems.querySelectorAll(".item-lista").forEach(x => {
          x.dataset.nombre.toLowerCase().includes(valor) ? x.classList.remove("hidden") : x.classList.add("hidden")
        })
      })
    }
    ```

🧠 **Lección:** un string vacío es matemáticamente subcadena de CUALQUIER string, así que `nombre.includes('')` da `true` para todos — ese comportamiento sale SOLO de usar el valor de búsqueda como argumento de `.includes()` en la comparación real, no de llamarlo aparte sobre el propio texto buscado. Y `.includes()` (contiene) no es lo mismo que `===` (es exactamente igual) — para "coincidencia parcial" siempre hace falta el primero.

### E8 — `activarStepperCarrito(botonMas, botonMenos, spanCantidad)` — ✅ Completado (2 fallos)

- **❌ `.Number()` no existe:** `spanCantidad.textContent.Number()` — `Number` es una función global, no un método de los strings.
- **❌ `if` sin llaves:** una línea quedaba fuera del `if` por indentación engañosa (no rompía el resultado en este caso puntual, pero por casualidad).

!!! failure "❌ Código de Pau (intento 1)"
    ```js
    let num = spanCantidad.textContent.Number() // ❌ TypeError: .Number is not a function

    botonMenos.addEventListener("click", function(e){
      if(num > 0)
        num--;
        spanCantidad.textContent = num; // ❌ esta línea NO está dentro del if, aunque lo parezca
    })
    ```

!!! success "✅ Versión corregida"
    ```js
    function activarStepperCarrito(botonMas, botonMenos, spanCantidad) {
      let num = Number(spanCantidad.textContent)
      botonMas.addEventListener("click", function(e){
        num++;
        spanCantidad.textContent = num;
      })
      botonMenos.addEventListener("click", function(e){
        if(num > 0){
          num--;
          spanCantidad.textContent = num;
        }
      })
    }
    ```

🧠 **Lección:** `Number(valor)` es una función GLOBAL a la que se le pasa el valor como argumento — no existe como método sobre un string. Y un `if` sin `{}` solo controla la línea inmediatamente siguiente: JS no lee la indentación, así que cualquier línea extra "dentro" visualmente en realidad se ejecuta siempre, pase lo que pase la condición.

### E9 — `activarCierreModalFuera(modal)` — ✅ Completado (3 fallos)

- **❌ Callback sin el parámetro del evento:** `function(){` usaba `e.target` sin declarar `e` — `ReferenceError`.
- **❌ Comparación por `.id` con el id equivocado:** ni siquiera coincidía con el real del fixture (`modal-contenido-e9`).
- **❌ Comparar por `.id` en general no serviría igual:** cualquier hijo interno (el `<p>`, el `<button>`) tampoco tiene ese id — hacía falta comparar el elemento directo.

!!! failure "❌ Código de Pau (intento 1)"
    ```js
    modal.addEventListener("click", function(){ // ❌ falta el parámetro del evento
      if(e.target.id !== "modal-contenido"){ // ❌ e no existe; además el id real es "modal-contenido-e9"
        e.target.classList.add("hidden")
      }
    })
    ```

!!! success "✅ Versión corregida"
    ```js
    function activarCierreModalFuera(modal) {
      modal.addEventListener("click", function(e){
        if(e.target == modal){
          e.target.classList.add("hidden")
        }
      })
    }
    ```

🧠 **Lección:** para saber "¿el click fue justo en el fondo, o en algo de adentro?" no sirve comparar ids — sirve comparar los ELEMENTOS directamente contra `e.target`. Cualquier hijo interno del contenido tiene su propio id (o ninguno), nunca el del contenedor exterior.

### E10 — `activarDragReordenable(lista)` — ✅ Completado (4 fallos)

- **❌ Asignación al revés:** `e.target = item` (intentaba escribir en una propiedad de solo lectura) en vez de `item = e.target`.
- **❌ Argumentos de `insertBefore()` invertidos:** `insertBefore(e.target, item)` movía el elemento equivocado.
- **❌ `preventDefault()` llamado como función global:** `() => preventDefault()` sin `e`, ni como método del evento.
- **❌ Feature nueva para Pau:** Drag and Drop nativo (`dragstart`/`dragover`/`drop`) nunca se había tocado — teoría sumada en el momento en `docs/js/04-dom/03-eventos/04-arrastrar-soltar/`.

!!! failure "❌ Código de Pau (camino hasta la versión final)"
    ```js
    lista.addEventListener("dragstart", function(e){
      e.target = item; // ❌ event.target es de solo lectura, y además al revés
    })
    lista.addEventListener("drop", function(e){
      lista.insertBefore(e.target, item) // ❌ mueve el elemento soltado, no el arrastrado
    })
    lista.addEventListener("dragover", () => preventDefault()) // ❌ preventDefault no es global, falta `e.`
    ```

!!! success "✅ Versión corregida"
    ```js
    function activarDragReordenable(lista) {
      let item = null;
      lista.addEventListener("dragstart", function(e){
        item = e.target;
      })
      lista.addEventListener("drop", function(e){
        lista.insertBefore(item, e.target)
      })
      lista.addEventListener("dragover", (e) => e.preventDefault())
    }
    ```

🧠 **Lección:** `event.target` es de solo lectura, nunca se le asigna nada. `insertBefore(nodoAMover, nodoDeReferencia)` — el primer argumento es el que se mueve, el segundo antes de cuál se inserta; invertirlos mueve el elemento equivocado. Y `preventDefault()` es siempre un método del propio evento (`e.preventDefault()`), nunca una función suelta.

## 🔎 Por qué fallaron — resumen del bloque

Patrón dominante del día: **expresiones que se calculan pero nunca se usan** — un ternario suelto, una comparación `===` donde hacía falta una asignación `=`, `.includes("")` aplicado al lado equivocado — todas variantes del mismo error de fondo, "calcular algo no es lo mismo que hacer algo con ese resultado". Segundo patrón repetido: **confundir un elemento del DOM con el valor que contiene** (`contenedorTabla`/`contenedorItems` tratados como colecciones iterables, `spanCantidad` comparado como si fuera un número) — mismo error de fondo que ya había aparecido con `inputUsuario`/`inputBusqueda` (necesitan `.value`), ahora generalizado a colecciones y a `textContent`. Y varias reincidencias directas de los Fallos 37-40 del cierre de DOM (fuga de estado, bandera booleana, `clientX`/`clientY` — este último sin fallo, primera vez limpio), más nuevas: `dataset` siempre string, `classList.toggle()` invertido según el nombre de la clase, `insertBefore()` con argumentos al revés.

!!! failure "❌ `.append()` en vez de `.push()` + falta `async`/`await`"
    Traducción literal de Python: los arrays de JS no tienen `.append()` (es `.push()`), y `client.messages.create()` devuelve una `Promise` — sin `async`/`await`, `message` termina siendo la propia `Promise` sin resolver.

!!! failure "❌ `system = valor` dentro de una llamada, y `= none` como valor por defecto"
    Confundir los argumentos con nombre de Python (`chat(messages, temperature=0.0)`) con JS: `nombre = valor` dentro de una llamada NO nombra un parámetro, es una asignación — en un módulo ES (modo estricto) tira `ReferenceError` al asignar a una variable no declarada. Y `none` no existe en JS.

!!! failure "❌ `message.content[0].text` asumido, sin comprobar el tipo de bloque"
    Sonnet 5 antepone un bloque `{ type: "thinking" }` — `content[0]` no es el texto. El `undefined` resultante se guardó como respuesta del asistente y rompió la conversación multiturno con un `400 Field required` en el siguiente turno. Fix: `message.content.find(block => block.type === "text").text`.

🧠 **Lección del bloque:** el mismo patrón de fondo en los tres — asumir que la sintaxis o el comportamiento de Python se traslada literal a JS, sin verificar el equivalente real. Fallos 49-51 en `GOTCHAS.md`.
