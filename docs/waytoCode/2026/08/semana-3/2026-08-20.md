### E5 — `datosProductoCard(tarjeta)` — ✅ Completado (1 fallo)

- **❌ Error conceptual:** `producto = {...}` sin `let`/`const` — variable global implícita, grave en un archivo donde las 15 funciones comparten scope.

!!! failure "❌ Código de Pau (intento 1)"
    ```js
    function datosProductoCard(tarjeta) {
      let precio = parseFloat(tarjeta?.dataset?.precio)
      let categoria = tarjeta?.dataset?.categoria
      let stock = parseInt(tarjeta?.dataset?.stock)
      producto = {precio: precio, categoria: categoria, stock: stock} // ❌ sin let/const
      return producto;
    }
    ```

!!! success "✅ Versión corregida"
    ```js
    function datosProductoCard(tarjeta) {
      let precio = parseFloat(tarjeta?.dataset?.precio)
      let categoria = tarjeta?.dataset?.categoria
      let stock = parseInt(tarjeta?.dataset?.stock)
      const producto = {precio: precio, categoria: categoria, stock: stock}
      return producto;
    }
    ```

🧠 **Lección:** omitir `let`/`const` no tira error, crea una variable global implícita. En este archivo de ejercicios en particular, una fuga de una función puede pisar sin aviso una variable del mismo nombre en otra — `const` por defecto lo evita de raíz.

### E8 — `eliminarTarea(lista, texto)` — ✅ Completado (1 fallo)

- **❌ Error conceptual:** la rama `else` del `forEach` reseteaba la bandera `canvio` a `false` en cada ítem que NO coincidía — si el match no era el último elemento recorrido, el `true` quedaba pisado por la vuelta siguiente.

!!! failure "❌ Código de Pau (intento 1)"
    ```js
    function eliminarTarea(lista, texto) {
      const items = lista.querySelectorAll("li")
      let canvio = false;
      items.forEach(e => {
        if(e.textContent === texto){
           e.remove()
           canvio = true;
        }else {
          canvio = false; // ❌ pisa el true de una vuelta anterior
        }
      })
      return canvio ? items.length -1 : items.length; // además items es NodeList estático
    }
    ```

!!! success "✅ Versión corregida"
    ```js
    function eliminarTarea(lista, texto) {
      const items = lista.querySelectorAll("li");
      items.forEach(e => {
        if (e.textContent === texto) e.remove();
      });
      return lista.children.length; // HTMLCollection viva, ya refleja el DOM mutado
    }
    ```

🧠 **Lección:** una bandera que marca "encontré algo" solo debería poder pasar de `false` a `true`, nunca volver atrás en una vuelta sin match. Y cuando el propio DOM ya puede darte la respuesta después de mutarlo (`.children.length`), no hace falta arrastrar estado manual aparte para reconstruirla.

### E12 — `activarArrastre(tarjeta)` — ✅ Completado (1 fallo)

- **❌ Error de copiado:** `e.clientX` usado también para el eje `top`, en vez de `e.clientY` — la tarjeta nunca seguía verticalmente al mouse.

!!! failure "❌ Código de Pau (intento 1)"
    ```js
    tarjeta.style.left = e.clientX + "px";
    tarjeta.style.top = e.clientX + "px"; // ❌ debería ser clientY
    ```

!!! success "✅ Versión corregida"
    ```js
    tarjeta.style.left = e.clientX + "px";
    tarjeta.style.top = e.clientY + "px";
    ```

🧠 **Lección:** typo clásico de copiar una línea para el segundo eje sin ajustar la letra final — pasó desapercibido porque el test solo comprueba que la tarjeta "se movió", no el valor exacto. Revisar carácter por carácter al duplicar una línea casi idéntica.

### E15 — `validarConfirmacionEmail(email, confirmarEmail)` — ✅ Completado (1 fallo, 2 errores)

- **❌ Error 1:** marcaba `email.setCustomValidity(...)` en vez de `confirmarEmail` — el enunciado pide marcar el campo de confirmación, no el original.
- **❌ Error 2:** sin rama `else` que limpie el error con `setCustomValidity('')` — una vez inválido, el campo quedaba así para siempre.

!!! failure "❌ Código de Pau (intento 1)"
    ```js
    function validarConfirmacionEmail(email, confirmarEmail) {
        if (email.value !== confirmarEmail.value) {
           email.setCustomValidity('Las contraseñas no coinciden'); // ❌ campo equivocado
        }
        // ❌ sin else: queda inválido para siempre
    }
    ```

!!! success "✅ Versión corregida"
    ```js
    function validarConfirmacionEmail(email, confirmarEmail) {
        if (email.value !== confirmarEmail.value) {
           confirmarEmail.setCustomValidity('Los emails no coinciden');
        } else {
           confirmarEmail.setCustomValidity('');
        }
    }
    ```

🧠 **Lección:** `setCustomValidity()` deja el campo marcado inválido de forma permanente hasta que se lo vuelve a llamar con `''` — el `else` no es opcional. Y antes de llamar el método, confirmar cuál de los parámetros es el que el enunciado señala explícitamente, no asumir que es el primero.

## 🔎 Por qué fallaron — resumen del día

Ningún fallo de sintaxis: los cuatro son errores de **gestión de estado** — una variable sin declarar que se filtra al global (E5), una bandera que se resetea en el momento equivocado dentro de un loop (E8), un typo de copiar/pegar entre dos ejes de coordenadas (E12), y un estado de validación que apunta al elemento equivocado y nunca se limpia (E15). Patrón compartido: código que "funciona a medias" sin lanzar ningún error visible — hay que verificar el comportamiento real, no solo la ausencia de excepciones.
