### E1 — `activarFiltroCategorias(contenedorBotones, contenedorProductos)` — ✅ Completado (6 fallos)

- **❌ Listener sobre una colección, no sobre el contenedor:** `contenedorBotones.querySelectorAll("filtro-btn").addEventListener(...)` — un `NodeList` no tiene `addEventListener`, y además faltaba el punto del selector de clase.
- **❌ `closest()` con el orden y el argumento equivocados:** `closeset(e.target).dataset.categoria` — typo de `closest`, y se llamó como función suelta en vez de como método del elemento.
- **❌ Guard clause faltante:** sin `if(!btn) return;`, `btn` podía ser `null` y explotaba.
- **❌ `foreEach` (typo) y `toggle()` con el selector completo como nombre de clase:** `j.classList.toggle(".filtro-btn--activo")` — el punto queda pegado al nombre, busca una clase literal que no existe.
- **❌ `toggle()` sin forzar el resultado:** `x.classList.toggle("hidden")` sin segundo argumento invierte el estado anterior en vez de fijar el resultado según la condición — doble click a la misma categoría daba resultados distintos.
- **❌ Comparar la categoría equivocada:** `x.dataset.categoria === "todos"` (la categoría del PRODUCTO) en vez de `categoria === "todos"` (la categoría del FILTRO elegido) — ningún producto tiene esa categoría, ese caso nunca se cumplía.

!!! failure "❌ Código de Pau (camino hasta la versión final)"
    ```js
    contenedorBotones.querySelectorAll("filtro-btn").addEventListener("click", ...) // ❌ NodeList sin addEventListener, sin punto en el selector

    let btn = closeset(e.target).dataset.categoria // ❌ closest() es método del elemento, no función suelta; typo

    contenedorBotones.querySelectorAll(".filtro-btn").foreEach(j => { // ❌ typo: forEach
      if(j !== btn) j.classList.toggle(".filtro-btn--activo") // ❌ el punto queda dentro del nombre de clase
    })

    if(cat === x.dataset.categoria || cat === "todos") // ❌ compara la categoría del producto contra "todos", nunca coincide
      x.classList.toggle("hidden") // ❌ sin force: invierte, no fija el resultado
    ```

!!! success "✅ Versión corregida"
    ```js
    function activarFiltroCategorias(contenedorBotones, contenedorProductos) {
      contenedorBotones.addEventListener("click", (e) => {
        const btn = e.target.closest(".filtro-btn");
        if (!btn) return;

        contenedorBotones.querySelectorAll(".filtro-btn").forEach(j => {
          j.classList.toggle("filtro-btn--activo", j === btn);
        });

        const categoria = btn.dataset.categoria;
        contenedorProductos.querySelectorAll(".producto-card").forEach(x => {
          const coincide = x.dataset.categoria === categoria || categoria === "todos";
          x.classList.toggle("hidden", !coincide);
        });
      });
    }
    ```

🧠 **Lección:** `classList` trabaja siempre con NOMBRES de clase, nunca con selectores — el punto es exclusivo de `querySelector()`/`closest()`/`matches()`. Y `toggle(clase, booleano)` fuerza el resultado según una condición, en vez de invertir lo que ya había — imprescindible cuando el mismo cálculo se repite en cada evento y el resultado tiene que depender del estado actual, no del anterior.

### E2 — `activarAcordeonExclusivo(panel)` — ✅ Completado (3 fallos)

- **❌ `!expansion` sobre un string:** `expansion` es lo que devuelve `getAttribute()` — siempre un STRING (`"true"`/`"false"`), nunca un booleano. `!"false"` da SIEMPRE `false`, porque cualquier string no vacío es verdadero para `!`.
- **❌ Comparar un string contra un booleano:** `expansion === false` — tipos distintos con `===` nunca son iguales, da `false` siempre también.
- **❌ `classList.remove()` con un segundo argumento que no existe:** `remove("hidden", expansion === "true")` — `remove()` no tiene "force" como `toggle()`, ese segundo argumento se ignora.

!!! failure "❌ Código de Pau (camino hasta la versión final)"
    ```js
    faq.setAttribute("aria-expanded", !expansion) // ❌ niega un string, siempre da false

    faq.setAttribute("aria-expanded", expansion === false) // ❌ string vs booleano, siempre false

    faq.nextElementSibling.classList.remove("hidden", expansion === "true") // ❌ remove() no tiene force
    ```

!!! success "✅ Versión corregida"
    ```js
    function activarAcordeonExclusivo(panel) {
      panel.addEventListener("click", (e) => {
        const faq = e.target.closest(".faq-pregunta");
        if (!faq) return;

        const expansion = faq.getAttribute("aria-expanded");

        panel.querySelectorAll(".faq-pregunta").forEach(x => {
          x.nextElementSibling.classList.add("hidden");
          x.setAttribute("aria-expanded", "false");
        });

        faq.setAttribute("aria-expanded", expansion === "false");
        faq.nextElementSibling.classList.toggle("hidden", expansion === "true");
      });
    }
    ```

🧠 **Lección:** convertir un string `"true"`/`"false"` a la condición booleana real que hace falta SOLO funciona comparando contra el string exacto (`=== "false"`) — ni negar el string (`!string`) ni compararlo contra un booleano (`string === false`) dan el resultado esperado, porque JS evalúa "truthiness" (¿está vacío o no?), no el significado del texto.

### E5 — `validarRangoNumerico(inputEdad, spanError)` — ✅ Completado (3 fallos)

- **❌ `||` donde hacía falta `&&`:** `Number(inputEdad.value) >= 18 || Number(inputEdad.value) <= 65` — para "dentro de un rango" (los dos límites A LA VEZ) hace falta `&&`; con `||` casi cualquier número cumple alguna de las dos condiciones sueltas.
- **❌ Pasar el elemento en vez de un string:** `inputEdad.setCustomValidity(spanError)` — le pasó el nodo `spanError`, no un mensaje de texto.
- **❌ Asignación escondida dentro de otra llamada:** `setCustomValidity(spanError.textContent = "Error")` — técnicamente funciona (una asignación devuelve el valor asignado), pero es ilegible, dos acciones distintas en una sola expresión.

!!! failure "❌ Código de Pau (camino hasta la versión final)"
    ```js
    if(Number(inputEdad.value) >= 18 || Number(inputEdad.value) <= 65){ // ❌ || en vez de &&, casi siempre true
      inputEdad.setCustomValidity("")
    }else{
      inputEdad.setCustomValidity(spanError) // ❌ pasa el elemento, no un string
    }
    ```

!!! success "✅ Versión corregida"
    ```js
    function validarRangoNumerico(inputEdad, spanError) {
      const edad = Number(inputEdad.value);

      if (edad >= 18 && edad <= 65) {
        spanError.textContent = "";
        inputEdad.setCustomValidity(spanError.textContent);
      } else {
        spanError.textContent = "La edad debe estar entre 18 y 65 años";
        inputEdad.setCustomValidity(spanError.textContent);
      }
    }
    ```

🧠 **Lección:** reincidencia directa del patrón "AND vs OR en rangos" ya marcado como "a reforzar" — "dentro de un rango" siempre es `&&` (los dos límites a la vez), "fuera de un rango" siempre es `||`. Y `setCustomValidity()` solo existe en campos de formulario, nunca en un `<span>` u otro elemento genérico — necesita un STRING con el mensaje, no una referencia al elemento que lo muestra.

### E6 — `activarDropdownConCierre(boton, menu)` — ✅ Completado (1 fallo)

- **❌ `classList.contains()` en vez de `Element.contains()`:** `menu.classList.contains(e.target)` y `boton.classList.contains(e.target)` — dos métodos con el mismo nombre y comportamiento totalmente distinto: `classList.contains(nombreDeClase)` comprueba si un STRING de clase está presente; `elemento.contains(nodo)` comprueba si un NODO está adentro de otro. Pasarle un nodo del DOM al primero nunca coincide.

!!! failure "❌ Código de Pau (intento 1)"
    ```js
    document.addEventListener("click", (e) => {
      if(menu.classList.contains(e.target)) return; // ❌ contains() de clases, no de nodos
      if(boton.classList.contains(e.target)) return;
      menu.classList.add("hidden")
    })
    ```

!!! success "✅ Versión corregida"
    ```js
    function activarDropdownConCierre(boton, menu) {
      boton.addEventListener("click", () => menu.classList.toggle("hidden"));

      document.addEventListener("click", (e) => {
        if (menu.contains(e.target)) return;
        if (boton.contains(e.target)) return;
        menu.classList.add("hidden");
      });
    }
    ```

🧠 **Lección:** `Element.contains(nodo)` (¿este nodo está adentro de mí?) y `DOMTokenList.contains(nombreDeClase)` (¿tengo esta clase?) comparten nombre por casualidad, pero viven en objetos distintos y esperan argumentos distintos.

### E7 — `activarStepperConLimite(botonMas, botonMenos, spanCantidad, limite)` — ✅ Completado (6 fallos)

- **❌ Fuga de estado:** `let contador = Number(spanCantidad.dataset.cantidad)` leído UNA sola vez, fuera de los listeners — se desincroniza del DOM en cada click siguiente.
- **❌ Condiciones de límite equivocadas:** `if(contador > 0 && contador <= limite) contador++` — el `> 0` es del botón de RESTAR, no del de sumar; y `<= limite` deja pasarse un click más allá del máximo.
- **❌ `Math.min` usado como condición de un `if`, con argumentos equivocados:** `if(Math.min(0, limite + 1)) contador++` — `Math.min()` devuelve un VALOR, no es una condición, y los argumentos no eran ni el límite ni el próximo valor.
- **❌ Post-incremento dentro de una expresión reasignada:** `contador = Math.min(limite, contador++)` — `contador++` devuelve el valor VIEJO para la expresión mientras muta la variable por su cuenta; la reasignación pisa ese cambio con el valor viejo, dejando el contador congelado.
- **❌ Copiar y pegar sin adaptar (botón de restar):** coma en vez de punto (`spanCantidad,dataset.cantidad`), `Math.min` en vez de `Math.max`, `limite` en vez de `0` como piso, variable inexistente (`cantidad`/`cantador` en vez de `contador`).
- **❌ Olvidar persistir el estado:** calculaba `contador` y actualizaba `textContent`, pero nunca `spanCantidad.dataset.cantidad` — el siguiente click volvía a leer el valor viejo.

!!! failure "❌ Código de Pau (camino hasta la versión final)"
    ```js
    let contador = Number(spanCantidad.dataset.cantidad) // ❌ fuera de los listeners, fuga de estado

    botonMas.addEventListener("click", () => {
      if(contador > 0 && contador <= limite) contador++ // ❌ >0 no aplica a sumar; <= deja pasarse
    })

    contador = Math.min(limite, contador++) // ❌ el ++ se pisa con el valor viejo, queda congelado en 0

    // botón de restar, copiado sin adaptar:
    let contador = Number(spanCantidad,dataset.cantidad) // ❌ coma en vez de punto
    contador = Math.max(limite, cantador -1) // ❌ typo "cantador", piso equivocado (limite en vez de 0)
    ```

!!! success "✅ Versión corregida"
    ```js
    function activarStepperConLimite(botonMas, botonMenos, spanCantidad, limite) {
      botonMas.addEventListener("click", () => {
        let contador = Number(spanCantidad.dataset.cantidad);
        contador = Math.min(limite, contador + 1);
        spanCantidad.dataset.cantidad = contador;
        spanCantidad.textContent = `${contador}`;
      });

      botonMenos.addEventListener("click", () => {
        let contador = Number(spanCantidad.dataset.cantidad);
        contador = Math.max(0, contador - 1);
        spanCantidad.dataset.cantidad = contador;
        spanCantidad.textContent = `${contador}`;
      });
    }
    ```

🧠 **Lección:** `Math.min`/`Math.max` son la forma segura de fijar un límite (clamping) en vez de condiciones `if` con `<=`/`>=` propensas a errores de "por uno". Y el operador `++`/`--` DENTRO de una expresión cuyo resultado se reasigna a la misma variable es una trampa — el efecto secundario se pierde, tapado por la propia asignación (mismo mecanismo de fondo que "Postfix vs. prefix" ya anotado el 13/08).

### E8 — `filtrarPorNombreOCategoria(inputBusqueda, contenedorItems)` — ✅ Completado (4 fallos)

- **❌ `.contains()` sobre un string:** no existe en strings de JS, es `.includes()`.
- **❌ `toggle()` solo dentro del `if` de coincidencia, forzado a `true`:** ocultaba justo lo que SÍ coincidía, y lo que no coincidía nunca se tocaba.
- **❌ Acumulador declarado FUERA del `forEach`:** `let son = false` compartida entre todas las vueltas — una vez que un ítem la ponía en `true`, todos los siguientes heredaban ese valor aunque no coincidieran.
- **❌ `toggle()` fuera del `forEach` por error:** `x` ya no existía ahí (`ReferenceError`).

!!! failure "❌ Código de Pau (camino hasta la versión final)"
    ```js
    let son = false; // ❌ fuera del forEach, se comparte entre todos los ítems
    contenedorItems.querySelectorAll(".item-producto").forEach(x => {
      if(x.dataset.nombre.toLowerCase().contains(item) || x.dataset.categoria.toLowerCase().contains(item)) // ❌ .contains() no existe en strings
        son = true;
    })
    x.classList.toggle("hidden", !son) // ❌ fuera del forEach, x no existe
    ```

!!! success "✅ Versión corregida"
    ```js
    function filtrarPorNombreOCategoria(inputBusqueda, contenedorItems) {
      inputBusqueda.addEventListener("input", (e) => {
        const item = e.target.value.toLowerCase();
        contenedorItems.querySelectorAll(".item-producto").forEach(x => {
          let son = false;
          if (x.dataset.nombre.toLowerCase().includes(item) || x.dataset.categoria.toLowerCase().includes(item))
            son = true;
          x.classList.toggle("hidden", !son);
        });
      });
    }
    ```

🧠 **Lección:** un acumulador o bandera que necesita reiniciarse en cada ítem tiene que declararse DENTRO del bucle — fuera del bucle se comparte entre todas las vueltas y arrastra el resultado del ítem anterior.

### E10 — `activarSeleccionGrid(contenedor)` — ✅ Completado (4 fallos)

- **❌ Expresión sin asignar:** `x.checked` solo, varias veces, sin `=` — no hace nada.
- **❌ Gap de teoría real:** no sabía que un checkbox se marca solo al clickearlo (comportamiento nativo del navegador, el `change` llega DESPUÉS).
- **❌ Acumulador inicializado con el valor equivocado:** `let todasMarcadas = master.checked` — si el maestro estaba en `false` y se marcaba el último producto que faltaba, el acumulador arrancaba en `false` y nada en el bucle lo subía a `true` (el `if` solo baja a `false`, nunca sube). El maestro quedaba sin marcar aunque todos los productos ya estuvieran marcados.
- **❌ Variable compartida entre dos ramas de lógica distinta:** al corregir el acumulador a `true` fijo, se rompió la otra rama — `x.checked = todasMarcadas` (ahora siempre `true`) marcaba TODOS los productos aunque el maestro se acabara de DESMARCAR.

!!! failure "❌ Código de Pau (camino hasta la versión final)"
    ```js
    let todasMarcadas = master.checked // ❌ arranca en false si el maestro estaba desmarcado, nunca sube a true
    contenedorItems.forEach(x => {
      if(e.target === master)
        x.checked = todasMarcadas // ❌ ahora comparte variable con la otra rama, se rompe si todasMarcadas es fija
      else{
        if(!x.checked) todasMarcadas = false;
      }
    })
    ```

!!! success "✅ Versión corregida"
    ```js
    function activarSeleccionGrid(contenedor) {
      const master = contenedor.querySelector("#check-maestro-repaso");

      contenedor.addEventListener("change", (e) => {
        let todasMarcadas = true;

        contenedor.querySelectorAll(".check-producto").forEach(x => {
          if (e.target === master) {
            x.checked = master.checked;
          } else {
            if (!x.checked) todasMarcadas = false;
          }
        });

        if (e.target !== master) master.checked = todasMarcadas;
      });
    }
    ```

🧠 **Lección:** cuando dos ramas de lógica distinta comparten una misma variable, cualquier cambio pensado para una rompe la otra sin avisar — cada rama necesita su propia fuente de verdad (leer el elemento real cuando haga falta, no una variable con doble propósito). Y el `change` de un checkbox se dispara DESPUÉS de que el navegador ya actualizó `.checked` por su cuenta — nunca hace falta asignarlo a mano para el que el usuario tocó directo, solo para sincronizar otros elementos.

## 🔎 Por qué fallaron — resumen del bloque

Patrón dominante del día: **confundir el TIPO de dato que devuelve un método con el que hace falta para la lógica** — `getAttribute()` da siempre string, nunca booleano (E2); `dataset` da siempre string (ya consolidado, sin fallo en E3); comparar string contra booleano con `===` o negarlo con `!` nunca funciona como se espera. Segundo patrón: **métodos que comparten nombre pero pertenecen a objetos distintos** — `closest()` llamado como función suelta en vez de método (E1), `classList.contains()` vs `Element.contains()` (E6), `classList.remove()` sin el "force" de `toggle()` (E2). Tercer patrón: **acumuladores y estado mal ubicados** — declarados fuera del bucle que los resetea (E8), leídos una sola vez fuera de un listener que los necesita frescos (E7), o compartidos entre dos ramas de lógica que no deberían tocar la misma variable (E10). Y una reincidencia directa: `&&` vs `||` en validación de rangos (E5), ya marcado como "a reforzar" desde antes de hoy.

### R1 — `resaltarFilaSeleccionada(tabla)` — ✅ Completado (2 fallos)

- **❌ `closest()` con typo y sin el punto del selector:** `e.target.closeset("fila-tabla")` — falta la `t` de `closest`, y sin el punto busca una etiqueta `<fila-tabla>` inexistente en vez de la clase.

!!! failure "❌ Código de Pau (camino hasta la versión final)"
    ```js
    let fila = e.target.closeset("fila-tabla") // ❌ typo "closest" + falta el punto del selector

      fila.classList.toggle("fila--activa", x === fila) // ❌ toggle() sobre "fila" (fija), nunca sobre "x"
    })
    ```

!!! success "✅ Versión corregida"
    ```js
    function resaltarFilaSeleccionada(tabla) {
      tabla.addEventListener("click", (e) => {
        const fila = e.target.closest(".fila-tabla");
        if (!fila) return;

        tabla.querySelectorAll(".fila-tabla").forEach(x => {
          x.classList.toggle("fila--activa", x === fila);
        });
      });
    }
    ```

🧠 **Lección:** en un `forEach` de exclusividad, el método siempre se llama sobre la variable del PARÁMETRO del callback (la de cada vuelta), nunca sobre una variable fija capturada de afuera — si no, todas las vueltas terminan tocando al mismo elemento.

### R2 — `sincronizarInterruptorTema(boton, panel)` — ✅ Completado (1 fallo)

- **❌ `.target` sobre un elemento que no es un evento:** `panel.target.classList.toggle(...)` — `panel` ya es el elemento en sí (parámetro de la función), no tiene `.target` (esa propiedad es de los eventos).

!!! failure "❌ Código de Pau (intento 1)"

    function sincronizarInterruptorTema(boton, panel) {

🧠 **Lección:** mejora de enfoque real respecto al acordeón del Bloque 2 — en vez de leer el `aria-pressed` viejo e invertirlo a mano (el camino largo que costó tanto esta mañana), se usó el valor de RETORNO de `classList.toggle()`, que ya es un booleano real (`true` si la clase quedó puesta).
