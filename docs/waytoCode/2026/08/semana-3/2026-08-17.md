### Ejercicio 11 — Filtros Twig (`length`, `date()`) — ✅ Completado (1 fallo)

- **❌ Error conceptual:** dentro del `{% for tarea in lista %}`, usó `lista.createdAt` en vez de `tarea.createdAt` — confundió la colección completa (`lista`) con la variable de la vuelta actual del loop (`tarea`).

!!! failure "❌ Código de Pau (intento 1)"
    ```twig
    {% for tarea in lista %}
    <li>{{lista.createdAt|date('d/m/Y')}}</li>
    {# ❌ "lista" es el array completo, no tiene createdAt — usa "tarea" #}
    {% include 'tareas/_item.html.twig' with {tarea: tarea} %}
    ```

!!! success "✅ Versión corregida"
    ```twig
    {% for tarea in lista %}
    <li>{{tarea.createdAt|date('d/m/Y')}}</li>
    {% include 'tareas/_item.html.twig' with {tarea: tarea} %}
    ```

🧠 **Lección:** el fallo no tiró ningún error — Twig no encuentra `createdAt` en `lista` (un array), resuelve la expresión como `null`, y el filtro `date()` sobre `null` no se queja: usa la fecha de HOY por defecto. En pantalla se veía una fecha con pinta de válida, pero era la misma para todas las tareas, sin relación con cuándo se crearon de verdad. Mismo patrón de fallo silencioso que `flush()` sin `$em->` (Fallo 23) — no hay excepción que avise, hay que verificar el dato contra la realidad, no solo contra "¿explotó o no?".

### F3 — `GET/POST /tareas/crear` — ✅ Completado (1 fallo)

- **❌ Error conceptual:** creó la `Tarea` y la pasó al formulario sin rellenar `done`/`createdAt` antes — como esos campos no están en `TareaType`, se quedaban `null`, y las columnas son `NOT NULL` en la base de datos.

!!! failure "❌ Código de Pau (intento 1)"
    ```php
    $tarea = new Tarea();
    $form = $this->createForm(TareaType::class, $tarea);
    // done y createdAt nunca se rellenan
    ```

!!! success "✅ Versión corregida"
    ```php
    $tarea = new Tarea();
    $tarea->setDone(false);
    $tarea->setCreatedAt(new \DateTimeImmutable());
    $form = $this->createForm(TareaType::class, $tarea);
    ```

🧠 **Lección:** los campos que NO están en el formulario tienen que llegar ya resueltos en la entidad ANTES de crear el formulario — nadie más los va a rellenar. Sin este paso, el `flush()` habría explotado por violar la restricción `NOT NULL`.

### F5 — `GET/POST /tareas/{id}/editar` — ✅ Completado (1 fallo)

- **❌ Error conceptual:** usaba `$request` dentro del método sin declararlo como parámetro — tener el `use Request` arriba solo importa la clase, no inyecta el objeto.

!!! failure "❌ Código de Pau (intento 1)"
    ```php
    public function tareaEditada(Tarea $tarea, EntityManagerInterface $em): Response
    {
        $form = $this->createForm(TareaType::class, $tarea);
        $form->handleRequest($request); // ❌ $request no existe en este método
    ```

!!! success "✅ Versión corregida"
    ```php
    public function tareaEditada(Request $request, Tarea $tarea, EntityManagerInterface $em): Response
    ```

🧠 **Lección:** cada método pide explícitamente cada dependencia que use, como parámetro de su propia firma — el `use` de la clase y la inyección del objeto son dos cosas distintas.

### F7 — `done` como `ChoiceType` expandido, solo en edición — ✅ Completado (4 fallos)

- **❌ Error 1:** el campo se llamaba `edicion`, pero `Tarea` no tiene esa propiedad — solo `title`, `done`, `createdAt`.
- **❌ Error 2:** el campo se añadía SIEMPRE en `buildForm()`, sin condición — iba a aparecer también en el formulario de crear.
- **❌ Error 3:** faltaba `'expanded' => true` — sin eso, sale como `<select>`, no como radio buttons.
- **❌ Error 4:** aunque `configureOptions()` tenía el default correcto, el controlador nunca pasaba el valor distinto en `editar()` — la opción se quedaba siempre en `false`.

!!! failure "❌ Código de Pau (intento 1)"
    ```php
    // buildForm() — sin condición
    ->add('edicion', ChoiceType::class, [
        'choices' => ['Pendiente' => false, "Hecha" => true],
    ]);

    // controlador — sin pasar la opción
    $form = $this->createForm(TareaType::class, $tarea);
    ```

!!! success "✅ Versión corregida"
    ```php
    // buildForm()
    if ($options['edicion']) {
        $builder->add('done', ChoiceType::class, [
            'choices' => ['Pendiente' => false, 'Hecha' => true],
            'expanded' => true,
        ]);
    }

    // controlador, solo en editar()
    $form = $this->createForm(TareaType::class, $tarea, ['edicion' => true]);
    ```

🧠 **Lección:** el patrón de opción personalizada (del PDF, con `esAdmin`) tiene TRES piezas sincronizadas — default en `configureOptions()`, lectura con `if` dentro de `buildForm()`, y el valor real pasado desde el controlador. Acertar solo la primera no alcanza. Marcado explícitamente para reforzar en próximos ejercicios (ver `GOTCHAS.md`).

### F8 — Formulario de búsqueda sin entidad + filtro `LIKE` — ✅ Completado (5 fallos)

- **❌ Error 1:** `Request $request` no declarado en `index()` (reincidencia del error de F5) + guardó el valor en `$titulo` pero comprobó/usó `$termino` (nunca definida) + una línea muerta (`new Tarea()` sin usar).
- **❌ Error 2:** en `TareaRepository::findByTitle()`, `n.name` en vez de `n.title` — `Tarea` no tiene propiedad `name`.
- **❌ Error 3:** copió el patrón completo de `crear()`/`editar()` (`handleRequest` + `isSubmitted` + `persist` + `redirect`) a un formulario de solo lectura — generó variables inexistentes (`$em`, `$tarea`) y además el redirect habría borrado el filtro buscado.

### F10 — De `form_widget` a `form_row` individual — ✅ Completado (2 fallos)

- **❌ Error 1:** al reescribir la plantilla, se perdió el `{% extends 'base.html.twig' %}` — por confundirlo con la regla de "un parcial no lleva extends" (que no aplica acá: esta plantilla se renderiza DIRECTO desde el controlador, no se incluye).
- **❌ Error 2:** al pasar de `form_widget` (que pinta todo automáticamente) a `form_row` uno por uno, se olvidó el campo `done` — que solo existe en modo edición. Al corregirlo con `{% if formularioTarea.done is defined %}`, quedó sin su `{% endif %}`, rompiendo la plantilla entera (Twig exige etiquetas balanceadas).

!!! failure "❌ Código de Pau (intento 1 y 2)"
    ```twig
    {# sin extends #}
    {% block body %}
        {{ form_row(formularioTarea.title) }}
        {# falta el campo done por completo #}
    ```
    ```twig
    {% if formularioTarea.done is defined %}
    {{ form_row(formularioTarea.done) }}
    {# ❌ falta {% endif %} #}
    ```

!!! success "✅ Versión corregida"
    ```twig
    {% extends 'base.html.twig' %}
    {% block body %}
        {{ form_row(formularioTarea.title) }}
        {% if formularioTarea.done is defined %}
            {{ form_row(formularioTarea.done) }}
        {% endif %}
        {{ form_row(formularioTarea.guardar) }}
    {% endblock %}
    ```

🧠 **Lección:** una página renderizada directo por el controlador (`$this->render(...)`) SIEMPRE lleva `extends` — la regla de "sin extends" es solo para parciales de `include`. Y al pasar de renderizado automático a manual, hay que enumerar TODOS los campos posibles, incluidos los condicionales — con `is defined` para los que no siempre existen.
