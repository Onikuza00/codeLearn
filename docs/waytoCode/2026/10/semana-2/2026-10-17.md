### Decisiones de reparto

- Cada concepto vive en un solo sitio: lo de JSX en JSX, lo de props en Props, `clsx` solo en CSS en React.
- «Componentes puros» pasa a 2.2 useState como primer capítulo, porque se necesita al entrar en estado.
- Descartados: «Tu UI como un árbol», «Props inmutables», «La prop `children`» y el bloque de Renderizado (condicional y listas), que no aportaba. Las referencias a esos capítulos se quitaron del resto.
- Las funciones como props van a 2.1 Eventos, y Eventos queda en el pilar 2, antes de `useState`.
- **Estilaje con Tailwind como estándar:** se comprobó en State of CSS 2026 (la encuesta oficial lo sigue tratando como referente; sin cifras de CSS Modules). Orden: mecánica del CSS en React, Tailwind y, como última opción, CSS Modules.

#### E1 — Proyecto base con Vite y Tailwind — ✅ (2 fallos)

!!! success "✅ Versión corregida (`App.jsx`)"
    ```jsx
    function App() {
      return (
        <h1 className="text-center text-7xl font-bold text-blue-800 p-3">
          Hola React
        </h1>
      )
    }
    export default App
    ```

!!! failure "❌ Fallo 1 — `class` en vez de `className` en JSX"
    ```jsx
    <h1 class="text-3xl font-bold text-blue-700">Hola React!</h1>   // ❌
    ```
    React 19 lo tolera, pero avisa en consola.

    🧠 **Lección:** JSX no es HTML: se compila a JavaScript, donde `class` es palabra reservada. El atributo se llama `className`.

!!! failure "❌ Fallo 2 — clases que no existen en Tailwind (`align-center`, `align-items-center`)"
    ```jsx
    <h1 className="flex align-center ...">          // ❌ no es una clase de Tailwind
    <h1 className="grid align-items-center ...">    // ❌ es el nombre de la propiedad CSS, no la clase
    ```
    El título seguía pegado a la izquierda. Lo que pedía el enunciado era centrar el texto en horizontal.

    🧠 **Lección:** el nombre de una clase de Tailwind no es el nombre de la propiedad CSS. Se busca en la documentación por lo que se quiere conseguir («text align»), no por la propiedad que se recuerda. Y centrar texto (`text-align`) y alinear un contenedor (`align-items`) son cosas distintas, en ejes distintos.

#### E2 — Personaliza el index.html y el logo — ✅ (4 fallos)

!!! success "✅ Versión corregida (`App.jsx` e `index.html`)"
    ```jsx
    import imagen from "./assets/react.svg"

    function App() {
      return (
        <div className="flex flex-col justify-center items-center gap-4">
          <h1 className="text-center text-7xl font-bold text-blue-800 p-3">Hola React</h1>
          <img className="w-[200px]" src={imagen} alt="Logo de React" />
        </div>
      )
    }
    ```
    ```html
    <link rel="icon" type="image/svg+xml" href="/favicon.svg" />
    ```

!!! failure "❌ Fallo 1 — `class` en vez de `className` (reincidencia del E1, mismo día)"
    ```jsx
    <div class="flex flex-col ...">   // ❌ en JSX es className
    <img class=" w-50" ... />         // ❌
    ```
    🧠 **Lección:** JSX se compila a JavaScript y `class` está reservada; el atributo es `className`. Fallado dos veces en el mismo día.

!!! failure "❌ Fallo 2 — `import` de un SVG con llaves"
    ```jsx
    import {imagen} from "./assets/react.svg"   // ❌ un .svg solo exporta por defecto
    ```
    🧠 **Lección:** las llaves piden un export con nombre; un archivo de recurso solo tiene el export por defecto, que se importa sin llaves.

!!! failure "❌ Fallo 3 — expresión de JSX escrita entre comillas"
    ```jsx
    <img src="{imagen}" ... />   // ❌ es la cadena literal "{imagen}", no la variable
    ```
    🧠 **Lección:** en un atributo de JSX, o es una cadena entre comillas o es una expresión entre llaves, nunca las dos a la vez.

!!! failure "❌ Fallo 4 — ruta con `public/` en el `href` del favicon"
    ```html
    <link rel="icon" href="public/favicon.svg" />   <!-- ❌ lo de public/ se sirve desde la raíz -->
    ```
    🧠 **Lección:** Vite sirve `public/` desde `/`; el nombre de la carpeta no va en la ruta.

#### E3 — Hero sin JSX — ✅ (4 fallos)

!!! success "✅ Versión corregida (`Hero.jsx`)"
    ```jsx
    import { createElement } from "react"

    function Hero() {
      return (
        createElement("section", { className: "flex flex-col items-center gap-4 p-4 mt-6" },
          createElement("h2", { className: "text-5xl font-bold" }, "Lanza tu proyecto"),
          createElement("p", { className: "mt-2 text-gray-500 text-xl" }, "Una landing rápida con React."),
          createElement("a", { className: "rounded-2xl bg-blue-700 text-white px-4 py-2 font-semibold", href: "#planes" }, "Empezar"),
        )
      )
    }
    export default Hero
    ```

!!! failure "❌ Fallo 1 — `createElement` sin importar"
    ```jsx
    function Hero(){   // ❌ falta: import { createElement } from "react"
    ```
    🧠 **Lección:** con JSX, Vite inserta lo necesario; sin JSX, `createElement` es una función más y hay que importarla.

!!! failure "❌ Fallo 2 — el componente devolvía una función"
    ```jsx
    return () => {            // ❌ devuelve una función, y dentro no hay return
      createElement("section", ...)
    }
    ```
    🧠 **Lección:** un componente devuelve el elemento, no una función que lo construya. Y sin `return`, el valor se pierde.

!!! failure "❌ Fallo 3 — `href` como tercer argumento en vez de dentro de las propiedades"
    ```jsx
    createElement("a", { className: "..." }, { href: "#planes" }, "Empezar")   // ❌ un objeto como hijo
    ```
    🧠 **Lección:** `createElement(tipo, propiedades, ...hijos)`: las propiedades son un solo objeto en el 2.º hueco; del 3.º en adelante todo es contenido, y un objeto no se puede pintar.

!!! failure "❌ Fallo 4 — `align-items` en Tailwind y `<button>` en lugar de párrafo"
    ```jsx
    { className: "... align-items ..." }   // ❌ no es clase de Tailwind (`items-center`)
    createElement("button", ..., "«Una landing rápida con React.»")   // ❌ pedía un párrafo
    ```
    🧠 **Lección:** reincidencia del E1: clase de Tailwind ≠ propiedad CSS. Y el elemento se elige por su significado (párrafo → `p`), no por cómo se ve.

#### E4 — Ventajas: la misma lista de dos formas — ✅ (2 fallos, cerrado con pendientes)

!!! success "✅ Versión corregida (`createElement`)"
    ```jsx
    createElement("section", { className: "..." },
      createElement("h2", { className: "font-semibold text-2xl" }, "Por qué elegirnos"),
      createElement("ul", { className: "flex flex-col gap-1" },
        createElement("li", null, "✓ Rápido"),
        createElement("li", null, "✓ Seguro"),
        createElement("li", null, "✓ Accesible"),
      ),
    )
    ```

!!! failure "❌ Fallo 1 — el `ul` se cerraba antes de recibir los `li`"
    ```jsx
    createElement("ul", {className: "flex flex-col gap-1"}),   // ❌ el ) cierra el ul vacío
    createElement("li","✓ Rápido"),                          // ❌ queda como hermano del ul
    ```
    🧠 **Lección:** los hijos van dentro de los paréntesis de su padre. En `createElement`, anidar es cuestión de dónde se cierra el `)`.

!!! failure "❌ Fallo 2 — texto en el hueco de las propiedades"
    ```jsx
    createElement("li", "✓ Rápido")   // ❌ el 2.º hueco son propiedades; el texto no se pinta
    ```
    🧠 **Lección:** `createElement(tipo, propiedades, ...hijos)`. Sin propiedades, el 2.º hueco es `null`. Reincidencia conceptual del E3 (fallo 3).
