## 🧩 Ejercicios

### D6 — Interfaz `TaskSorter` + implementaciones — 🟡 Parcial

| ✅ Sin fallos | ❌ Con fallos |
|:---:|:---:|
| 0 | 2 |

- `TaskSorter.php` (interfaz): sin fallos tras el repaso de teoría.
- `ByPrioritySorter.php`: completo, con fallos.
- `ByDueDateSorter.php`: pendiente.

!!! failure "❌ Confundir interfaz con clase, dos veces"
    Primer intento de `TaskSorter.php`:
    ```php
    class TaskSorter
    {
        public function sort(array $task):array
        {
             return sort($task);
        }
    }
    ```
    Una clase con cuerpo real, en vez de un contrato vacío.

!!! success "✅ Corregido"
    ```php
    interface TaskSorter
    {
        public function sort(array $tasks): array;
    }
    ```

🧠 **Lección:** una interfaz declara la firma de un método, nunca su implementación. `class` con lógica dentro no es lo mismo que `interface` — son palabras clave distintas del lenguaje.

!!! failure "❌ `extends` para cumplir un contrato, y nombre de clase duplicado"
    ```php
    class TaskSorter extends TaskSorter   // ❌ mismo nombre que la interfaz + extends en vez de implements
    {
        public function sort(array $task):array
        {
            return sort($task);
        }
    }
    ```
    Dos fallos a la vez: `extends` es para heredar código de una clase padre, no para cumplir un contrato de interfaz (eso es `implements`); y el archivo `ByPrioritySorter.php` declaraba una clase llamada `TaskSorter` — mismo nombre que la interfaz, en el mismo namespace, lo que PHP no permite (`Cannot declare class ... because the name is already in use`).

!!! success "✅ Corregido"
    ```php
    class ByPrioritySorter implements TaskSorter
    {
        public function sort(array $tasks): array
        {
            usort($tasks, function ($a, $b) {
                $rangoA = match ($a->getPriority()) {
                    TaskPriority::High => 0,
                    TaskPriority::Medium => 1,
                    TaskPriority::Low => 2,
                    null => 3,
                };
                $rangoB = match ($b->getPriority()) {
                    TaskPriority::High => 0,
                    TaskPriority::Medium => 1,
                    TaskPriority::Low => 2,
                    null => 3,
                };

                return $rangoA <=> $rangoB;
            });

            return $tasks;
        }
    }
    ```

🧠 **Lección:** el nombre de la clase tiene que coincidir con el del archivo (PSR-4), y nunca puede repetir el nombre de la interfaz que implementa en el mismo namespace. Fallo intermedio también registrado: en el primer borrador del `match`, `$rangoB` comparaba `$a->getPriority()` en vez de `$b->getPriority()` — copiar y pegar sin cambiar la variable interna hacía que la comparación siempre diera `0`, sin ordenar nada.

### E1 — `base.html.twig`, header de la app — ✅ Completado (varios fallos)

- **❌ Clases de Tailwind inventadas o con typo, cuatro veces:** `max-w-4x1` (uno por otra, no `4xl`), `min-h-dvh-75` (unidad `dvh` inexistente con ese guion), `min-w-300` y `h-30` (números fuera de la escala real de Tailwind, que salta de `28` a `32`).
- **❌ Sintaxis de variante mal formada, tres veces:** `:flex-col`, `:focus-text-yellow-700`, `:hover-bg-white`/`:hover-text-sky-900` — los dos puntos van entre la variante y la utilidad (`hover:bg-white`), nunca delante de todo ni sustituyendo el guion interno de la utilidad.
- **❌ `sort()` de PHP no es `usort()`:** reincidencia del mismo fallo que en `TaskSorter` — devuelve booleano, no el array, y no sirve para un criterio propio.
- **❌ `{{ tasks.title }}` para el nombre del producto:** usaba una variable de otra plantilla (una colección de tareas, sin `.title`) para el texto de marca, que debía ser fijo.
- **❌ Botón vacío y sin navegación:** `<button>` sin texto ni acción, en vez de un `<a>` con `href` a la ruta de crear tarea.
- **❌ Rutas cruzadas tras un cambio:** el enlace de marca y el del botón intercambiaron sus destinos al corregir uno de los dos.
- **❌ `max-width` en el header en vez de en el contenido:** con `inset-x-0 fixed`, aplicar además `max-width` a la propia barra la deja pegada a un lado con hueco vacío al otro, en vez de cubrir todo el ancho.

!!! success "✅ Estado final"
    ```twig
    <header class="top-0 inset-x-0 bg-sky-500 fixed z-10 flex flex-col md:flex-row gap-4 md:justify-between items-center px-3 py-3 md:py-0 md:px-9 h-32 md:h-16">
        <a href="{{ path('app_dashboard') }}" class="focus:text-yellow-700">
            <span class="text-white text-lg md:text-xl font-semibold uppercase">Dashboard de Tareas</span>
        </a>
        <a href="{{ path('task_new') }}"
           class="px-3 py-2 text-white bg-sky-900 rounded-lg font-semibold hover:bg-white hover:text-sky-900 transition">
            Nueva tarea
        </a>
    </header>
    ```

🧠 **Lección:** un elemento `fixed` sale del flujo del documento — el contenido de debajo necesita un `padding-top` de compensación igual a la altura real del header, o quedará tapado. Con altura distinta por breakpoint (`h-32` en móvil, `h-16` en escritorio), esa compensación también tiene que ser responsive.
