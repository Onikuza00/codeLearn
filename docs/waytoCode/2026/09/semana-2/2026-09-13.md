### Curso de API de Claude — Uso de herramientas (rehecho desde 0) — ✅ Completado (varios fallos)

Ejercicio completo (`IA/practica/Claude/Tools/tools.js`) rehecho desde cero, guiado paso a paso, sin copiar de la teoría.

- **❌** Código de los docs pegado tal cual en el archivo (2 veces): la función `getCurrentDatetime` de la teoría, y luego `runConversation` pegado antes de tener sus dependencias (`addAssistantMessage`) escritas.
- **❌** `const respuesta = chat(messages);` sin `await` — imprimía `Promise { <pending> }`.
- **❌** `await chat(messages).find(...)` — `await` se aplica a toda la cadena `chat(messages).find(...)`, no solo a `chat(messages)`; `.find()` corría sobre una Promise sin resolver.
- **❌** `try`/`catch` envolviendo el bucle `for` entero en vez de cada iteración, con el `catch` vacío (sin `push` ni `return`).
- **❌** `let toolResultBlock;` declarado dentro del `try`, inaccesible desde el `catch` por scoping de bloque.
- **❌** `addAssistantMessage` guardando el objeto de respuesta completo como `content` en vez de `.content` — error real de la API: `messages.1.content: Input should be a valid array`.
- **❌** Typo `stream.on('inputJon', ...)` en el ejercicio de streaming.

!!! failure "❌ Precedencia de `await` + `.content` sin desempaquetar"
    ```js
    const llamadaFinal = await chat(messages).find((block) => block.type === 'text');
    // ❌ await solo aplica a chat(messages), .find() corre sobre la Promise sin resolver

    function addAssistantMessage(messages, response) {
      messages.push({ role: 'assistant', content: response }); // ❌ response es el mensaje completo, no su .content
    }
    ```

!!! success "✅ Versión corregida"
    ```js
    const llamadaFinal = (await chat(messages)).find((block) => block.type === 'text').text;

    function addAssistantMessage(messages, response) {
      messages.push({ role: 'assistant', content: response.content });
    }
    ```

🧠 **Lección:** `await` se aplica a toda la expresión que sigue, no solo al primer término — mismo patrón de precedencia que ya está en `GOTCHAS.md`. Y la API de Claude exige que `content` sea siempre un array de bloques, nunca el objeto de respuesta completo.

### Curso de API de Claude — RAG y búsqueda agencial (bloque nuevo) — ✅ Completado (varios fallos)

Ejercicio construido antes que la teoría (orden invertido a petición explícita): `IA/practica/Claude/RAG/rag.js`. Segmentación por párrafo/tamaño/frase, búsqueda léxica, embeddings con VoyageAI, similitud/distancia coseno, y refactor final a una clase `VectorIndex`.

- **❌** `chunkByParagraph`: `split('\n')` en vez de `split('\n\n')`, y `e.trim !== " "` (sin ejecutar `trim()`, comparando contra un espacio en vez de contra `''`).
- **❌** `query.split(' ').toLowerCase()` — `split()` devuelve un array, `.toLowerCase()` es método de string; el orden correcto es `query.toLowerCase().split(' ')`.
- **❌** Comentario invertido en `chunkBySize`: decía "si el chunk llegó al final, retrocedemos" cuando es justo al revés.
- **❌** `const embeeding = generateEmbedding(result[0]);` sin `await`.
- **❌** `console.log(datos)` puesto **antes** de `const datos = await respuesta.json();` — `ReferenceError` por *temporal dead zone*.
- **❌** Argumentos invertidos en `generateEmbeddingsBatch` al menos 3 veces seguidas: `(query, ['query'])`, `(['query'], query)`, `(['document'], chunk)` — hasta dar con `([query], 'query')`.
- **❌ Real, no de código:** límite de 3 peticiones/minuto de la cuenta gratuita de VoyageAI saltando al hacer una petición por chunk sin agrupar — resuelto pasando a `generateEmbeddingsBatch` (un array de textos, una sola llamada).

!!! failure "❌ Orden de argumentos de `generateEmbeddingsBatch(textos, inputType)`"
    ```js
    const queryEmbedding = await generateEmbeddingsBatch(['query'], query);
    // ❌ 'query' (el texto literal) como textos, la pregunta real como inputType — al revés

    const chunkEmbeddings = await Promise.all(
      chunks.map((chunk) => generateEmbeddingsBatch(['document'], chunk))
    );
    // ❌ misma inversión, y además vuelve a llamar la API una vez por chunk (deshace el batch)
    ```

!!! success "✅ Versión corregida"
    ```js
    const [queryEmbedding] = await generateEmbeddingsBatch([query], 'query');
    const chunkEmbeddings = await generateEmbeddingsBatch(chunks, 'document');
    ```

🧠 **Lección:** `chunks` ya era un array de textos (la forma que la función espera), no hacía falta envolverlo — pero `query` era un string suelto y sí. La confusión repetida fue swapear qué parámetro es el array de textos y cuál el tipo (`'query'`/`'document'`), no el concepto del batch en sí.

## 🧠 Fallos y aprendizajes

- El patrón de precedencia de `await` sobre una cadena completa (`await x.y()` vs `(await x).y()`) volvió a aparecer, ya registrado como refuerzo en `GOTCHAS.md`.
- Confusión nueva y recurrente hoy: orden de parámetros en funciones con más de un argumento del mismo "tipo aparente" (dos strings, uno de los cuales hay que envolver en array y el otro no) — vale la pena vigilar este patrón en próximos ejercicios con funciones de 2+ parámetros.
- Los límites de cuentas gratuitas de APIs externas (VoyageAI, 3 RPM) son un fallo real de infraestructura, no de código — pero se resuelve con buen diseño (batch de peticiones) en vez de solo reintentar.
