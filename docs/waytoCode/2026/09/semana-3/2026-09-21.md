#### E1 — `validarRangoNumerico(inputEdad, spanError)` — ✅ Completado (2 fallos)

- **❌ Fallo 1:** el `else` leía `spanError.textContent` antes de que nadie lo escribiera; con el span vacío, `setCustomValidity("")` dejaba el campo **válido** con un 10.
- **❌ Fallo 2:** media corrección repetida: arregló una mitad de cada rama y dejó la otra sin tocar; después puso `spanError.textContent = " "` para pasar el test (`length > 0`) sin mostrar ningún mensaje.

!!! success "✅ Versión corregida"
    ```js
    function validarRangoNumerico(inputEdad, spanError) {
      const edad = Number(inputEdad.value)
      const mensaje = "Error en el rango de edades"

      if(edad >= 18 && edad <= 65){
        spanError.textContent = "";
        inputEdad.setCustomValidity('');
      }else{
        inputEdad.setCustomValidity(mensaje);
        spanError.textContent = mensaje;
      }
    }
    ```

!!! failure "❌ Código de Pau (primera versión)"
    ```js
    function validarRangoNumerico(inputEdad, spanError) {
      let edad = Number(inputEdad.value)

      if(edad >= 18 && edad <= 65){
        inputEdad.setCustomValidity('');
      }else{
        inputEdad.setCustomValidity(spanError.textContent); // ❌ el span está vacío: nadie ha escrito el mensaje → "" = válido
      }
      // ❌ ninguna rama toca el <span>
    ```

🧠 **Lección:** cada rama tiene que tocar los dos estados (lo que ve el usuario y la validez del campo), y un valor se escribe antes de leerse. Un test blando (`length > 0`) no sustituye al enunciado: código que acierta por casualidad.

#### E2 — `validarCodigoPostal(inputCodigo, spanError)` — ✅ Completado (4 fallos)

- **❌ Fallo 1:** `.contains()` sobre un string: no existe (es de `Element` y `classList`); en strings es `.includes()`. También intentó `input.length` sobre el elemento en vez de `input.value.length`.
- **❌ Fallo 2:** `"0123456789".includes(codigoEntero)` busca el código como un trozo seguido, no carácter a carácter: da `true` para `"12345"` y `false` para `"13579"`. Los papeles de `includes` estaban invertidos.
- **❌ Fallo 3:** confundió `map` (transforma) con `every` (pregunta si todos cumplen), y `every` sobre un string sin `split("")`.
- **❌ Fallo 4:** rama válida con `spanError.textContent = " "` en vez de `""`: el test exige vacío.

!!! success "✅ Versión corregida (opción A: `!isNaN`)"
    ```js
    function validarCodigoPostal(inputCodigo, spanError) {
      const codi = inputCodigo.value
      if ((codi.length === 5) && !isNaN(codi)) {
        inputCodigo.setCustomValidity(spanError.textContent = "")
      } else {
        inputCodigo.setCustomValidity(spanError.textContent = "El código postal debe tener 5 dígitos")
      }
    }
    ```

!!! failure "❌ Código de Pau (versión guardada)"
    ```js
    function validarCodigoPostal(inputCodigo, spanError) {
      const mensaje = "CP invàlido"
      if(inputCodigo.value.length === 5 && inputCodigo.value.contains("0123456789")){ // ❌ contains no existe en strings; roles invertidos
        inputCodigo.setCustomValidity("")
        spanError.textContent = " "  // ❌ un espacio no es "vacío"
      }else{
        input.Codigo.setCustomValidity(mensaje)
        spanError.textContent = mensaje;
      }
    }
    ```

🧠 **Lección:** elemento frente a valor (`input.length` frente a `input.value.length`), y `a.includes(b)` pregunta si `a` contiene entero a `b`. Decisión consciente: `!isNaN` valida por conversión, no por carácter, y deja pasar `"12.34"`, `"-1234"` y cinco espacios; `every` con los dígitos habría cumplido el enunciado al pie de la letra.

#### E3 — `validarConfirmacionEmail(email, confirmarEmail)` — ✅ Completado (2 fallos)

- **❌ Fallo 1:** marcó `email` en vez de `confirmarEmail` (reincidencia del fallo 40 de `GOTCHAS.md`).
- **❌ Fallo 2:** media corrección: arregló el `if` pero el `else` seguía limpiando `email`, así que `confirmarEmail` quedaba inválido para siempre tras corregir.

!!! success "✅ Versión corregida"

    ```js
    function validarConfirmacionEmail(email, confirmarEmail) {
      if(email.value !== confirmarEmail.value){
        confirmarEmail.setCustomValidity("Los emails no coinciden")
      }else{
        confirmarEmail.setCustomValidity("");
      }
    }
    ```

!!! failure "❌ Código de Pau (primera versión)"
    ```js
    function validarConfirmacionEmail(email, confirmarEmail) {
      if(email.value !== confirmarEmail.value){
        email.setCustomValidity("Error los ee-mails no coinciden") // ❌ el enunciado marca el campo de confirmación

    ```

🧠 **Lección:** el campo que se marca es el que señala el enunciado, no el primer parámetro que tienes a mano, y el mismo campo se marca y se limpia en las dos ramas.

#### E4 — `activarDropdownConCierre(boton, menu)` — ✅ Completado (2 fallos)

- **❌ Fallo 1:** el `document.addEventListener` estaba **dentro** del handler del botón. El click que abre el menú burbujea hasta `document`, ejecuta el listener recién registrado y lo cierra en el mismo click; además, cada click al botón registraba otro listener más.
- **❌ Fallo 2:** al tratar el botón, la condición decía "cierra si es fuera **o** es el botón" (`||`), justo al revés; después quitó la parte del botón en vez de corregirla (media corrección). "Fuera de dos cosas" exige `&&` con las dos negaciones.

!!! success "✅ Versión corregida"
    ```js
    function activarDropdownConCierre(boton, menu) {
      boton.addEventListener("click", () => {
        menu.classList.toggle("hidden")
      })

      document.addEventListener("click", (e) => {
        if(!menu.contains(e.target) && !boton.contains(e.target))
          menu.classList.add("hidden")
      })
    }
    ```

!!! failure "❌ Código de Pau (primera versión)"
    ```js
    function activarDropdownConCierre(boton, menu) {
      boton.addEventListener("click", () => {
        menu.classList.toggle("hiden")
        document.addEventListener("click", (e) => {  // ❌ listener registrado dentro de otro handler: se dispara con el mismo click que abre y se acumula
          if(!menu.contains(e.target))                // ❌ no excluye el click en el botón: cuenta como "fuera del menú"
            menu.classList.add("hidden")
        })
      })
    }
    ```

🧠 **Lección:** un listener se registra una sola vez, fuera de cualquier otro handler, porque el click que abre también burbujea a `document`. Y "fuera de A y de B" es `!A && !B` (De Morgan, como los rangos). `Element.contains(nodo)` era el `contains` correcto, y `boton.contains(boton)` es `true`.
