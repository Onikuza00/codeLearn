#### E1 — `moverArriba(lista)` — ✅ Completado (1 fallo)

!!! success "✅ Versión corregida"
    ```js
    function moverArriba(lista) {
      lista.addEventListener("click", (e) => {
        const btn = e.target.matches(".btn-subir")
        if(!btn) return
        const item = e.target.closest(".item-lista")
        const brother = item.previousElementSibling
        if(!brother) return
        lista.insertBefore(item, brother)
      })
    }
    ```

!!! failure "❌ Fallo 1 — `insertBefore` con el orden invertido"
    Copió el orden de `moverAbajo`, donde se mueve el hermano de abajo. Al subir, quien se mueve es el propio item.
    ```js
    lista.insertBefore(brother, item)   // ❌ deja al de arriba justo antes del item, donde ya estaba: no cambia nada
    ```
    Pulsando ▲ en C con `A, B, C, D`, la lista se quedaba en `A, B, C, D` en vez de `A, C, B, D`.

    🧠 **Lección:** `insertBefore(nodoAMover, referencia)`: se pregunta «¿quién se mueve?». Subir mueve el propio item; bajar mueve al vecino de abajo. Reincidencia del fallo 65 (23/08, 23/09 y hoy).

#### E2 — `activarAcordeonExclusivo(panel)` — ⏳ En curso (1 fallo hasta ahora)

Queda a medias: el listener, el guard, el flag `abierto` y el `forEach` sobre `.faq-item` están escritos, pero el cuerpo del `forEach` aún está vacío.

!!! failure "❌ Fallo 1 — comparar el string de `getAttribute` con un booleano"
    ```js
    const abierto = faq.getAttribute("aria-expanded") === true   // ❌ "true" === true es siempre false
    ```
    🧠 **Lección:** `getAttribute` devuelve siempre un **string** y `===` exige mismo tipo. El flag booleano se obtiene comparando con el string: `=== "true"`. Lo que se lee del DOM es texto y hay que convertirlo antes de razonar con ello.
