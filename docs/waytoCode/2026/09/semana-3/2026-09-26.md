#### E1 — `activarAcordeonExclusivo(panel)` — ✅ Completado (5 fallos)

!!! success "✅ Versión corregida"
    ```js
    function activarAcordeonExclusivo(panel) {
      panel.addEventListener("click", (e) => {
        const btn = e.target.closest(".faq-pregunta")
        if (!btn) return
        const respuesta = btn.nextElementSibling
        const estabaCerrada = respuesta.classList.contains("hidden")

        panel.querySelectorAll(".faq-pregunta").forEach(x => {
          x.setAttribute("aria-expanded", "false")
          x.nextElementSibling.classList.add("hidden")
        })

        if (estabaCerrada) {
          btn.setAttribute("aria-expanded", "true")
          respuesta.classList.remove("hidden")
        }
      })
    }
    ```

!!! failure "❌ Fallo 1 — comparar el string de `getAttribute` con un booleano"
    Reincidencia del jueves: `"true" === true` es siempre `false`.
    ```js
    const abierto = x.getAttribute("aria-expanded") === true   // ❌ getAttribute devuelve el TEXTO "true"
    ```
    🧠 **Lección:** lo que sale del DOM es texto. El booleano se obtiene comparando contra el string: `=== "true"`.

!!! failure "❌ Fallo 2 — usar un string como condición"
    ```js
    const abierto = x.getAttribute("aria-expanded", "true")   // ❌ getAttribute solo recibe un argumento; devuelve "true" o "false"
    if(abierto){ ... }                                         // ❌ "false" es un string no vacío: siempre es truthy
    ```
    🧠 **Lección:** un string no vacío es *truthy* aunque diga `"false"`. Antes de usar algo como condición, hay que convertirlo a booleano de verdad.

!!! failure "❌ Fallo 3 — la pulsada tiene dos casos y solo se trataba uno"
    ```js
    }else{
      if(!abierto){
        hermano.classList.remove("hidden")       // ❌ solo cubre "estaba cerrada"
        x.setAttribute("aria-expanded", "true")
      }                                          // ❌ sin rama para "estaba abierta": nunca se cerraba
    }
    ```
    Con dos clics seguidos en la misma pregunta, la segunda no se cerraba (test 3).

    🧠 **Lección:** un `if` sin `else` cubre un solo caso. Antes de escribirlo, tabla de casos: cada fila de la tabla necesita su código.

!!! failure "❌ Fallo 4 — preguntar la clase al elemento equivocado"
    ```js
    const activo = !btn.classList.contains("hidden")   // ❌ "hidden" está en la respuesta, no en el botón: siempre da true
    ```
    🧠 **Lección:** `classList.contains` se pregunta a quien **lleva** la clase, no a `e.target`. Ante la duda: «¿quién tiene esta clase?».

!!! failure "❌ Fallo 5 — guard clause perdida al reescribir"
    ```js
    const btn = e.target.closest(".faq-pregunta")
    const hermano = btn.nextElementSibling            // ❌ sin "if (!btn) return": un clic fuera de una pregunta lanza TypeError
    ```
    🧠 **Lección:** `closest` devuelve `null` si no encuentra nada. Guard clause (early return) siempre justo después.

    ```js
    })
    ```
    🧠 **Lección:** una línea debe asignar con `=`, hacer `return` o llamar a algo que muta el DOM. Si no hace ninguna de las tres, no hace nada.

#### E5 — `activarPopoverConCierreFuera(boton, popover)` — ✅ Completado (3 fallos)

!!! success "✅ Versión corregida"
    ```js
    function activarPopoverConCierreFuera(boton, popover) {
      boton.addEventListener("click", () => {
        popover.classList.toggle("hidden")
        boton.setAttribute("aria-expanded", !popover.classList.contains("hidden"))
      })

      document.addEventListener("click", (e) => {
        if (!boton.contains(e.target) && !popover.contains(e.target)) {
          popover.classList.add("hidden")
          boton.setAttribute("aria-expanded", "false")
        }
      })
    }
    ```

!!! failure "❌ Fallo 1 — `aria-expanded` invertido y con un solo caso"
    ```js
    popover.classList.toggle("hidden")
    if(popover.classList.contains("hidden"))          // ❌ entra cuando está OCULTO...
      boton.setAttribute("aria-expanded","true")      // ❌ ...y pone "true"; y sin else, el otro caso no se actualiza
    ```
    Tras el primer clic el atributo se quedaba en `"false"` con el popover visible.

    🧠 **Lección:** `aria-expanded` no es «algo que se pone en un caso»: es una **copia del estado real** (¿está visible?). Una traza con los dos clics lo habría detectado.

!!! failure "❌ Fallo 2 — `classList.contains` con un nodo"
    Reincidencia del nº 10 de Repaso urgente (fallo 55).
    ```js
    boton.classList.contains(e.target)   // ❌ classList.contains recibe un nombre de clase (string), no un nodo: siempre false, sin error
    ```
    🧠 **Lección:** dos `contains` distintos. `elemento.contains(nodo)` pregunta «¿este nodo está dentro?»; `classList.contains(clase)` pregunta «¿tengo esta clase?».

!!! failure "❌ Fallo 3 — `if` sobrante delante de un valor derivado"
    ```js
    if(popover.classList.contains("hidden"))                                       // ❌ este if sobra
      boton.setAttribute("aria-expanded", !popover.classList.contains("hidden"))   // ya calcula el valor por sí sola
    ```
    Solo se actualizaba cuando el popover estaba oculto; al abrirlo, el atributo se quedaba en `"false"`.

    🧠 **Lección:** cuando el valor ya sale de una expresión booleana, no lleva un `if` alrededor: se asigna siempre.

| Antes de cambiar un total, «¿esto ya estaba hecho?» (idempotencia) | E10 |

También quedó claro, sin ser fallo de código, que «¿quién llama a mi función y cuándo?» decide si la función valida al llamarla (E2) o se engancha a eventos (E4). Y una forma más corta de resolver el acordeón: **resetear todo y abrir solo lo que toca**, guardando antes el estado de la pulsada.
