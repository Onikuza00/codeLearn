#### E1 — `filtrarPorNombreOCategoria(inputBusqueda, contenedorItems)` — ✅ Completado (4 fallos)

!!! success "✅ Versión corregida"
    ```js
    function filtrarPorNombreOCategoria(inputBusqueda, contenedorItems) {
      inputBusqueda.addEventListener("input", () => {
        const valor = inputBusqueda.value.toLowerCase()
        contenedorItems.querySelectorAll(".item-producto").forEach(x => {
          const esVisible = x.dataset.nombre.toLowerCase().includes(valor) || x.dataset.categoria.toLowerCase().includes(valor)
          x.classList.toggle("hidden", !esVisible)
        })
      })
    }
    ```

!!! failure "❌ Fallo 1 — `===` en vez de `includes`"
    El enunciado pide que el nombre o la categoría **contengan** el texto, no que sean iguales.
    ```js
    const esVisible = x.dataset.nombre === inputBusqueda.value.toLowerCase() || x.dataset.categoria === inputBusqueda.value.toLowerCase(); // ❌ igualdad exacta: "cami" nunca es igual a "Camiseta roja"
    ```
    🧠 **Lección:** "contiene" es `includes`, "es igual" es `===`. Con `===` el texto escrito tendría que ser el nombre entero.

!!! failure "❌ Fallo 2 — proponer `contains` para comparar strings"
    Propuso `contains` como método del string (no llegó a escribirlo en el archivo). No existe en strings.
    ```js
    "Camiseta roja".contains("cami")   // ❌ TypeError: contains no existe en strings
    "Camiseta roja".includes("cami")   // ✅ el método de string es includes
    ```
    🧠 **Lección:** `contains` es de `Element` (`menu.contains(nodo)`) y de `classList`; en strings es `includes`. Reincidencia de los tres `contains()` (nº 10 de Repaso urgente).

!!! failure "❌ Fallo 3 — `toLowerCase()` solo en un lado de la comparación"
    ```js
    const valor = inputBusqueda.value.toLowerCase();
    const esVisible = x.dataset.nombre.includes(valor) || x.dataset.categoria.includes(valor); // ❌ "Camiseta roja" conserva la C mayúscula
    ```
    🧠 **Lección:** para no distinguir mayúsculas hay que normalizar **los dos lados**: el texto escrito y el dato donde se busca.

!!! failure "❌ Fallo 4 — `valor` leído fuera del listener"
    ```js
    function filtrarPorNombreOCategoria(inputBusqueda, contenedorItems) {
      const valor = inputBusqueda.value.toLowerCase();   // ❌ se lee UNA vez, con el buscador vacío
      inputBusqueda.addEventListener("input", () =>
        contenedorItems.querySelectorAll(".item-producto").forEach(x => { /* usa valor */ })
      )
    }
    ```
    🧠 **Lección:** lo que cambia en cada evento se lee dentro del listener (fallo 56, nº 7). Aquí `valor` quedaba siempre en `""` y `includes("")` es `true`, así que el filtro no ocultaba nada.

#### E2 — `activarStepperConLimite(botonMas, botonMenos, spanCantidad, limite)` — ✅ Completado (2 fallos)

!!! success "✅ Versión corregida"
    ```js
    function activarStepperConLimite(botonMas, botonMenos, spanCantidad, limite) {
      botonMas.addEventListener("click", () => {
        let valor = Number(spanCantidad.textContent)
        if(valor < limite) {
          valor++
          spanCantidad.textContent = valor
        }
      })

      botonMenos.addEventListener("click", () => {
        let valor = Number(spanCantidad.textContent)
        if(valor > 0) {
          valor--
          spanCantidad.textContent = valor
        }
      })
    }
    ```

!!! failure "❌ Fallo 1 — `Number()` sobre el elemento en vez de su valor"
    ```js
    let valor = Number(spanCantidad)   // ❌ spanCantidad es el <span>, no el número que muestra
    if(valor < limite) {               // NaN < limite → false: el botón nunca hace nada
    ```
    🧠 **Lección:** un elemento no es el valor que contiene (fallo 46, nº 11). Para el valor hay que pasar por `.textContent`, `.value` o `.dataset.X`.

!!! failure "❌ Fallo 2 — `const` con `valor++`"
    ```js
    const valor = Number(spanCantidad.textContent)
    if(valor < limite) {valor++   // ❌ TypeError: Assignment to constant variable
    ```
    🧠 **Lección:** `const` por defecto, `let` cuando reasignas. `++` y `--` reasignan.

#### E3 — `validarPrecioEnRango(inputPrecio, spanError)` — ✅ Completado (4 fallos)

!!! success "✅ Versión corregida"
    ```js
    function validarPrecioEnRango(inputPrecio, spanError) {
      function validar(){
        const precio = Number(inputPrecio.value)
        const mensaje = "Hay un error"

        if(precio >= 10 && precio <= 500){
          inputPrecio.setCustomValidity("")
          spanError.textContent = ""
        }else{
          inputPrecio.setCustomValidity(mensaje)
          spanError.textContent = mensaje
        }
      }
      inputPrecio.addEventListener("input", validar)
      validar()
    }
    ```

!!! failure "❌ Fallo 1 — variable que copia el texto del `<span>` en vez de escribir en él"
    ```js
    let error = spanError.textContent   // ❌ copia el texto en una variable suelta
    error = "Hay un error"              // ❌ cambia la variable; el <span> no se entera
    if(precio >= 10 && precio <= 500){
      inputPrecio.setCustomValidity("");
      error = ""                        // ❌ tampoco toca el <span>
    }
    ```
    🧠 **Lección:** un string se copia por valor. Para que el usuario lea algo hay que escribir en el elemento: `spanError.textContent = ...`.

!!! failure "❌ Fallo 2 — validar solo dentro del listener"
    ```js
    inputPrecio.addEventListener("input", () => {   // ❌ al llamar a la función solo se registra el listener
      let precio = Number(inputPrecio.value)
      // ...
    })
    ```
    🧠 **Lección:** si el test fija el valor y llama a la función sin disparar eventos, la lógica tiene que ejecutarse también **al llamar**. Patrón: extraer una función con nombre, ejecutarla una vez y pasarla como manejador (sin paréntesis).

!!! failure "❌ Fallo 3 — parámetros en `validar` que tapan los de la función exterior"
    ```js
    function validar(inputPrecio, spanError){ ... }   // ❌ shadowing
    inputPrecio.addEventListener("input", validar)    // el navegador llama validar(evento): inputPrecio = evento, spanError = undefined
    ```
    🧠 **Lección:** un listener recibe el **evento** como primer argumento. Una función interna sin parámetros ve las variables de la exterior por closure.

!!! failure "❌ Fallo 4 — dos textos distintos para el mismo error"
    ```js
    inputPrecio.setCustomValidity("error")       // ❌
    spanError.textContent = "Hay un error"       // ❌ no coincide con el texto del campo
    ```
    🧠 **Lección:** el mensaje se escribe antes de leerse, una sola vez, en una `const mensaje` que usan los dos sitios.

#### E4 — `validarTelefonoExacto(inputTelefono, spanError)` — ✅ Completado (3 fallos)

!!! success "✅ Versión corregida"
    ```js
    function validarTelefonoExacto(inputTelefono, spanError) {
      function validacion(){
        const numeros = "0123456789"
        const digito = inputTelefono.value.split("").every(x => numeros.includes(x))
        const longi = inputTelefono.value.length === 9
        const valido = digito && longi
        const mensaje = "Hay un error"

        if(valido){
          inputTelefono.setCustomValidity("")
          spanError.textContent = ""
        }else{
          inputTelefono.setCustomValidity(mensaje)
          spanError.textContent = mensaje
        }
      }

      inputTelefono.addEventListener("input", validacion)
      validacion()
    }
    ```

!!! failure "❌ Fallo 1 — `every` sin callback"
    ```js
    inputTelefono.value.split("").every.includes("1089")   // ❌ every es una función: hay que llamarla con un callback
    ```
    🧠 **Lección:** `every(c => ...)` recibe una función que responde a un carácter con `true` o `false`. Además `"1089"` deja fuera la mayoría de los dígitos: a la izquierda va la cadena con todos.

!!! failure "❌ Fallo 2 — `includes` con los papeles invertidos"
    ```js
    const digito = inputTelefono.value.split("").every(x => x.includes("0123456789"))   // ❌ ¿un carácter contiene entera esa cadena? Nunca
    ```
    🧠 **Lección:** `a.includes(b)` pregunta si `a` contiene entero a `b`: el texto grande a la izquierda (`numeros`) y el carácter suelto a la derecha (`x`). Reincidencia del fallo 2 del 21/09.

!!! failure "❌ Fallo 3 — llaves pegadas tras `addEventListener(...)`"
    ```js
    inputTelefono.addEventListener("input", validacion){   // ❌ SyntaxError: después de ")" no puede ir "{"
      validacion()
    }
    ```
    🧠 **Lección:** `addEventListener(...)` es una llamada normal que termina en `)`. Son dos sentencias separadas: registrar el listener y ejecutar `validacion()` una vez. Un error de sintaxis rompe **todo** el archivo, no solo el ejercicio.

#### E5 — `activarFiltroCategorias(contenedorBotones, contenedorProductos)` — ✅ Completado (3 fallos)

!!! success "✅ Versión corregida"
    ```js
    function activarFiltroCategorias(contenedorBotones, contenedorProductos) {
      contenedorBotones.addEventListener("click", function(e) {
        const btn = e.target.closest("button")
        if(!btn) return
        const categoria = btn.dataset.categoria
        const todos = categoria === "todos"

        contenedorProductos.querySelectorAll(".producto-card").forEach(x => {
          const coincide = x.dataset.categoria === categoria
          x.classList.toggle("hidden", !(coincide || todos))
        })
        contenedorBotones.querySelectorAll(".filtro-btn").forEach(x => {
          x.classList.toggle("filtro-btn--activo", x === btn)
        })
      })
    }
    ```

!!! failure "❌ Fallo 1 — el parámetro del listener tratado como un elemento"
    ```js
    contenedorBotones.addEventListener("click", (x) => {
      // ...
      const valido = j.dataset.categoria === x.dataset.categoria   // ❌ x es el EVENTO: x.dataset es undefined
    ```
    🧠 **Lección:** el listener recibe el evento (`e`). El botón se saca con `e.target.closest(...)` y un guard clause (`if(!btn) return`) **antes** de usarlo.

!!! failure "❌ Fallo 2 — `&&` donde bastaba con uno de los dos casos"
    ```js
    const cat = x.dataset.categoria === categoria
    const valido = cat && todos       // ❌ exige que coincida la categoría Y que el botón sea "todos"
    x.classList.toggle("hidden", !valido)
    ```
    🧠 **Lección:** "basta con uno" es `||`, "hacen falta los dos a la vez" es `&&` (nº 2). Con `&&` los productos quedaban todos ocultos siempre.

!!! failure "❌ Fallo 3 — no rotar el botón activo"
    ```js
    contenedorProductos.querySelectorAll(".producto-card").forEach(x => { /* solo tocaba hidden */ })
    // ❌ ninguna línea marcaba el botón pulsado ni quitaba la clase al anterior
    ```
    🧠 **Lección:** el enunciado decía que cualquier otro botón activo deja de estarlo. Se lee entero y se apuntan las tres cosas que deben ocurrir. Patrón de exclusividad: `toggle("filtro-btn--activo", x === btn)` sobre **todos** los botones.

#### E6 — `moverAbajo(lista)` — ✅ Completado (3 fallos)

!!! success "✅ Versión corregida"
    ```js
    function moverAbajo(lista) {
      lista.addEventListener("click", (e) => {
        const esBotonBajar = e.target.matches(".btn-bajar")
        if(!esBotonBajar) return
        const item = e.target.closest(".item-lista")
        const hermano = item.nextElementSibling
        if(!hermano) return
        lista.insertBefore(hermano, item)
      })
    }
    ```

!!! failure "❌ Fallo 1 — `e.target === x` nunca es cierto"
    ```js
    lista.querySelectorAll(".item-lista").forEach(x => {
      const hermano = x.nextElementSibling
      if(!hermano) return
      if(e.target === x) lista.insertBefore(x, hermano)   // ❌ el click cae en el <button> del <li>, no en el <li>
    })
    ```
    🧠 **Lección:** el click cae en el hijo más profundo. Para llegar al elemento contenedor se sube con `closest()`.

!!! failure "❌ Fallo 2 — `insertBefore(x, hermano)` es un no-op"
    ```js
    lista.insertBefore(x, hermano)   // ❌ x ya está justo antes de hermano
    ```
    🧠 **Lección:** `insertBefore(nodoAMover, referencia)` deja el nodo justo antes de la referencia. Para bajar un elemento, quien se mueve es su hermano de abajo: `insertBefore(hermano, item)`. Reincidencia del fallo 65 (23/08 y hoy).

!!! failure "❌ Fallo 3 — `forEach` sobre todos los items en vez de navegar"
    ```js
    lista.querySelectorAll(".item-lista").forEach(x => {
      const hermano = x.nextElementSibling
      if(!hermano) return
      const item = e.target.closest(".item-lista")
      if(item) lista.insertBefore(hermano, x)   // ❌ item siempre existe: se intercambia cada x, no el pulsado
    })
    ```
    Pulsando el botón de A con `A, B, C, D` la lista acababa en `A, B, D, C` en vez de `B, A, C, D`.

    🧠 **Lección:** búsqueda frente a navegación. Con el item pulsado (`closest`) y su hermano (`nextElementSibling`) no hace falta recorrer nada, y el `x` del `forEach` ya no pinta nada.

| Patrón | Dónde |
|---|---|
