#### E2 — `mostrarUsuario(id)` — ✅ Completado (3 fallos)

!!! success "✅ Versión corregida"
    ```js
    function mostrarUsuario(id) {
      return pedirUsuario(id)
        .then(usuario => 'Bienvenido, ' + usuario.nombre)
        .catch(error => { throw new Error('No se pudo cargar el usuario') })
    }
    ```

!!! failure "❌ Fallo 1 — tratar el objeto resuelto como si fuera solo el nombre"
    ```js
    .then(nombre => 'Bienvenido, ' + nombre)   // ❌ "nombre" es en realidad { id, nombre: 'Usuario X' }
    ```
    Resultado: `"Bienvenido, [object Object]"` en vez del texto esperado.

    🧠 **Lección:** `.then()` recibe el valor completo con el que resolvió la promesa — el nombre del parámetro no cambia qué es. Hace falta `usuario.nombre`.

!!! failure "❌ Fallo 2 — pasar un `Error` ya construido a `.catch()`"
    ```js
    .catch(new Error('No se pudo cargar el usuario'))   // ❌ .catch() espera una función, no un valor
    ```
    🧠 **Lección:** `.catch(callback)` necesita una función que reciba el motivo del rechazo — no un `Error` construido de antemano.

!!! failure "❌ Fallo 3 — `=` en vez de `=>`, y `throw` sin llaves"
    ```js
    .catch(error = throw new Error('No se pudo cargar por el usuario'))   // ❌ "=" no es "=>"; y throw es una instrucción, no una expresión
    ```
    🧠 **Lección:** una arrow function sin llaves solo admite una expresión de retorno directo. `throw` es una instrucción — con `throw` hacen falta llaves: `error => { throw new Error(...) }`.

#### E4 — `pedirConFallback(id)` — ✅ Completado (1 fallo)

!!! success "✅ Versión corregida"
    ```js
    function pedirConFallback(id) {
      return pedirUsuario(id)
        .catch(() => perfilInvitado())
    }
    ```

!!! failure "❌ Fallo 1 — llamada extra pasando una promesa en vez de una función"
    ```js
    .then(pedirUsuario(id))   // ❌ invoca pedirUsuario OTRA VEZ ahora mismo y le pasa la promesa resultante a .then(); al no ser una función, .then() la ignora
    ```
    Pasó los tests por casualidad (`.then()` con un argumento no-función no hace nada), pero dispara una petición duplicada innecesaria.

    🧠 **Lección:** el `.catch(() => perfilInvitado())` ya deja la cadena completa. `.then()`/`.catch()` esperan una función; pasarles el resultado de invocar una no tiene efecto sobre el valor, solo efectos secundarios no deseados.

**Patrón a vigilar (mismo día, no reincidencia todavía):** el Fallo 2 de E2 y el Fallo 1 de E4 son el mismo error de fondo — pasar un valor ya calculado (un `Error`, una promesa) donde `.then()`/`.catch()` esperan una función. Si vuelve a aparecer en un día distinto, sube a Repaso urgente.

#### E2 — `cargarDashboard()` — ✅ Completado (1 fallo)

!!! success "✅ Versión corregida"
    ```js
    function cargarDashboard() {
      const promesas = [pedirPerfil(), pedirPedidos()]
      return Promise.all(promesas)
        .then(([info, pedid]) => {
          return {
            nombre: info.nombre,
            pedidos: pedid.length,
            totalGastado: pedid.reduce((n, pedido) => n + pedido.total, 0)
          }
        })
    }
    ```

!!! failure "❌ Fallo 1 — tratar el array de `Promise.all` como si fuera un objeto"
    ```js
    .then(x => { { x.nombre, x.pedidos, x.totalGastado } })   // ❌ "x" es el array [perfil, pedidos], no un objeto: x.nombre no existe
    ```
    🧠 **Lección:** `Promise.all` se cumple con un **array**, en el mismo orden que las promesas de entrada. Hay que desestructurarlo (`([perfil, pedidos]) => ...`) antes de acceder a sus propiedades.

#### E3 — `cargarCarrito(ids)` — ✅ Completado (2 fallos)

!!! success "✅ Versión corregida"
    ```js
    function cargarCarrito(ids) {
      const promesas = ids.map(x => pedirProducto(x))
      return Promise.all(promesas)
    }
    ```

!!! failure "❌ Fallo 1 — acceder a `.id` sobre el propio id"
    ```js
    ids.map(x => pedirProducto(x.id))   // ❌ "x" ya es el id directo (un número); x.id es undefined
    ```
    🧠 **Lección:** `ids` es un array plano de números — cada elemento del `map` ES el id, no un objeto que lo contiene.

!!! failure "❌ Fallo 2 — `.then()` de más, tratando el array como un solo producto"
    ```js
    .then((x) => { return { id: x.id, nombre: x.nombre, precio: x.precio } })   // ❌ x es el array de productos completo, no uno solo
    ```
    🧠 **Lección:** `Promise.all` ya se cumple con el array final, en el formato correcto — no hace falta ninguna transformación después.

#### E4 — `cargarWidgets()` — ✅ Completado (4 fallos)

!!! success "✅ Versión corregida"
    ```js
    function cargarWidgets() {
      const nombres = ['clima', 'noticias', 'bolsa'];
      return Promise.allSettled([cargarClima(), cargarNoticias(), cargarBolsa()])
        .then(resultados => resultados.map((resultado, i) => ({
          nombre: nombres[i],
          estado: resultado.status === 'fulfilled' ? 'ok' : 'error',
          datos: resultado.status === 'fulfilled' ? resultado.value : null
        })));
    }
    ```

!!! failure "❌ Fallo 1 — `allSettled` con argumentos sueltos en vez de un array"
    ```js
    Promise.allSettled(cargarClima(), cargarNoticias(), cargarBolsa())   // ❌ un solo argumento, un array; no tres sueltos
    ```
    🧠 **Lección:** `Promise.allSettled` (igual que `all`, `race` y `any`) recibe UN array con las promesas dentro, no promesas como argumentos separados.

!!! failure "❌ Fallo 2 — desestructurar cada resultado como si fueran 3 valores"
    ```js
    x.map(([nom, est, dat]) => { ... })   // ❌ cada elemento es UN objeto { status, value } o { status, reason }, no un trío de valores
    ```
    🧠 **Lección:** `allSettled` se cumple con un array de N objetos (uno por promesa), cada uno con `status` y `value`/`reason` — el `.map()` procesa un resultado por vuelta, no los tres a la vez.

!!! failure "❌ Fallo 3 — falta el nombre del widget"
    Sin usar el índice del `.map()`, no había forma de saber si un resultado era de clima, noticias o bolsa.

    🧠 **Lección:** `allSettled` no devuelve ningún nombre — el orden del array de salida es el mismo que el de entrada, así que el índice sirve para emparejar cada resultado con un array de nombres propio.

!!! failure "❌ Fallo 4 — falta el `return` de la función"
    ```js
    const promesas = Promise.allSettled(...).then(...)   // ❌ guardado en una variable, nunca devuelto
    ```
    🧠 **Lección:** sin `return`, la función no devuelve ninguna promesa — quien la llame recibe `undefined`.

#### E5 — `cargarConLimite(promesa, ms)` — ✅ Completado (2 fallos)

!!! success "✅ Versión corregida"
    ```js
    function cargarConLimite(promesa, ms) {
      const tempo = new Promise((resolve, reject) => {
        setTimeout(() => {
          reject(new Error("Tiempo agotado"))
        }, ms)
      })
      return Promise.race([promesa, tempo])
        .then((info) => {
          return { cargando: false, error: null, datos: info }
        })
        .catch((error) => {
          return { cargando: false, error: error.message, datos: null }
        })
    }
    ```

!!! failure "❌ Fallo 1 — `Promise.race` dentro del propio constructor de `tempo`"
    ```js
    const tempo = new Promise((resolve, reject) => {
        setTimeout(() => { reject(new Error("Tiempo agotado")) }, ms)
        return Promise.race([promesa, tempo])   // ❌ usa "tempo" antes de que exista, y lo que se devuelve aquí dentro se ignora siempre
    })
    ```
    🧠 **Lección:** lo que devuelve el ejecutor de `new Promise` no sirve para nada — nunca se usa. Y una constante no se puede referenciar dentro de su propia inicialización.

!!! failure "❌ Fallo 2 — guardar el `Error` entero en vez de su mensaje"
    ```js
    .catch((error) => { return { cargando: false, error: error, datos: null } })   // ❌ guarda el objeto Error completo, no el texto
    ```
    🧠 **Lección:** el enunciado pide el mensaje (un string) en `error`, no el objeto `Error` — hace falta `error.message`.
