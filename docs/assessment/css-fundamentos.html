🎨 Examen Práctico CSS — Nexus Agency

Cliente: Nexus — agencia creativa digital especializada en branding y desarrollo web.

Tiempo estimado: 60–75 min.

Regla de oro: Mobile First. Base sin media query = mobile. Una sola media query por sección. BEM estricto en todo. Sin valores mágicos — todo desde :root.

Archivos: nexus.html + nexus.css. Todo desde cero.

Sección 1 — Header Flex BEM :focus-visible

.header — fondo oscuro, texto claro. Flex row. Logo a izquierda, nav centrado, botón CTA "Hablemos" a derecha.
  • Mobile: nav links apilados (column), botón CTA abajo del todo.
  • Desktop (768px+): todo en una fila. El nav ocupa el centro con flex: 1 + justify-content: center.
  • a11y :focus-visible en cada link del nav y en el CTA.
  • Motion Transición suave en hover de links y botón. Respetar prefers-reduced-motion.
  • BEM: .header__logo, .header__nav, .header__link, .header__cta.
  • Usá variables para colores, espaciado y tipografía.

Sección 2 — Hero Flex clamp() Variables Motion

.hero — gran titular, subtítulo, botón CTA. Todo centrado en una columna.
  • Título con clamp(2rem, 5vw, 4.5rem).
  • Subtítulo con clamp(1rem, 2vw, 1.25rem).
  • Fondo: color primario + degradado suave usando variables CSS.
  • Padding vertical generoso con variable de espaciado.
  • Botón CTA con hover sutil (cambiar fondo o escalar). prefers-reduced-motion respetado.
  • BEM: .hero__title, .hero__subtitle, .hero__cta.

Sección 3 — Servicios Grid auto-fit BEM Variables

.grid-cards — 6 servicios en grid responsive SIN media queries. Icono + título + descripción breve.
  • Usá exactamente este patrón que Pau tiene que memorizar:
.grid-cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(280px, 1fr));
  gap: 1.5rem;
}
  • Mobile: 1 columna. Tablet: 2. Desktop: 3. Todo sin media queries gracias al patrón de arriba.
  • BEM: .service__card, .service__icon, .service__title, .service__desc.
  • Usá emojis para iconos (🎨 📱 🌐 📸 ✏️ 🚀).
  • Cards con gap, padding, border-radius desde variables.
  • Transición en hover: subir 2-3px. Respetar prefers-reduced-motion.

Sección 4 — Layout de página Grid areas BEM

.layout — layout completo de página con grid-template-areas. Header, main, aside y footer. Los hijos deben ser DIRECTOS del contenedor grid.
  • Usá exactamente este patrón que Pau tiene que memorizar:
.layout {
  display: grid;
  grid-template-areas:
    "header header header"
    "main   main   aside"
    "footer footer footer";
  gap: 1rem;
}
header { grid-area: header; } /* HIJOS DIRECTOS del contenedor */
main   { grid-area: main; }
aside  { grid-area: aside; }
footer { grid-area: footer; }
  • Mobile: todo apilado en 1 columna (header, main, aside, footer). Re-definí las áreas con media query.
  • Desktop (768px+): el patrón de 3 columnas de arriba: header full, main + aside, footer full.
  • Dentro de <main> meté una galería de 4 proyectos destacados con repeat(2, 1fr).
  • Dentro de <aside> meté una lista de categorías o un widget de contacto.
  • BEM en los elementos internos: .project__card, .project__img, etc.
  • :focus-visible en los enlaces del aside.

Sección 5 — Pricing Grid :has() CQ BEM

.pricing — 3 planes: Básico, Profesional, Enterprise. Cada card: nombre, precio, features, botón CTA.
  • Desktop: 3 columnas iguales con grid-template-columns: repeat(3, 1fr).
  • Mobile: 1 columna apilada.
  • :has() La card que contiene el badge "Más popular" debe ser visualmente distinta: borde celeste, fondo ligeramente distinto, o escalada 1.05.
  • CQ Container Query:
    • Cada .pricing__card es un container de inline-size.
    • Si el contenedor mide >= 400px: card en disposición vertical normal.
    • Si mide < 400px: apilar features y que el CTA quede al final (esto se ve sobre todo en mobile).
  • BEM: .pricing__card, .pricing__name, .pricing__price, .pricing__feature, .pricing__cta, .pricing__badge.
  • :focus-visible en los CTA.

Sección 6 — Footer Grid BEM

.footer — 3 columnas: col1 = logo + desc, col2 = enlaces rápidos, col3 = contacto + redes.
  • Mobile: 1 columna apilada.
  • Desktop: 3 columnas iguales.
  • Fondo oscuro (como el header), texto claro.
  • BEM: .footer__col, .footer__title, .footer__link, .footer__text.
  • Enlaces hover con transición.

Sección 7 — Contacto Flex BEM Form

.contacto — formulario de contacto funcional con nombre, email, asunto, mensaje y botón de envío.
  • Estructura: dos columnas en desktop (info a izquierda, formulario a derecha), una columna apilada en mobile.
  • Columna de info: título, texto breve, email y teléfono de contacto, iconos decorativos.
  • Columna del formulario: <form> con action="#" y method="POST".
  • Campos: nombre (text), email (email), asunto (select con opciones: Consulta, Proyecto, Colaboración, Otro), mensaje (textarea), y botón submit "Enviar mensaje".
  • Cada campo envuelto en .contacto__field con su <label> asociado.
  • BEM: .contacto__form, .contacto__field, .contacto__label, .contacto__input, .contacto__select, .contacto__textarea, .contacto__btn, .contacto__info, .contacto__text, .contacto__item.
  • Estilado completo: inputs con border, padding, border-radius desde variables, foco con :focus + outline personalizado.
  • a11y Cada <input> y <textarea> con su <label> vinculado via for/id. Placeholders visibles pero no reemplazan labels.
  • Transición en hover/focus de los inputs. prefers-reduced-motion respetado.
  • El nav del header ya tiene un link #contacto — asegurate de que el id="contacto" esté en el contenedor de la sección.

Sección 8 — Stats Grid BEM clamp()

.stats — 4 cifras destacadas en grid responsive: clientes felices, proyectos entregados, años de experiencia, premios ganados.
  • Estructura: 4 items en grid con repeat(auto-fit, minmax(200px, 1fr)).
  • Cada item: icono decorativo + número grande + etiqueta descriptiva.
  • Números con clamp(2.5rem, 5vw, 4rem) para que escalen.
  • Etiqueta en tamaño más chico, color secundario o gris claro.
  • Fondo de la sección: ligeramente distinto al fondo general (ej. var(--color-bg-alt)) para separación visual.
  • BEM: .stats__item, .stats__icon, .stats__number, .stats__label.
  • Transición sutil en hover del item completo (escala o sombra). prefers-reduced-motion respetado.

Sección 9 — Testimonios Grid CQ BEM

.testimonials — 3 testimonios de clientes en grid. Cada card: avatar, nombre, cargo, cita y valoración con estrellas.
  • Desktop: 3 columnas con repeat(3, 1fr). Mobile: 1 columna apilada.
  • Avatar circular con object-fit: cover y border-radius: 50%. Usá fotos de pravatar o similar.
  • Cita con comillas decorativas vía CSS (::before / ::after o un span con el carácter “).
  • Valoración: 5 estrellas con emoji ⭐ o caracteres ★/☆ estilados con color variable.
  • CQ Container Query en cada .testimonials__card:
    • Container de inline-size.
    • Si el contenedor mide < 300px: cita más compacta, avatar más chico, estrellas debajo del nombre.
    • Si mide >= 300px: layout normal con avatar a la izquierda y contenido a la derecha.
  • BEM: .testimonials__card, .testimonials__avatar, .testimonials__name, .testimonials__role, .testimonials__quote, .testimonials__stars.
  • Transición suave en hover de la card. prefers-reduced-motion.

Requisitos Globales

Variables Definí en :root: --color-primary, --color-secondary, --color-accent, --color-text, --color-bg, --color-dark, --space-xs a --space-xl (escala 4-8-12-16-24-32-48px en rem), --radius-sm, --radius-md, --font-body, --font-heading. Usalas en absolutamente todo. Nada de valores mágicos.
Motion Todas las transiciones/animaciones deben respetar prefers-reduced-motion: no-preference. Si el usuario prefiere motion reducido, cero animaciones.
BEM Estricto en todo el proyecto. Sin clases sueltas, sin IDs como selectores CSS, sin anidación rara. Bloques: .header, .hero, .services, .portfolio, .stats, .testimonials, .pricing, .contacto, .footer. Elementos con doble underscore: .header__logo, .service__card, etc.
