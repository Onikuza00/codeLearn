1 🟢 textoBadge(tarjeta, alternativo) ⏳ Pendiente

Cada tarjeta de producto puede llevar o no una etiqueta destacada (por ejemplo "Nuevo" u "Oferta"). Recibe la tarjeta y un texto alternativo. Si la tarjeta tiene esa etiqueta, devolvé su texto; si no la tiene, devolvé el texto alternativo — sin que el programa se rompa por buscar algo que no está.

Cuando algo puede no existir en la página, buscarlo y asumir directamente que está ahí es una de las causas más comunes de que un script se detenga en seco a mitad de ejecución. Conviene pensar primero en el caso "no está" y después en el caso feliz.

textoBadge(tarjetaConEtiqueta, "Sin etiqueta") → "Nuevo"
textoBadge(tarjetaSinEtiqueta, "Sin etiqueta") → "Sin etiqueta" 
<div class="tarjeta">
  <span class="badge">Nuevo</span>
</div>
function textoBadge(tarjeta, alternativo) {
  const etiqueta = tarjeta.querySelector('.badge');
  return etiqueta ? etiqueta.textContent : alternativo;
}

2 🟢 productosVisibles(lista) ⏳ Pendiente

Un listado de productos filtrado por el usuario marca con una clase los que no cumplen el filtro, ocultándolos visualmente. Recibe el contenedor del listado y devolvé un array con el texto de los productos que siguen visibles — los ocultos no cuentan.

Que un elemento siga existiendo en el HTML no significa que el usuario lo esté viendo — "existe" y "está visible" son preguntas distintas, y confundirlas es un bug clásico en listados con filtros.

productosVisibles(listaConDosOcultos) → ["Mouse", "Monitor"]
productosVisibles(listaSinOcultos) → ["Mouse", "Teclado", "Monitor"] 
<ul class="lista">
  <li class="producto">Mouse</li>
  <li class="producto oculto">Teclado</li>
  <li class="producto">Monitor</li>
</ul>
function productosVisibles(lista) {
  const productos = lista.querySelectorAll('.producto:not(.oculto)');
  return Array.from(productos).map(p => p.textContent);
}

3 🟡 siguienteItem(menu) ⏳ Pendiente

En un menú de navegación, un ítem lleva marcada la sección activa. Recibe el menú y devolvé el texto del ítem que va justo después del activo — útil para una navegación tipo "siguiente" por teclado. Si el activo es el último, o si ningún ítem está marcado como activo, devolvé null.

Cuando la posición de un elemento respecto a sus hermanos importa, hay que poder moverse por la estructura del documento a partir de ese elemento, no solo encontrarlo.

siguienteItem(menuConProductosActivo) → "Contacto"
siguienteItem(menuConContactoActivo) → null // Contacto es el último 
<ul class="menu">
  <li>Inicio</li>
  <li class="activo">Productos</li>
  <li>Contacto</li>
</ul>
function siguienteItem(menu) {
  const activo = menu.querySelector('.activo');
  if (!activo) return null;
  const siguiente = activo.nextElementSibling;
  return siguiente ? siguiente.textContent : null;
}

1 🟡 mostrarNombreUsuario(parrafo, nombre) ⏳ Pendiente

Un formulario de registro permite elegir un nombre de usuario, y ese nombre se muestra luego en un párrafo de bienvenida. El problema: cualquier usuario podría escribir código HTML o de script como si fuera su nombre. Recibe el párrafo y el nombre ingresado, y mostralo siempre como texto plano — nunca como HTML que el navegador interprete o ejecute.

Insertar texto que viene de un usuario directamente en la página, dejando que el navegador lo interprete como marcado, es la puerta de entrada a inyecciones de código. Todo dato externo se trata como texto, nunca como HTML de confianza.

mostrarNombreUsuario(parrafo, "Ana") → el párrafo muestra "Ana"
mostrarNombreUsuario(parrafo, "<b>Ana</b>") → el párrafo muestra literalmente "<b>Ana</b>", no negrita 
<p class="usuario"></p>
function mostrarNombreUsuario(parrafo, nombre) {
  parrafo.textContent = nombre;
}

2 🟢 datosProductoCard(tarjeta) ⏳ Pendiente

Cada tarjeta de producto guarda su precio, categoría y stock como atributos personalizados en el propio elemento HTML (pensados para leerse desde JS, no para mostrarse directo). Recibe la tarjeta y devolvé un objeto plano { precio, categoria, stock } listo para usarse en un carrito — con precio y stock ya convertidos a número, no como texto.

Los atributos leídos desde el HTML siempre llegan como texto, aunque parezcan números. Si no los convertís, sumar dos "números" así puede pegarlos como texto en vez de sumarlos — un bug silencioso porque JS no avisa del error de tipo.

datosProductoCard(tarjeta) → { precio: 19.99, categoria: "electronica", stock: 5 } 
<div class="producto-card"
     data-precio="19.99"
     data-categoria="electronica"
     data-stock="5">
</div>
function datosProductoCard(tarjeta) {
  return {
    precio: Number(tarjeta.dataset.precio),
    categoria: tarjeta.dataset.categoria,
    stock: Number(tarjeta.dataset.stock)
  };
}

3 🟡 alternarFavorito(boton) ⏳ Pendiente

Un botón tipo "me gusta" cambia de estado cada vez que se pulsa: si estaba apagado pasa a estar activo, y viceversa. Recibe el botón y devolvé true si quedó activo después de esta llamada, o false si quedó inactivo. Debe funcionar bien llamándolo varias veces seguidas sobre el mismo botón.

Un estado que se invierte cada vez que se llama a la función necesita que esa función sepa en qué estado está el elemento AHORA, no solo que lo fije siempre en un valor.

alternarFavorito(boton) → true  // primera vez, se activa
alternarFavorito(boton) → false  // segunda vez, se desactiva
alternarFavorito(boton) → true  // tercera vez, se activa de nuevo 
<button class="like"></button>
function alternarFavorito(boton) {
  boton.classList.toggle('activo');
  return boton.classList.contains('activo');
}

4 🟢 agregarTarea(lista, texto) ⏳ Pendiente

En una lista de tareas pendientes, cada tarea nueva se añade al final de la lista. Recibe el contenedor de la lista y el texto de la tarea, agregala como un nuevo ítem, y devolvé cuántas tareas hay en total después de añadirla. Tiene que funcionar bien aunque se llame varias veces seguidas para ir agregando tareas una tras otra.

Agregar contenido nuevo a una lista que ya existe en la página, sin reconstruir toda la lista desde cero, es una operación constante en interfaces dinámicas: tareas pendientes, comentarios, resultados de búsqueda...

agregarTarea(lista, "Comprar pan") → 1
agregarTarea(lista, "Estudiar JS") → 2 
<ul class="tareas"></ul>
function agregarTarea(lista, texto) {
  const li = document.createElement('li');
  li.textContent = texto;
  lista.appendChild(li);
  return lista.children.length;
}

5 🟡 eliminarTarea(lista, texto) ⏳ Pendiente

Cuando una tarea se completa, desaparece de la lista de pendientes. Recibe el contenedor de la lista y el texto de la tarea a quitar, eliminala de la lista, y devolvé cuántas tareas quedan. Si el texto no corresponde a ninguna tarea existente, no cambies nada y devolvé la cantidad de tareas que ya había.

Quitar un elemento del documento solo tiene sentido sobre un elemento que efectivamente ya está ahí — primero hay que localizarlo, y contemplar qué pasa cuando la búsqueda no encuentra nada.

eliminarTarea(lista, "Estudiar JS") → 2  // quedan 2 de 3
eliminarTarea(lista, "Bailar") → 3  // no existía, no cambia nada 
<ul class="tareas">
  <li>Comprar pan</li>
  <li>Estudiar JS</li>
  <li>Pagar factura</li>
</ul>
function eliminarTarea(lista, texto) {
  const items = Array.from(lista.querySelectorAll('li'));
  const item = items.find(li => li.textContent === texto);
  if (item) item.remove();
  return lista.children.length;
}

1 🟢 evitarNavegacion(enlace) ⏳ Pendiente

Un enlace se usa como disparador de una acción en JS (por ejemplo, abrir un panel), no para navegar a otra página. Recibe el enlace y hacé que, al hacer click, el navegador NO siga el href ni recargue la página.

Por defecto, cualquier click sobre un enlace dispara la navegación del navegador, pase lo que pase en tu código JS. Cuando el enlace es solo un gancho para lógica propia, hay que decirle explícitamente al navegador que no siga su comportamiento normal.

evitarNavegacion(enlace)
// tras un click sobre el enlace, el navegador no navega a ningún lado 
<a href="#" class="enlace">Ver más</a>
function evitarNavegacion(enlace) {
  enlace.addEventListener('click', (evento) => {
    evento.preventDefault();
  });
}

2 🔴 activarDelegacionTareas(lista) ⏳ Pendiente

En una lista de tareas, al hacer click sobre cualquier tarea esa tarea concreta debe marcarse como completada visualmente, y un segundo click la desmarca. La lista puede ir creciendo con tareas nuevas después de haber activado este comportamiento, y esas tareas nuevas también deben poder marcarse igual, sin volver a configurar nada. Un click sobre una tarea nunca debe afectar a las demás.

Enganchar el comportamiento a cada ítem por separado deja de funcionar en cuanto aparece un ítem que no existía cuando se configuró todo. Hay una forma de reaccionar a los clicks de todos los ítems de un contenedor, presentes y futuros, sin repetir la configuración por cada uno.

activarDelegacionTareas(lista)
// click en el primer ítem → solo ese ítem cambia
// se agrega un ítem nuevo a la lista
// click en el ítem nuevo → también cambia, sin volver a llamar activarDelegacionTareas 
<ul class="tareas">
  <li>Tarea 1</li>
  <li>Tarea 2</li>
</ul>
function activarDelegacionTareas(lista) {
  lista.addEventListener('click', (evento) => {
    const item = evento.target.closest('li');
    if (item && lista.contains(item)) {
      item.classList.toggle('done');
    }
  });
}

3 🟡 activarEnvioConEnter(input, alEnviar) ⏳ Pendiente

En un chat, el mensaje se envía pulsando la tecla Enter dentro del campo de texto, sin necesidad de ningún botón. Recibe el campo de texto y una función alEnviar. Cuando el usuario pulsa Enter, llamá a alEnviar pasándole el texto actual del campo. Si pulsa cualquier otra tecla, no debe pasar nada.

No todas las teclas significan lo mismo dentro de un mismo campo — "algo pasó en el teclado" no alcanza como información; hace falta distinguir cuál tecla se pulsó antes de decidir si reaccionar o no.

activarEnvioConEnter(input, miFuncion)
// el usuario escribe "Hola" y pulsa Enter → miFuncion("Hola")
// el usuario pulsa cualquier otra tecla → miFuncion no se llama 
<input type="text" class="mensaje">
function activarEnvioConEnter(input, alEnviar) {
  input.addEventListener('keydown', (evento) => {
    if (evento.key === 'Enter') {
      alEnviar(input.value);
    }
  });
}

4 🔴 activarArrastre(tarjeta) ⏳ Pendiente

Una tarjeta de la interfaz se puede arrastrar con el ratón: el usuario la pulsa, la mueve por la pantalla sin soltar el botón, y la tarjeta lo sigue en tiempo real actualizando su posición (left/top). Al soltar el botón, la tarjeta se queda donde está y deja de seguir al cursor — mover el ratón después de soltar no debe volver a moverla. Recibe la tarjeta.

Un arrastre tiene tres momentos distintos — empieza, está en curso, termina — y cada uno necesita reaccionar a una interacción distinta del ratón. El momento más fácil de olvidar es "terminó": sin él, la tarjeta seguiría al cursor para siempre, incluso después de soltar el botón.

activarArrastre(tarjeta)
// el usuario pulsa sobre la tarjeta y mueve el ratón → la tarjeta se mueve con él
// el usuario suelta el botón y sigue moviendo el ratón → la tarjeta ya no se mueve 
<div class="tarjeta-arrastrable"
     style="position:absolute;left:0px;top:0px;">
</div>
function activarArrastre(tarjeta) {
  let arrastrando = false;

  tarjeta.addEventListener('mousedown', () => {
    arrastrando = true;
  });

  document.addEventListener('mousemove', (evento) => {
    if (!arrastrando) return;
    tarjeta.style.left = evento.clientX + 'px';
    tarjeta.style.top = evento.clientY + 'px';
  });

  document.addEventListener('mouseup', () => {
    arrastrando = false;
  });
}

5 🟡 activarContadorCaracteres(input, contador) ⏳ Pendiente

Debajo de un campo de texto hay un pequeño contador que muestra cuántos caracteres se llevan escritos, y se actualiza al instante con cada letra que se escribe o se borra — no solo cuando el usuario termina de escribir o cambia de campo. Recibe el campo de texto y el elemento contador, y mantené el contador sincronizado con la longitud del texto en todo momento.

Hay eventos de formulario que solo se disparan cuando el campo pierde el foco, y otros que se disparan con cada cambio de valor, tecla a tecla. Un contador "en vivo" necesita el segundo tipo, no el primero.

activarContadorCaracteres(input, contador)
// el usuario escribe "Hola" letra por letra → el contador va mostrando 1, 2, 3, 4 
<input type="text" class="mensaje-texto">
<span class="contador">0</span>
function activarContadorCaracteres(input, contador) {
  input.addEventListener('input', () => {
    contador.textContent = input.value.length;
  });
}

1 🟢 datosFormulario(formulario) ⏳ Pendiente

Antes de enviar un formulario de registro (con campos como nombre y email) a un servidor, hace falta juntar todos sus valores actuales en un único objeto, usando el nombre de cada campo como clave. Recibe el formulario y devolvé ese objeto.

Un formulario HTML ya sabe agrupar sus propios campos por nombre — no hace falta ir campo por campo a mano si sabés dónde buscar esa agrupación ya lista.

datosFormulario(formularioRegistro) → { nombre: "Pau", email: "pau@mail.com" } 
<form class="registro">
  <input name="nombre" value="Pau">
  <input name="email" value="pau@mail.com">
</form>
function datosFormulario(formulario) {
  const datos = new FormData(formulario);
  return Object.fromEntries(datos.entries());
}

2 🟡 validarConfirmacionEmail(email, confirmarEmail) ⏳ Pendiente

En un formulario de registro, el usuario escribe su email dos veces para confirmar que no se equivocó al tipearlo. Recibe el campo de email y el campo de confirmación. Si no coinciden, marcá el campo de confirmación como inválido con un mensaje propio explicando el problema — el navegador debe considerar el formulario no válido por ese campo. Si coinciden, quitá esa marca para que el campo vuelva a considerarse correcto.

Los formularios HTML tienen su propio sistema de validación incorporado (el que muestra esos globos nativos del navegador), y se puede participar en él con reglas propias, no solo con las automáticas de tipo o formato.

// email = "pau@mail.com", confirmarEmail = "otro@mail.com"
validarConfirmacionEmail(email, confirmarEmail) → el campo de confirmación queda inválido
// email = "pau@mail.com", confirmarEmail = "pau@mail.com"
validarConfirmacionEmail(email, confirmarEmail) → el campo de confirmación queda válido de nuevo 
<input type="email" class="email" value="pau@mail.com">
<input type="email" class="confirmar-email" value="">
function validarConfirmacionEmail(email, confirmarEmail) {
  if (confirmarEmail.value !== email.value) {
    confirmarEmail.setCustomValidity('Los emails no coinciden');
  } else {
    confirmarEmail.setCustomValidity('');
  }
}
