1 🟢 pedirUsuario(id) ⏳ Pendiente

Simula la petición de los datos de un usuario a un servidor. Escribe pedirUsuario(id): debe devolver una promesa que, pasados 300 milisegundos, se cumpla con el objeto { id, nombre: 'Usuario ' + id } si id es mayor que 0, o se rechace con new Error('id inválido') si id es 0 o negativo.

El ejecutor de una promesa se ejecuta al instante, no cuando alguien se suscribe a su resultado — por eso el retraso simulado va dentro, reproduciendo la latencia real de una petición de red.

pedirUsuario(3) → (tras 300ms) { id: 3, nombre: "Usuario 3" }
pedirUsuario(0) → (tras 300ms) rechaza con "id inválido" 
function pedirUsuario(id) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (id > 0) {
        resolve({ id, nombre: 'Usuario ' + id });
      } else {
        reject(new Error('id inválido'));
      }
    }, 300);
  });
}

2 🟢 mostrarUsuario(id) ⏳ Pendiente

Usando pedirUsuario(id) del ejercicio anterior, escribe mostrarUsuario(id): debe devolver una promesa nueva que se cumpla con el texto 'Bienvenido, ' + nombre cuando pedirUsuario(id) tenga éxito. Si pedirUsuario(id) falla, mostrarUsuario(id) también debe fallar, pero con el motivo new Error('No se pudo cargar el usuario') en vez del original.

Consumir una promesa que ya tienes devuelve siempre una promesa NUEVA — no modifica la original. Y el motivo de un rechazo se puede transformar en otro distinto antes de que llegue a quien te llama a ti.

mostrarUsuario(3) → "Bienvenido, Usuario 3"
mostrarUsuario(-1) → rechaza con "No se pudo cargar el usuario" 
function mostrarUsuario(id) {
  return pedirUsuario(id)
    .then(usuario => 'Bienvenido, ' + usuario.nombre)
    .catch(() => {
      throw new Error('No se pudo cargar el usuario');
    });
}

3 🟡 procesarPedido(carrito) ⏳ Pendiente

Ya tienes hechas tres funciones que devuelven promesas (en dia-20-asincronia-fixtures.js): validarCarrito(carrito) (se cumple con el mismo carrito si tiene al menos un producto, o se rechaza con new Error('Carrito vacío') si está vacío), calcularTotal(carrito) (se cumple con la suma de los precio de cada producto) y confirmarPedido(total) (se cumple con el texto 'Pedido confirmado por ' + total + '€'). Escribe procesarPedido(carrito): debe llamar a las tres, en ese orden, pasando a cada una el resultado de la anterior, y devolver el resultado final como una promesa.

Cada paso de la cadena recibe lo que devolvió el anterior. Si un paso intermedio no devuelve ese valor, el siguiente paso recibe undefined en vez del valor real — el fallo más típico al encadenar promesas.

procesarPedido([{precio:10},{precio:5}]) → "Pedido confirmado por 15€"
procesarPedido([]) → rechaza con "Carrito vacío" 
function procesarPedido(carrito) {
  return validarCarrito(carrito)
    .then(carrito => calcularTotal(carrito))
    .then(total => confirmarPedido(total));
}

4 🟡 pedirConFallback(id) ⏳ Pendiente

Ya tienes hecha perfilInvitado() (en fixtures), que siempre se cumple con { id: null, nombre: 'Invitado' }. Escribe pedirConFallback(id): debe intentar pedirUsuario(id) (ejercicio 1); si esa promesa falla, el resultado debe recuperarse usando perfilInvitado() en su lugar. El resultado de pedirConFallback(id) debe cumplirse siempre, nunca rechazarse.

Un fallo a mitad de una cadena se puede "recuperar": si no se vuelve a lanzar, lo que sigue después se ejecuta con normalidad usando el valor de reserva. Es distinto de gestionar el fallo solo al final, que únicamente informa de que algo salió mal.

pedirConFallback(3) → { id: 3, nombre: "Usuario 3" }
pedirConFallback(-1) → { id: null, nombre: "Invitado" } 
function pedirConFallback(id) {
  return pedirUsuario(id)
    .catch(() => perfilInvitado());
}

5 🔴 buscarProductos(termino) ⏳ Pendiente

Ya tienes hecha buscarEnServidor(termino) (en fixtures): se cumple con un array de resultados si termino no está vacío, o se rechaza con new Error('Término vacío') si lo está. Escribe buscarProductos(termino): debe devolver una promesa que se cumpla siempre — con el array de resultados si todo fue bien, o con un array vacío [] si buscarEnServidor falló. Además, la variable ya dada buscando debe quedar en true justo al empezar la búsqueda, y volver a false al terminar, pase lo que pase (tanto si tuvo éxito como si falló).

Hay una forma de "engancharse" al final de una promesa que se ejecuta siempre, gane o pierda la operación, y que no puede cambiar el valor que sigue adelante — solo sirve para limpiar (aquí, apagar el indicador de carga).

buscarProductos('taza') → ["taza A", "taza B"]
buscarProductos('') → [] 
function buscarProductos(termino) {
  buscando = true;
  return buscarEnServidor(termino)
    .then(resultados => resultados)
    .catch(() => [])
    .finally(() => {
      buscando = false;
    });
}

1 🟢 obtenerUsuarioConCache(id, cache) ⏳ Pendiente

En una web, pedir al servidor un usuario que ya se cargó antes es tiempo perdido. cache es un objeto con los usuarios ya cargados, con el id como clave (por ejemplo { 7: { id: 7, nombre: 'Ana' } }). Escribe obtenerUsuarioConCache(id, cache): si cache tiene una entrada para ese id, devuelve ese usuario sin llamar al servidor; si no la tiene, pídelo con pedirUsuario(id) (tu función del Bloque 1). En los dos casos, quien llame a tu función tiene que recibir siempre una promesa, para poder usar .then() sin saber de dónde salió el dato.

Existe una forma de crear una promesa que ya nace cumplida con un valor, sin esperar a nada. Sirve para normalizar: que una función devuelva siempre lo mismo (una promesa), venga el dato de la caché o del servidor. Es la idea de librerías como React Query: si el dato ya está, se sirve al momento; si no, se pide.

obtenerUsuarioConCache(7, { 7: { id: 7, nombre: 'Ana' } }) → { id: 7, nombre: "Ana" } (al momento, desde la caché)
obtenerUsuarioConCache(3, {}) → { id: 3, nombre: "Usuario 3" } (tras 300ms, desde pedirUsuario) 
function obtenerUsuarioConCache(id, cache) {
  if (id in cache) return Promise.resolve(cache[id]);
  return pedirUsuario(id);
}

2 🟢 cargarDashboard() ⏳ Pendiente

El panel de usuario necesita dos datos que vienen de peticiones distintas y que no dependen una de otra: pedirPerfil() (se cumple con { nombre, email }) y pedirPedidos() (se cumple con un array de pedidos, cada uno { id, total }). Ya están hechas. Escribe cargarDashboard(): lanza las dos peticiones a la vez (no una detrás de otra) y devuelve una promesa que se cumpla con un único objeto { nombre, pedidos, totalGastado }: nombre es el del perfil, pedidos es cuántos pedidos hay, y totalGastado es la suma de los total de todos los pedidos.

Si las dos peticiones no dependen una de otra, esperarlas una detrás de otra suma sus tiempos; lanzadas a la vez, el total es el de la más lenta. El resultado llega como un array en el mismo orden en que las lanzaste (no en el que terminaron). En React harás lo mismo: juntar varias peticiones en un solo objeto antes de guardarlo en el estado del componente.

cargarDashboard() → { nombre: "Pau", pedidos: 2, totalGastado: 55 } 
function cargarDashboard() {
  return Promise.all([pedirPerfil(), pedirPedidos()])
    .then(([perfil, pedidos]) => ({
      nombre: perfil.nombre,
      pedidos: pedidos.length,
      totalGastado: pedidos.reduce((suma, pedido) => suma + pedido.total, 0)
    }));
}

3 🟡 cargarCarrito(ids) ⏳ Pendiente

El carrito guarda solo los id de los productos, y para pintarlo hace falta el detalle de cada uno. pedirProducto(id) (ya hecha) se cumple con { id, nombre, precio }. Escribe cargarCarrito(ids): pide el detalle de todos los productos a la vez y devuelve una promesa que se cumpla con el array de productos, en el mismo orden que ids. Si ids está vacío, se cumple con [].

Aquí no sabes cuántas peticiones hay hasta que llega el array de ids, así que el array de promesas se construye a partir de él. Ojo: cada elemento de ese array tiene que ser una petición ya lanzada, no undefined. Este array de productos es justo lo que en React recorrerás con .map() para pintar una lista.

cargarCarrito([1, 3]) → [{ id: 1, nombre: "Producto 1", precio: 10 }, { id: 3, nombre: "Producto 3", precio: 30 }]
cargarCarrito([]) → [] 
function cargarCarrito(ids) {
  return Promise.all(ids.map(id => pedirProducto(id)));
}

4 🟡 cargarWidgets() ⏳ Pendiente

La portada tiene tres widgets independientes, que se cargan con cargarClima(), cargarNoticias() y cargarBolsa() (ya hechas). Si uno falla, los otros dos se tienen que pintar igual. Escribe cargarWidgets(): lanza las tres cargas a la vez y devuelve una promesa que se cumpla siempre con un array de tres objetos, en ese mismo orden, con la forma { nombre, estado, datos }: nombre es 'clima', 'noticias' o 'bolsa'; estado es 'ok' si esa carga fue bien o 'error' si falló; y datos es lo que devolvió la carga, o null si falló.

Hay una forma de esperar a varias promesas que no se rinde cuando una falla: espera a todas y te dice, de cada una, si se cumplió (y con qué valor) o si se rechazó (y por qué). Cada widget con su propio estado de carga o error es exactamente lo que tendrá cada componente en React.

cargarWidgets() → [
  { nombre: "clima", estado: "ok", datos: { temperatura: 22 } },
  { nombre: "noticias", estado: "error", datos: null },
  { nombre: "bolsa", estado: "ok", datos: { indice: 1050 } }
] 
function cargarWidgets() {
  const nombres = ['clima', 'noticias', 'bolsa'];
  return Promise.allSettled([cargarClima(), cargarNoticias(), cargarBolsa()])
    .then(resultados => resultados.map((resultado, i) => ({
      nombre: nombres[i],
      estado: resultado.status === 'fulfilled' ? 'ok' : 'error',
      datos: resultado.status === 'fulfilled' ? resultado.value : null
    })));
}

5 🔴 cargarConLimite(promesa, ms) ⏳ Pendiente

Una petición que tarda demasiado deja la pantalla en "Cargando..." para siempre. Escribe cargarConLimite(promesa, ms): recibe una petición ya lanzada (promesa) y un tiempo máximo en milisegundos. Si la petición termina bien antes de ese tiempo, devuelve { cargando: false, error: null, datos } con lo que devolvió. Si pasan ms milisegundos sin que termine, el resultado es { cargando: false, error: 'Tiempo agotado', datos: null }. Y si la petición falla antes, { cargando: false, error: <mensaje del error>, datos: null }. La promesa que devuelves se cumple siempre, nunca se rechaza. Para probarla tienes ya hechas peticionRapida() (100ms, se cumple con 'Datos cargados'), peticionLenta() (2 segundos, mismo resultado) y peticionFallida() (100ms, se rechaza con new Error('Error 500')).

Si pones a competir la petición con un temporizador que falla a los ms milisegundos, gana la que termine primero, sea bien o mal. El objeto { cargando, error, datos } es el que devuelve casi cualquier hook useFetch de React: el componente decide qué pintar mirando esas tres propiedades.

cargarConLimite(peticionRapida(), 1000) → { cargando: false, error: null, datos: "Datos cargados" }
cargarConLimite(peticionLenta(), 300) → { cargando: false, error: "Tiempo agotado", datos: null }
cargarConLimite(peticionFallida(), 1000) → { cargando: false, error: "Error 500", datos: null } 
function cargarConLimite(promesa, ms) {
  const temporizador = new Promise((_, reject) => {
    setTimeout(() => reject(new Error('Tiempo agotado')), ms);
  });
  return Promise.race([promesa, temporizador])
    .then(datos => ({ cargando: false, error: null, datos }))
    .catch(error => ({ cargando: false, error: error.message, datos: null }));
}
