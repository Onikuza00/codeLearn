1 🟢 hayAlgunoCaro(productos, limite) ⏳ Pendiente

Recibe un array de objetos {nombre, precio}. Devolvé true si algún producto supera limite. Usá some().

some() pregunta "¿hay AL MENOS UNO que cumpla?" y corta apenas encuentra el primero — a diferencia de filter, no te da un array, te da un booleano directo.

hayAlgunoCaro([{nombre:"a",precio:10},{nombre:"b",precio:50}], 30) → true
hayAlgunoCaro([{nombre:"a",precio:10},{nombre:"b",precio:20}], 30) → false 
function hayAlgunoCaro(productos, limite) {
  return productos.some(p => p.precio > limite);
}

2 🟢 todosDisponibles(productos) ⏳ Pendiente

Recibe un array de objetos {nombre, stock}. Devolvé true si todos tienen stock > 0. Usá every().

every() es lo opuesto de some(): pregunta "¿TODOS cumplen?" y corta apenas encuentra el primero que NO cumple. Un array vacío siempre da true con every (no hay ningún elemento que falle).

todosDisponibles([{nombre:"a",stock:5},{nombre:"b",stock:2}]) → true
todosDisponibles([{nombre:"a",stock:5},{nombre:"b",stock:0}]) → false 
function todosDisponibles(productos) {
  return productos.every(p => p.stock > 0);
}

3 🟢 buscarPorId(usuarios, id) ⏳ Pendiente

Recibe un array de objetos {id, nombre}. Devolvé el objeto cuyo id coincide, o undefined si no existe. Usá find().

find() devuelve el PRIMER elemento que cumple la condición (el objeto completo, no un array). Si ninguno cumple, devuelve undefined — nunca null, ojo con ese detalle al comparar.

buscarPorId([{id:1,nombre:"Ana"},{id:2,nombre:"Bruno"}], 2) → {id:2,nombre:"Bruno"}
buscarPorId([{id:1,nombre:"Ana"}], 5) → undefined 
function buscarPorId(usuarios, id) {
  return usuarios.find(u => u.id === id);
}

4 🟢 posicionDe(usuarios, id) ⏳ Pendiente

Igual que buscarPorId, pero devolvé el índice del objeto cuyo id coincide, o -1 si no existe. Usá findIndex().

findIndex() es a find() lo que indexOf() es a includes(): mismo criterio de búsqueda, pero te da la posición en vez del elemento. Por eso el "no encontrado" es -1, no undefined.

posicionDe([{id:1,nombre:"Ana"},{id:2,nombre:"Bruno"}], 2) → 1
posicionDe([{id:1,nombre:"Ana"}], 5) → -1 
function posicionDe(usuarios, id) {
  return usuarios.findIndex(u => u.id === id);
}

5 🟡 hayHuecos(array) ⏳ Pendiente

Recibe un array de números. Devolvé true si hay algún null o undefined mezclado. Usá some().

Mismo some() del E1, pero la condición ahora es sobre el tipo/valor del elemento en sí (n === null || n === undefined), no sobre una propiedad de un objeto. some sirve para cualquier "¿hay al menos uno que...?", venga de donde venga la condición.

hayHuecos([1, 2, null, 4]) → true
hayHuecos([1, 2, 3, 4]) → false 
function hayHuecos(array) {
  return array.some(n => n === null || n === undefined);
}

1 🟡 duplicarPuntuacion(jugador) ⏳ Pendiente

Recibe { nombre, puntos }. Devolvé un objeto nuevo con el doble de puntos. NO mutes jugador. Usá spread.

Mismo patrón que actualizarEdad (Día 10): { ...jugador, puntos: jugador.puntos * 2 } copia todas las propiedades y pisa puntos. El runner comprueba las DOS cosas: que el resultado sea correcto, Y que jugador siga intacto después de llamar tu función.

duplicarPuntuacion({nombre:"Ana", puntos:10}) → {nombre:"Ana", puntos:20}
// el objeto original {nombre:"Ana", puntos:10} debe seguir igual 
function duplicarPuntuacion(jugador) {
  return { ...jugador, puntos: jugador.puntos * 2 };

2 🟡 agregarItem(carrito, item) ⏳ Pendiente

Recibe un array carrito. Devolvé un array nuevo con item agregado al final. NO uses push sobre el original. Usá spread.

push() muta el array en el lugar — es el equivalente en arrays de asignar directo una propiedad de un objeto. La versión "no mutar, crear nuevo" es [...carrito, item], igual que { ...objeto, clave: valor } con objetos.

agregarItem(["manzana", "pan"], "leche") → ["manzana", "pan", "leche"]
// el array original ["manzana", "pan"] debe seguir igual 
function agregarItem(carrito, item) {
  return [...carrito, item];
}

3 🟡 predecirValorFinal() ⏳ Pendiente

Mirá este código SIN ejecutarlo y predecí qué imprime el console.log final. Tu función debe devolver ese número.

function mutarObjeto(obj) {
  obj.valor = obj.valor + 10;
}

function mutarPrimitivo(valor) {
  valor = valor + 10;
}

const datos = { valor: 5 };
mutarObjeto(datos);
mutarPrimitivo(datos.valor);
console.log(datos.valor); // → ?

La clave: mutarObjeto(datos) recibe la REFERENCIA al objeto — modificar obj.valor adentro sí afecta a datos. Pero mutarPrimitivo(datos.valor) recibe un número SUELTO: en el momento en que lo pasás como argumento, ese número se copia por valor. Reasignar valor adentro de la función no toca datos.valor para nada — un primitivo sacado de un objeto sigue siendo un primitivo independiente.

function predecirValorFinal() {
  // mutarObjeto SÍ afecta datos.valor: 5 + 10 = 15
  // mutarPrimitivo recibe una COPIA del número, no afecta nada más
  return 15;
}

1 🔴 crearBoton(texto) ⏳ Pendiente

Devuelve { texto, onClick } donde onClick debe devolver "Click en: " + texto. El código de partida en dia-13-metodos-avanzados-soluciones.js YA TIENE un bug de "this perdido": funciona si llamás boton.onClick(), pero revienta si sacás el método suelto (const click = boton.onClick; click()). Arreglalo.

Cuando llamás boton.onClick(), this es boton. Pero si sacás la función y la llamás sola, pierde ese contexto — this ya no apunta a nada útil. La forma más simple de arreglarlo: no depender de this en absoluto, y usar un closure sobre el parámetro texto directamente (arrow function). Alternativa válida: .bind(this) dentro del objeto.

const boton = crearBoton("Guardar");
const click = boton.onClick; // se saca "suelto"
click() → "Click en: Guardar" 
function crearBoton(texto) {
  return {
    texto: texto,
    // arrow function: no tiene su propio "this", usa el closure
    // sobre "texto" en vez de depender de this.texto
    onClick: () => 'Click en: ' + texto
  };
}

2 🔴 crearContadorConThis() ⏳ Pendiente

Devolvé un objeto { valor, incrementar }. incrementar debe usar una arrow function interna que sume 1 a this.valor y devuelva el valor actualizado.

Al contrario que E9: acá incrementar SÍ es un método normal (lo llamás siempre como c.incrementar(), nunca suelto), así que this dentro de él es el objeto correctamente. La arrow function interna demuestra la otra cara del "this léxico": no crea su propio this, hereda el de incrementar en el momento en que se define — por eso this.valor adentro de la arrow apunta al mismo objeto sin trucos extra.

const c = crearContadorConThis();
c.incrementar() → 1
c.incrementar() → 2
c.incrementar() → 3 
function crearContadorConThis() {
  return {
    valor: 0,
    incrementar: function () {
      const sumarUno = () => {
        this.valor++;
      };
      sumarUno();
      return this.valor;
    }
  };
}

1 🟢 dividirSeguro(a, b) ⏳ Pendiente

Si b es 0, lanzá un Error con mensaje descriptivo y capturalo devolviendo null. Si no, devolvé a / b.

throw new Error("mensaje") corta la ejecución y salta directo al catch más cercano. Es la forma de decir "esto no debería pasar, andá a manejarlo en otro lado" en vez de devolver un valor raro (NaN, Infinity) que el que llama a la función capaz ni revisa.

dividirSeguro(10, 2) → 5
dividirSeguro(10, 0) → null 
function dividirSeguro(a, b) {
  try {
    if (b === 0) throw new Error('No se puede dividir por cero');
    return a / b;
  } catch (error) {
    return null;
  }
}

2 🟡 parsearJSON(texto) ⏳ Pendiente

Intentá convertir texto con JSON.parse. Si el texto no es JSON válido, devolvé null en vez de dejar que el error rompa el programa.

JSON.parse lanza un SyntaxError cuando el texto está mal formado — no devuelve undefined ni null silenciosamente. Cualquier función que reciba datos "de afuera" (una API, un input del usuario) y los parsee necesita este mismo patrón de try/catch.

parsearJSON('{"a":1}') → {a: 1}
parsearJSON('{invalido}') → null 
function parsearJSON(texto) {
  try {
    return JSON.parse(texto);
  } catch (error) {
    return null;
  }
}

3 🟡 procesarConLimpieza(fn) ⏳ Pendiente

Ejecutá fn(). Si lanza error, capturalo (el resultado queda null). Pase lo que pase, el finally debe marcar procesoTerminado = true. Devolvé { resultado, procesoTerminado }.

El bloque finally se ejecuta SIEMPRE — haya error o no, haya return en el try o en el catch. Es el lugar correcto para "limpieza" que tiene que pasar sí o sí (cerrar una conexión, apagar un loading, marcar que terminó), sin duplicar esa línea en el try Y en el catch.

procesarConLimpieza(() => 42) → {resultado: 42, procesoTerminado: true}
procesarConLimpieza(() => { throw new Error("fail"); }) → {resultado: null, procesoTerminado: true} 
function procesarConLimpieza(fn) {
  let procesoTerminado = false;
  let resultado;
  try {
    resultado = fn();
  } catch (error) {
    resultado = null;
  } finally {
    procesoTerminado = true;
  }
  return { resultado, procesoTerminado };
}

1 🔴 class ErrorEdadInvalida + validarEdad(edad) ⏳ Pendiente

Creá class ErrorEdadInvalida extends Error con constructor(edad) que arme un mensaje descriptivo y guarde this.edad. Luego validarEdad(edad) debe lanzar new ErrorEdadInvalida(edad) si edad < 0 o edad > 120; si es válida, devolvé la misma edad.

Extender Error te deja crear tipos de error con nombre propio y datos extra (this.edad), en vez de un Error genérico con solo un mensaje de texto. Regla clave de clases derivadas: super(mensaje) tiene que llamarse ANTES de usar this en el constructor — si no, JS tira ReferenceError.

validarEdad(30) → 30
validarEdad(150) → 💥 lanza ErrorEdadInvalida (edad: 150) 
class ErrorEdadInvalida extends Error {
  constructor(edad) {
    super(`La edad ${edad} no es válida (debe estar entre 0 y 120)`);
    this.edad = edad;
  }
}

function validarEdad(edad) {
  if (edad < 0 || edad > 120) {
    throw new ErrorEdadInvalida(edad);
  }
  return edad;
}

2 🟡 manejarValidacion(edad) ⏳ Pendiente

Llamá a validarEdad(edad) dentro de un try. Usá instanceof ErrorEdadInvalida en el catch para distinguirlo de cualquier otro error. Devolvé "Edad válida: X", "Edad inválida: <mensaje>" o "Error inesperado: <mensaje>" según corresponda.

instanceof pregunta "¿este objeto fue creado con esta clase (o una que la extiende)?" — es lo que te permite reaccionar distinto según el TIPO de error, en vez de tratar cualquier catch (error) como si fuera el mismo problema. Depende de E14: si ErrorEdadInvalida o validarEdad todavía no están completos, este ejercicio va a fallar en cadena.

manejarValidacion(30) → "Edad válida: 30"
manejarValidacion(150) → "Edad inválida: La edad 150 no es válida (debe estar entre 0 y 120)" 
function manejarValidacion(edad) {
  try {
    validarEdad(edad);
    return `Edad válida: ${edad}`;
  } catch (error) {
    if (error instanceof ErrorEdadInvalida) {
      return `Edad inválida: ${error.message}`;
    }
    return `Error inesperado: ${error.message}`;
  }
}
