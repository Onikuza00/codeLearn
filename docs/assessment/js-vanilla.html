📋 Examen Práctico JS — Task Dashboard

Contexto: Tenés que construir un dashboard de gestión de tareas desde cero. Sin frameworks, sin librerías, sin copiar código. JavaScript vanilla 100%.

Tiempo estimado: 50–65 min.

Reglas: const por defecto, let solo si reasignás. Nada de var. Early returns. Funciones de <= 20 líneas. Sin innerHTML para crear elementos (usá createElement).

Archivos: dashboard.html + dashboard.js. Todo desde cero.

Datos iniciales (copialos en tu JS):

const tasks = [
  { id: 1, title: 'Diseñar header responsive', category: 'CSS', completed: true },
  { id: 2, title: 'Implementar grid de servicios', category: 'CSS', completed: true },
  { id: 3, title: 'Agregar animaciones con GSAP', category: 'JS', completed: false },
  { id: 4, title: 'Crear endpoint de usuarios', category: 'PHP', completed: false },
  { id: 5, title: 'Revisar accesibilidad', category: 'CSS', completed: false },
  { id: 6, title: 'Optimizar imágenes', category: 'UX', completed: true },
];

Feature 1 — Estructura inicial DOM

Renderizar el dashboard — Creá toda la estructura HTML desde JavaScript usando createElement y appendChild.
  • Creá un <header> con un título "Task Dashboard 🔥" y un subtítulo con el total de tareas.
  • Creá un <section class="filters"> con 3 botones de filtro: "Todas", "Pendientes", "Completadas".
  • Creá un <section class="stats"> que muestre: Total, Completadas, Pendientes (solo los números).
  • Creá un <main class="task-list"> vacío donde se renderizarán las cards de tareas.
  • Creá un <form class="add-task"> con un input de texto, un select de categorías (CSS, JS, PHP, UX) y un botón "Agregar".
  • Todo debe crearse desde JS. El HTML solo tiene <div id="app"></div>.

Feature 2 — Renderizar tareas Arrays DOM

Mostrar las tareas — Función renderTasks(array) que recibe un array y pinta las cards en el DOM.
  • Cada card debe tener: checkbox de completada, título, categoría (con un color distinto por categoría), y botón "Eliminar".
  • Usá map() + join('') o createElement por cada tarea. La que prefieras.
  • Si la tarea está completada, la card debe tener una clase .task--done que la opaque o tache el texto.
  • Renderizá todo llamando a renderTasks(tasks) al cargar la página.
  • BONUS: Usá dataset para guardar el id de cada tarea en la card.

Feature 3 — Filtrar tareas Filter Events

Filtros funcionales — Al clickear un botón de filtro, mostrar solo las tareas correspondientes.
  • "Todas": muestra todas.
  • "Pendientes": filter(t => !t.completed).
  • "Completadas": filter(t => t.completed).
  • El botón activo debe tener una clase visual distinta (ej: .filter--active).
  • Usá delegación de eventos o event listeners separados — como prefieras, pero explicá por qué elegiste uno u otro.
  • Al cambiar el filtro, actualizá también las stats (Feature 5).

Feature 4 — Agregar tareas Events createElement

Formulario funcional — Al enviar el formulario, crear una nueva tarea y agregarla al array.
  • Escuchá el evento submit del formulario.
  • Prevení el comportamiento por defecto (e.preventDefault()).
  • Creá un objeto tarea con: id (Date.now() o Math.random), title, category, completed: false.
  • Agregalo al array con spread operator: tasks = [...tasks, newTask] (o push si usás let).
  • Re-renderizá con el filtro actual activo.
  • Limpiá el input después de agregar.
  • Validá que el input no esté vacío — si está vacío, mostrá un mensaje o agregá :has(:invalid) si también estilás con CSS.

Feature 5 — Stats en vivo Reduce

Estadísticas actualizadas — Función updateStats() que calcula total, completadas y pendientes con reduce().
  • Usá reduce() para contar: tasks.reduce((acc, t) => { t.completed ? acc.done++ : acc.pending++; return acc; }, { done: 0, pending: 0 }).
  • Actualizá el contenido de .stats cada vez que se rendericen tareas.

Feature 6 — Async: cargar tareas externas Fetch Async/Await

Cargar tareas desde una API — Al inicio, intentar cargar tareas desde https://jsonplaceholder.typicode.com/todos?_limit=5.
  • Creá una función async function loadExternalTasks().
  • Usá fetch() con await.
  • Mapeá la respuesta al formato de tus tareas: { id, title, category: 'API', completed }.
  • Si la API responde bien, combiná las tareas externas con las locales usando spread.
  • Si la API falla (try/catch), usá solo las tareas locales y mostrá un mensaje en consola.
  • Llamá a loadExternalTasks() al inicio y después renderizá.
  • BONUS: Mostrá un indicador de carga mientras se resuelve el fetch.

Feature 7 — Eliminar tareas Filter Events

Botón eliminar funcional — Al clickear "Eliminar" en una card, sacar la tarea del array y re-renderizar.
  • Usá filter() para crear un nuevo array sin la tarea eliminada.
  • Identificá la tarea por su id (usá dataset.id o dataset.taskId).
  • Antes de eliminar, mostrá un confirm('¿Eliminar tarea?').
  • Re-renderizá después de eliminar.

Bonus — Persistencia localStorage

Opcional — Guardar las tareas en localStorage y recuperarlas al recargar.
  • Al modificar el array (agregar, eliminar, toggle), guardalo con localStorage.setItem('tasks', JSON.stringify(tasks)).
  • Al cargar la página, revisá si hay tareas guardadas con JSON.parse(localStorage.getItem('tasks')).
  • Si hay datos guardados, usalos en vez del array inicial. Si no, usá el array de ejemplo.
  • Esto demuestra que entendés persistencia en el navegador.
⏱️ Priorizá las features en orden. Si no llegás a todo, que esté completo hasta Feature 4 como mínimo. El Bonus es solo si sobra tiempo.

✅ Checklist de conceptos evaluados

  • ☐ createElement / appendChild para construir el DOM desde cero
  • ☐ map(), filter(), reduce() para manipular arrays de datos
  • ☐ Event listeners (submit, click) y delegación
  • ☐ Spread operator para agregar items sin mutar
  • ☐ dataset para guardar datos en el DOM
  • ☐ async / await + fetch + try/catch
  • ☐ filter() para eliminar elementos
  • ☐ reduce() para acumular valores
  • ☐ const/let, template literals, arrow functions
  • ☐ localStorage para persistencia (bonus)
