1 🟢 Entidad Tarea ⏳ Pendiente

Creá la entidad Tarea con make:entity: title (string), done (bool), createdAt (datetime). Migrá la BD.

Repaso del flujo completo: make:entity → make:migration → doctrine:migrations:migrate. Ver Doctrine → Entity.

symfony console make:entity Tarea
symfony console make:migration
symfony console doctrine:migrations:migrate 
// src/Entity/Tarea.php
class Tarea
{
    private ?int $id = null;
    private ?string $title = null;
    private ?bool $done = false;
    private ?\DateTimeImmutable $createdAt = null;
}
2 🟢 GET /tareas — listar ⏳ Pendiente

Ruta + método de controller que devuelva todas las tareas usando el Repository (no el EntityManager a mano) y las renderice con Twig.

Ver Doctrine → Repository — findAll() es uno de los 5 métodos que ya trae hecho.

GET /tareas → 200, HTML con la lista 
#[Route('/tareas', name: 'tarea_index')]
public function index(TareaRepository $tareaRepository): Response
{
    return $this->render('tarea/index.html.twig', [
        'tareas' => $tareaRepository->findAll(),
    ]);
}

4 🟢 Twig — tarea/index.html.twig ⏳ Pendiente

Extiende base.html.twig. Un {% for %} listando títulos con link a tarea_show. Si no hay tareas, usá el {% else %} del propio for.

Ver Twig → Estructuras de control y Twig → Enlaces dinámicos (path()).

{% extends 'base.html.twig' %}
{% block body %}
  <ul>
  {% for tarea in tareas %}
    <li><a href="{{ path('tarea_show', {id: tarea.id}) }}">{{ tarea.title }}</a></li>
  {% else %}
    <li>No hay tareas.</li>
  {% endfor %}
  </ul>
{% endblock %}
5 🟢 Twig — tarea/show.html.twig ⏳ Pendiente

El título, y un {% if %}/{% else %} que muestre "✅ Hecha" o "⏳ Pendiente" según tarea.done.

Notación de punto: tarea.done llama a isDone()/getDone() por detrás — nunca accede a la propiedad privada directo. Ver Twig → Tipos de variables.

  <h1>{{ tarea.title }}</h1>
  {% if tarea.done %}
    <p>✅ Hecha</p>
  {% else %}

  {% endif %}

6 🟡 POST /tareas — crear ⏳ Pendiente

Ruta + método que reciba title por query string (Request $request, $request->query->get('title')) y cree una Tarea nueva con el EntityManager: persist() + flush(). done = false, createdAt = new \DateTimeImmutable().

Primera vez usando el EntityManager en este proyecto — hasta ahora solo leíste con el Repository. persist() solo prepara, flush() ejecuta el INSERT real. Ver Doctrine → El EntityManager.

curl -X POST "http://localhost:8000/tareas?title=Estudiar+Symfony" → 201/302, tarea creada 
#[Route('/tareas', name: 'tarea_crear', methods: ['POST'])]
public function crear(Request $request, EntityManagerInterface $em): Response
{
    $tarea = new Tarea();
    $tarea->setTitle($request->query->get('title'));
    $tarea->setDone(false);
    $tarea->setCreatedAt(new \DateTimeImmutable());

    $em->persist($tarea);
    $em->flush();

    return $this->redirectToRoute('tarea_index');
}
7 🟢 POST /tareas/{id}/completar ⏳ Pendiente

Marcá una tarea existente como hecha: ParamConverter para traerla (Tarea $tarea), setDone(true), y flush() — sin persist().

La entidad ya está gestionada por Doctrine (vino de la BD vía ParamConverter) — modificarla y hacer flush() alcanza. persist() es solo para entidades NUEVAS que Doctrine todavía no conoce.

curl -X POST http://localhost:8000/tareas/1/completar → tarea 1 con done = true 
#[Route('/tareas/{id}/completar', name: 'tarea_completar', methods: ['POST'])]
public function completar(Tarea $tarea, EntityManagerInterface $em): Response
{
    $tarea->setDone(true);
    $em->flush();

    return $this->redirectToRoute('tarea_index');
}
8 🟢 POST /tareas/{id}/borrar ⏳ Pendiente

Borrá una tarea existente: ParamConverter para traerla, remove() + flush().

remove() es el opuesto simétrico de persist() — marca para borrar, no ejecuta nada hasta el flush(). Ver Doctrine → El EntityManager.

curl -X POST http://localhost:8000/tareas/1/borrar → tarea 1 ya no existe 
#[Route('/tareas/{id}/borrar', name: 'tarea_borrar', methods: ['POST'])]
public function borrar(Tarea $tarea, EntityManagerInterface $em): Response
{
    $em->remove($tarea);
    $em->flush();

    return $this->redirectToRoute('tarea_index');
}
9 🔴 QueryBuilder — findPendientes() ⏳ Pendiente

En TareaRepository, un método personalizado findPendientes() que devuelva solo las tareas con done = false, ordenadas por createdAt descendente (las más nuevas primero). Usalo en la ruta GET /tareas en vez de findAll().

Mismo patrón que findByNameLike de la doc: createQueryBuilder → where → setParameter → orderBy → getQuery → getResult. Ver Doctrine → QueryBuilder (línea por línea).

// src/Repository/TareaRepository.php
public function findPendientes(): array
{
    return $this->createQueryBuilder('t')
        ->where('t.done = :done')
        ->setParameter('done', false)
        ->orderBy('t.createdAt', 'DESC')
        ->getQuery()
        ->getResult();
}
10 🟡 Twig — include ⏳ Pendiente

Sacá el <li> del {% for %} de tarea/index.html.twig a un fragmento nuevo tarea/_item.html.twig, e incluilo con {% include %} pasándole la variable tarea.

Diferencia con extends: include mete un trozo pequeño y reutilizable en un punto cualquiera, no hereda la estructura entera. Ver Twig → Include.

{# templates/tarea/_item.html.twig #}
<li><a href="{{ path('tarea_show', {id: tarea.id}) }}">{{ tarea.title }}</a></li>

{# templates/tarea/index.html.twig #}
{% for tarea in tareas %}
  {% include 'tarea/_item.html.twig' with {tarea: tarea} %}
{% else %}
  <li>No hay tareas.</li>
{% endfor %}
11 🟢 Twig — filtros ⏳ Pendiente

En tarea/index.html.twig: un título con el total de tareas usando el filtro length, y en cada <li> la fecha de createdAt formateada con date('d/m/Y').

Filtros encadenables con |. Ver Twig → Filtros útiles (tabla completa: length, date, default, etc).

<h1>Tareas ({{ tareas|length }})</h1>
<ul>
{% for tarea in tareas %}
  <li>{{ tarea.title }} — {{ tarea.createdAt|date('d/m/Y') }}</li>
{% endfor %}
</ul>
