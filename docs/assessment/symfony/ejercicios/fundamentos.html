6 🟡 POST /tareas — crear ⏳ Pendiente

Ruta + método que reciba title por query string (Request $request, $request->query->get('title')) y cree una Tarea nueva con el EntityManager: persist() + flush(). done = false, createdAt = new \DateTimeImmutable().

Primera vez usando el EntityManager en este proyecto — hasta ahora solo leíste con el Repository. persist() solo prepara, flush() ejecuta el INSERT real. Ver Doctrine → El EntityManager.

curl -X POST "http://localhost:8000/tareas?title=Estudiar+Symfony" → 201/302, tarea creada 
#[Route('/tareas', name: 'tarea_crear', methods: ['POST'])]
public function crear(Request $request, EntityManagerInterface $em): Response
{
    $tarea = new Tarea();
    $tarea->setTitle($request->query->get('title'));
    $tarea->setDone(false);
    $tarea->setCreatedAt(new \DateTimeImmutable());

    $em->persist($tarea);
    $em->flush();

    return $this->redirectToRoute('tarea_index');
}
7 🟢 POST /tareas/{id}/completar ⏳ Pendiente

Marcá una tarea existente como hecha: ParamConverter para traerla (Tarea $tarea), setDone(true), y flush() — sin persist().

La entidad ya está gestionada por Doctrine (vino de la BD vía ParamConverter) — modificarla y hacer flush() alcanza. persist() es solo para entidades NUEVAS que Doctrine todavía no conoce.

curl -X POST http://localhost:8000/tareas/1/completar → tarea 1 con done = true 
#[Route('/tareas/{id}/completar', name: 'tarea_completar', methods: ['POST'])]
public function completar(Tarea $tarea, EntityManagerInterface $em): Response
{
    $tarea->setDone(true);
    $em->flush();

    return $this->redirectToRoute('tarea_index');
}
8 🟢 POST /tareas/{id}/borrar ⏳ Pendiente

Borrá una tarea existente: ParamConverter para traerla, remove() + flush().

remove() es el opuesto simétrico de persist() — marca para borrar, no ejecuta nada hasta el flush(). Ver Doctrine → El EntityManager.

curl -X POST http://localhost:8000/tareas/1/borrar → tarea 1 ya no existe 
#[Route('/tareas/{id}/borrar', name: 'tarea_borrar', methods: ['POST'])]
public function borrar(Tarea $tarea, EntityManagerInterface $em): Response
{
    $em->remove($tarea);
    $em->flush();

    return $this->redirectToRoute('tarea_index');
}
9 🔴 QueryBuilder — findPendientes() ⏳ Pendiente

En TareaRepository, un método personalizado findPendientes() que devuelva solo las tareas con done = false, ordenadas por createdAt descendente (las más nuevas primero). Usalo en la ruta GET /tareas en vez de findAll().

Mismo patrón que findByNameLike de la doc: createQueryBuilder → where → setParameter → orderBy → getQuery → getResult. Ver Doctrine → QueryBuilder (línea por línea).

// src/Repository/TareaRepository.php
public function findPendientes(): array
{
    return $this->createQueryBuilder('t')
        ->where('t.done = :done')
        ->setParameter('done', false)
        ->orderBy('t.createdAt', 'DESC')
        ->getQuery()
        ->getResult();
}

1 🟢 TareaType con make:form ⏳ Pendiente

Genera TareaType vinculado a la entidad Tarea con el maker. El maker añade un campo por cada propiedad de la entidad — dejalo solo con title, editable, con label y required. done y createdAt los gestiona el servidor, no el usuario desde el formulario.

Ver Formularios → make:form paso a paso y Formularios → buildForm().

symfony console make:form TareaType Tarea 
// src/Form/TareaType.php
class TareaType extends AbstractType
{
    public function buildForm(FormBuilderInterface $builder, array $options): void
    {
        $builder->add('title', TextType::class, [
            'label' => 'Título',
            'required' => true,
        ]);
    }

    public function configureOptions(OptionsResolver $resolver): void
    {
        $resolver->setDefaults(['data_class' => Tarea::class]);
    }
}
2 🟡 Constraints sobre title ⏳ Pendiente

Añade Constraints sobre la propiedad title de la entidad Tarea: no puede estar vacío, y mínimo 3 caracteres. Mensajes de error en castellano.

Las Constraints van sobre la entidad, no sobre el formulario — el formulario las aplica solo. Ver Formularios → Constraints.

#[Assert\NotBlank(message: 'El título es obligatorio.')]

private ?string $title = null;
3 🟡 GET/POST /tareas/crear ⏳ Pendiente

Un único método de controller que sirva las dos cosas: en GET muestra el formulario vacío; en POST válido, guarda la tarea con el EntityManager y redirige al listado; en POST inválido, vuelve a mostrar el formulario con los errores.

Combina lo que ya usaste en crear() de Fundamentos (Ejercicio 6: persist() + flush()) con el flujo nuevo de Formularios. Ver Formularios → Procesamiento con el controlador.

GET /tareas/crear → 200, formulario vacío
POST /tareas/crear (title válido) → 302 a tarea_index, tarea creada
POST /tareas/crear (title vacío) → 200, formulario con el error 
#[Route('/tareas/crear', name: 'tarea_crear')]
public function crear(Request $request, EntityManagerInterface $em): Response
{
    $tarea = new Tarea();
    $tarea->setDone(false);
    $tarea->setCreatedAt(new \DateTimeImmutable());

    $form = $this->createForm(TareaType::class, $tarea);
    $form->handleRequest($request);

    if ($form->isSubmitted() && $form->isValid()) {
        $em->persist($tarea);
        $em->flush();

        return $this->redirectToRoute('tarea_index');
    }

    return $this->render('tarea/crear.html.twig', [
        'formularioTarea' => $form->createView(),
    ]);
}
4 🟢 Twig — tarea/crear.html.twig ⏳ Pendiente

Ver Formularios → Renderizado en Twig (form_start / form_widget / form_end).

5 🔴 GET/POST /tareas/{id}/editar ⏳ Pendiente

Mismo TareaType, reutilizado para editar una tarea que ya existe: ParamConverter la trae, el formulario nace ya relleno con sus datos. Al guardar, no hace falta persist() — la entidad ya la conoce Doctrine.

Combina ParamConverter (Fundamentos E3/E7/E8) con Formularios: createForm(TareaType::class, $tarea) con una entidad YA cargada precarga sus valores actuales en el formulario, sin que hagas nada extra.

GET /tareas/1/editar → 200, formulario con el title actual ya puesto
POST /tareas/1/editar (title válido) → 302 a tarea_index, tarea actualizada 
#[Route('/tareas/{id}/editar', name: 'tarea_editar')]
public function editar(Tarea $tarea, Request $request, EntityManagerInterface $em): Response
{
    $form = $this->createForm(TareaType::class, $tarea);
    $form->handleRequest($request);

    if ($form->isSubmitted() && $form->isValid()) {
        $em->flush(); // sin persist(): $tarea ya la gestiona Doctrine

        return $this->redirectToRoute('tarea_index');
    }

    return $this->render('tarea/crear.html.twig', [
        'formularioTarea' => $form->createView(),
    ]);
}

7 🟡 Campo done como ChoiceType expandido ⏳ Pendiente

En el formulario de edición (no en el de crear), añade el campo done como ChoiceType con dos opciones ("Pendiente" / "Hecha") mostradas como radio buttons, no como desplegable.

Combina la opción personalizada del configureOptions() (patrón esAdmin del PDF: una opción propia que buildForm() lee para decidir qué campos añadir) con ChoiceType + expanded. Ver Formularios → Tipos de campo y → Opciones (choices, expanded).

public function buildForm(FormBuilderInterface $builder, array $options): void
{
    $builder->add('title', TextType::class, ['label' => 'Título']);

    if ($options['esEdicion']) {
        $builder->add('done', ChoiceType::class, [
            'label' => 'Estado',
            'choices' => ['Pendiente' => false, 'Hecha' => true],
            'expanded' => true,
        ]);
    }
}

public function configureOptions(OptionsResolver $resolver): void
{
    $resolver->setDefaults(['data_class' => Tarea::class, 'esEdicion' => false]);
}
8 🔴 Formulario de búsqueda (sin entidad) ⏳ Pendiente

Un BusquedaType con un único campo termino (texto), sin vincularlo a ninguna clase. En GET /tareas, si llega un término, filtra las tareas cuyo title lo contenga.

Un formulario no siempre está atado a una entidad — sin data_class, simplemente recoge datos sueltos. Combina esto con QueryBuilder (Fundamentos E9: createQueryBuilder → where → setParameter), usando el operador LIKE.

GET /tareas?termino=symfony → solo tareas cuyo título contiene "symfony" 
// src/Form/BusquedaType.php — sin configureOptions con data_class
public function buildForm(FormBuilderInterface $builder, array $options): void
{
    $builder
        ->add('termino', TextType::class, ['required' => false])
        ->add('buscar', SubmitType::class);
}

// TareaRepository.php
public function findByTitulo(string $termino): array
{
    return $this->createQueryBuilder('t')
        ->where('t.title LIKE :termino')
        ->setParameter('termino', '%'.$termino.'%')
        ->getQuery()->getResult();
}
9 🟡 Borrar con formulario, no con link ⏳ Pendiente

Sustituye el link directo de borrado (Fundamentos E8) por un mini-formulario de un solo botón (SubmitType, sin campos de datos) que haga POST a la misma ruta de borrar.

Un link <a> hace siempre GET y no lleva token CSRF — cualquier página podría "borrar por ti" con solo poner ese link. Un formulario sí protege la acción. Ver Formularios → el tip del token CSRF en form_end().

{# dentro de tarea/_item.html.twig #}
<form method="post" action="{{ path('tarea_borrar', {id: tarea.id}) }}">
    <button type="submit">Borrar</button>
</form>
