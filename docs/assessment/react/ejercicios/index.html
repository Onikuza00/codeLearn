Cómo trabajar estos ejercicios.

  • Hay cinco ejercicios por subbloque de Fundamentos, pensados para piezas que se repiten en una landing o en una aplicación: barras de navegación, héroes, precios, testimonios, formularios…
  • Todos se hacen en un único proyecto, el que creas en el primero. Cada ejercicio vive en su carpeta: src/ejercicios/ex12/ es el 2.º del subbloque 1, ex34/ el 4.º del subbloque 3, y así.
  • Para ver un ejercicio en el navegador, impórtalo en App.jsx y pinta ese componente.
  • El aspecto se describe con palabras: las clases de Tailwind las buscas tú.
  • La solución está oculta tras un botón. Inténtalo antes de abrirla.
  • 🟢 fácil · 🟡 medio. Los ejercicios van de menos a más dentro de cada subbloque.

1 · 🟢 Proyecto base con Vite y Tailwind

✅ Completado ▼

Vas a crear el proyecto donde harás todos los ejercicios, y que te servirá de punto de partida para una landing. Un proyecto de React es una carpeta con herramientas ya preparadas: Vite lo crea y lo arranca, y Tailwind te permite dar estilo con clases.

Qué tienes que hacer

  1. Crea un proyecto de Vite con la plantilla de React, llamado ejercicios-react, e instala sus dependencias.
  2. Instala Tailwind en ese proyecto y déjalo conectado, de modo que se pueda usar en cualquier componente.
  3. Limpia lo que trae la plantilla: borra los estilos de ejemplo y deja App.jsx mostrando solo un título.
  4. Crea la carpeta src/ejercicios. En ella irás metiendo una carpeta por ejercicio: ex12, ex13…
  5. Arranca el servidor y comprueba en el navegador que el título se ve con estilo.

Cómo debe verse. Un título «Hola React» en letra muy grande y en negrita, de color azul, centrado en la página y con algo de espacio por encima. Si el título se ve con la letra por defecto del navegador, Tailwind no está bien conectado.

http://localhost:5173

              Hola React        ← grande, negrita, azul, centrado

📖 Teoría: Entorno con Vite · Tailwind en React

// terminal
pnpm create vite@latest ejercicios-react --template react
cd ejercicios-react
pnpm install
pnpm add tailwindcss @tailwindcss/vite
pnpm dev
// vite.config.js
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import tailwindcss from "@tailwindcss/vite";

export default defineConfig({
    plugins: [react(), tailwindcss()],
});
// src/index.css
@import "tailwindcss";
// src/App.jsx
export default function App() {
    return <h1 className="mt-10 text-center text-4xl font-bold text-blue-600">Hola React</h1>;
}

2 · 🟢 Personaliza el index.html y el logo

✅ Completado ▼

Lo primero que ve un visitante de una landing es la pestaña del navegador: el título y el icono. Eso no se cambia dentro de React, sino en el archivo HTML que sirve Vite.

Qué tienes que hacer

  1. Abre el index.html de la raíz del proyecto y cambia el idioma de la página a español.
  2. Cambia el título de la pestaña a «Mi landing».
  3. Añade una descripción de la página, la que leen los buscadores.
  4. Pon un icono propio en la pestaña, sustituyendo el que trae Vite. Sirve cualquier imagen pequeña o un SVG sencillo.
  5. Consigue un logo (una imagen cualquiera) y muéstralo en App.jsx con una etiqueta <img>. Tú decides si lo guardas en public/ o en src/assets/; en un comentario del archivo explica por qué.

Cómo debe verse. En la pestaña del navegador se ve tu icono y el texto «Mi landing». En la página, el logo pequeño (unos 64 píxeles de ancho), centrado y con algo de espacio por encima.

Pestaña:  [icono] Mi landing

Página:
              [logo 64px]

📖 Teoría: Entorno con Vite

// index.html
<!doctype html>
<html lang="es">
  <head>
    <meta charset="UTF-8" />
    <link rel="icon" type="image/svg+xml" href="/favicon.svg" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <meta name="description" content="Landing de ejemplo hecha con React." />
    <title>Mi landing</title>
  </head>
  <body>
    <div id="root"></div>
    <script type="module" src="/src/main.jsx"></script>
  </body>
</html>
// src/App.jsx
// El logo va en src/assets porque se importa: Vite lo procesa y le añade un hash.
// El favicon va en public/ porque el navegador lo pide con su nombre exacto.
import logo from "./assets/logo.svg";

export default function App() {
    return <img src={logo} alt="Logo de Mi landing" className="mx-auto mt-10 w-16" />;
}

3 · 🟢 Hero sin JSX

✅ Completado ▼

JSX es una comodidad: por debajo, todo son llamadas a createElement. Para entenderlo, escribe la cabecera principal de una landing (un hero) sin usar ninguna etiqueta JSX.

Qué tienes que hacer

  1. Crea src/ejercicios/ex13/Hero.jsx con un componente Hero que no tenga ninguna etiqueta JSX dentro.
  2. Debe contener un contenedor con: un título «Lanza tu proyecto», un párrafo «Una landing rápida con React.» y un enlace «Empezar» que apunte a #planes.
  3. Dale las clases de estilo desde las propiedades de cada elemento.
  4. Muéstralo desde App.jsx.

Cómo debe verse. Todo centrado y en una columna estrecha, con bastante espacio por encima. El título muy grande y en negrita; el párrafo en gris, con un poco de separación; el enlace con forma de píldora azul, texto blanco en seminegrita y separado del párrafo.

      Lanza tu proyecto        ← muy grande, negrita
  Una landing rápida con React.   ← gris
          ( Empezar )              ← píldora azul

📖 Teoría: React sin JSX

// src/ejercicios/ex13/Hero.jsx
import { createElement } from "react";

export default function Hero() {
    return createElement(
        "div",
        { className: "mx-auto mt-16 max-w-xl text-center" },

        createElement("p", { className: "mt-3 text-gray-500" }, "Una landing rápida con React."),
        createElement(
            "a",

            "Empezar",
        ),
    );
}

5 · 🟢 De desarrollo a producción

✅ Completado ▼

Una landing no se publica con el servidor de desarrollo, sino con una versión ya preparada. Vas a generarla, mirarla por dentro y comprobar que no se comporta igual que en desarrollo.

Qué tienes que hacer

  1. En App.jsx escribe un mensaje por la consola del navegador cada vez que se pinta el componente.
  2. Con el servidor de desarrollo arrancado, abre la consola y apunta cuántas veces sale el mensaje al cargar la página.
  3. Genera la versión de producción del proyecto y abre la carpeta dist/: apunta qué archivos hay y qué tienen de raro los nombres de los de dentro de assets/.
  4. Arranca el servidor que sirve esa versión (no el de desarrollo), ábrela en el navegador y vuelve a contar los mensajes.
  5. Escribe en src/ejercicios/ex15/notas.md qué has visto y a qué crees que se debe la diferencia.

Cómo debe verse. No hay nada que ver en la página: el resultado es el archivo de notas, con tus observaciones (cuántas veces sale el mensaje en cada caso y qué hay dentro de dist/).

Desarrollo:  mensaje ×2
Producción:  mensaje ×1
dist/  →  index.html + assets/ (con un código en el nombre)

📖 Teoría: Entorno con Vite

// terminal
pnpm build     # genera dist/
pnpm preview   # sirve la versión de producción
// src/ejercicios/ex15/notas.md
En desarrollo el mensaje sale dos veces: main.jsx envuelve la app en StrictMode, que
en desarrollo ejecuta los componentes dos veces para detectar errores. En producción
sale una sola vez, porque StrictMode no actúa.

dist/ contiene index.html y la carpeta assets/ con el JavaScript y el CSS ya
empaquetados. Los nombres llevan un código (hash) que cambia cuando cambia el
contenido, para que el navegador no use una copia vieja guardada en caché.

3 · 🟡 Banner de oferta con días restantes

⏳ Pendiente ▼

Muchas landings muestran una franja superior con una oferta que caduca. El texto depende de cuántos días quedan, y eso se calcula con JavaScript.

Qué tienes que hacer

  1. Crea src/ejercicios/ex23/BannerOferta.jsx con un componente BannerOferta.
  2. Dentro, guarda la fecha en que termina la oferta, escrita como texto con formato «2026-12-31».
  3. Calcula cuántos días faltan desde hoy hasta esa fecha, redondeando hacia arriba.
  4. El texto debe ser: «Quedan N días de oferta» si faltan 2 o más; «¡Último día de oferta!» si falta 1; «La oferta ha terminado» si ya pasó.
  5. Comprueba los tres casos cambiando la fecha, y muéstralo desde App.jsx.

Cómo debe verse. Una franja a todo lo ancho en la parte de arriba, con fondo ámbar, texto centrado, en seminegrita y con espacio interior arriba y abajo.

¡Último día de oferta!
La oferta ha terminado

📖 Teoría: JSX con llaves

// src/ejercicios/ex23/BannerOferta.jsx
function textoRestante(fechaFin) {
    const msPorDia = 1000 * 60 * 60 * 24;
    const dias = Math.ceil((new Date(fechaFin) - new Date()) / msPorDia);

    if (dias <= 0) return "La oferta ha terminado";
    if (dias === 1) return "¡Último día de oferta!";
    return `Quedan ${dias} días de oferta`;
}

export default function BannerOferta() {
    const fechaFin = "2026-12-31";

    return (
        <div className="bg-amber-300 py-2 text-center font-semibold text-amber-950">
            {textoRestante(fechaFin)}
        </div>
    );
}

// src/ejercicios/ex25/Barra.jsx
function colorPara(valor) {
    if (valor < 30) return "#ef4444";
    if (valor < 70) return "#f59e0b";
    return "#22c55e";
}

export default function Barra({ nombre, nivel }) {
    const valor = Math.min(100, Math.max(0, nivel));

    return (
        <div className="mb-3">
            <p className="text-sm font-semibold text-gray-700">{nombre}</p>
            <div className="flex items-center gap-3">
                <div className="h-3 flex-1 overflow-hidden rounded-full bg-gray-200">
                    <div
                        className="h-full rounded-full"
                        style={{ width: `${valor}%`, backgroundColor: colorPara(valor) }}
                    />
                </div>
                <span className="w-12 text-sm text-gray-600">{valor} %</span>
            </div>
        </div>
    );
}

2 · 🟢 Rejilla de características responsive

⏳ Pendiente ▼

La sección de «características» de una landing es una rejilla de tarjetas que se reorganiza según el ancho de la pantalla. Se diseña primero para el móvil.

Qué tienes que hacer

  1. Crea src/ejercicios/ex52/Caracteristica.jsx. Recibe icono (un emoji), titulo y texto.
  2. Crea Ex52.jsx con seis características (por ejemplo: ⚡ Rápido, 🔒 Seguro, 📱 Móvil primero, 🎨 Personalizable, 🔍 Buscable, 🌍 Accesible), cada una con una frase corta.
  3. Muéstralo desde App.jsx, empezando por el diseño de móvil.

Cómo debe verse. En móvil, una tarjeta debajo de otra; a partir de una pantalla pequeña, dos columnas; a partir de una pantalla grande, tres. Cada tarjeta con borde fino, esquinas bien redondeadas y espacio interior. El emoji grande; el título en seminegrita; el texto en gris. Al pasar el ratón, la tarjeta sube un poco y aparece una sombra más marcada, con una animación suave.

móvil:    [⚡] / [🔒] / [📱] / …
pequeña:  [⚡][🔒] / [📱][🎨] / …
grande:   [⚡][🔒][📱] / [🎨][🔍][🌍]

📖 Teoría: Tailwind en React

3 · 🟡 Insignias de producto

⏳ Pendiente ▼

En una tienda o en una lista de planes aparecen pequeñas insignias que cambian de color según el estado. Vas a hacer una cuyo color depende de un dato.

Qué tienes que hacer

  1. Crea src/ejercicios/ex53/Insignia.jsx. Recibe un dato tipo, que solo puede valer "nuevo", "oferta" o "agotado".
  2. El texto que se ve debe llevar mayúscula inicial: «Nuevo», «Oferta», «Agotado».
  3. Crea Ex53.jsx que muestre las tres insignias, una al lado de otra, y muéstralo desde App.jsx.
  4. Comprueba en el navegador que las tres tienen su color. Si alguna sale sin color, revisa cómo escribes las clases.

Cómo debe verse. Cada insignia es una píldora (esquinas totalmente redondeadas), con relleno pequeño y letra pequeña en seminegrita. «Nuevo» con fondo verde muy suave y texto verde oscuro; «Oferta» con fondo rojo suave y texto rojo oscuro; «Agotado» con fondo gris claro y texto gris oscuro. Las tres en una fila, con un pequeño espacio entre ellas.

[ Nuevo ]  [ Oferta ]  [ Agotado ]
  verde       rojo        gris

4 · 🟡 Tarjeta de plan con variantes

⏳ Pendiente ▼

Una tarjeta de plan puede ser «destacada», «popular» y estar «agotada», y esas variantes se suman. Hay que combinarlas sin que el código se vuelva un lío.

Qué tienes que hacer

  1. Crea src/ejercicios/ex54/PlanVariantes.jsx. Recibe nombre, precio y tres datos que son verdadero o falso: destacado, popular y agotado. Los tres son opcionales.
  2. Crea Ex54.jsx con cuatro tarjetas: una sin ninguna variante, una destacada, una destacada y popular, y una agotada.
  3. Muéstralo desde App.jsx.

Cómo debe verse. La tarjeta base tiene borde fino gris, esquinas redondeadas y relleno. «Destacado»: fondo ámbar muy suave. «Popular»: un aro azul alrededor de la tarjeta. «Agotado»: la tarjeta entera medio transparente. Las variantes se pueden sumar (destacado y popular a la vez). Las cuatro tarjetas van en columna, con separación entre ellas.

PlanVariantes nombre="Básico" precio={9}                  → base
PlanVariantes … destacado                             → fondo ámbar
PlanVariantes … destacado popular                     → fondo ámbar + aro azul
PlanVariantes … agotado                               → medio transparente

📖 Teoría: CSS en React (sección clsx)

// terminal
pnpm add clsx
// src/ejercicios/ex54/PlanVariantes.jsx
import clsx from "clsx";

export default function PlanVariantes({ nombre, precio, destacado, popular, agotado }) {
    return (
        <article
            className={clsx(
                "rounded-lg border border-gray-200 p-4",

                popular && "ring-2 ring-blue-500",
                agotado && "opacity-50",
            )}
        >
            <h3 className="font-semibold text-gray-900">{nombre}</h3>
            <p className="text-gray-500">{precio} €/mes</p>
        </article>
    );
}

            <PlanVariantes nombre="Pro" precio={19} destacado={true} />
            <PlanVariantes nombre="Equipo" precio={29} destacado={true} popular={true} />

5 · 🟡 Dos tarjetas, mismas clases

⏳ Pendiente ▼

Cuando dos componentes usan el mismo nombre de clase en su CSS, no deberían pisarse. Aquí lo compruebas con dos tarjetas de una landing.

Qué tienes que hacer

  1. Crea dos componentes en src/ejercicios/ex55/: TarjetaPlan (recibe nombre, precio y destacada, opcional) y TarjetaTestimonio (recibe autor y texto).
  2. Cada uno tiene su propio archivo de estilos, y los dos usan las mismas clases: tarjeta y titulo. Además, TarjetaPlan tiene una clase destacada que se suma a tarjeta solo cuando recibe ese dato.
  3. Crea Ex55.jsx con una TarjetaPlan destacada y una TarjetaTestimonio, y muéstralo desde App.jsx.
  4. Comprueba que los títulos de las dos tarjetas son distintos entre sí aunque la clase se llame igual. Mira el HTML en las herramientas de desarrollo y fíjate en el nombre de la clase.

Cómo debe verse. La tarjeta de plan: borde fino gris, esquinas redondeadas y relleno; título en azul oscuro de letra grande. Cuando es destacada, el borde pasa a dorado y el fondo a un amarillo muy pálido. La tarjeta de testimonio: fondo verde muy pálido con borde verde claro; título en verde oscuro, más pequeño y todo en mayúsculas. Las dos, una debajo de la otra.

Plan Pro                 → azul, grande, fondo amarillo pálido
19 €/mes

LUCÍA PÉREZ              → verde, pequeño, mayúsculas
«Nos cambió la forma de trabajar.»
