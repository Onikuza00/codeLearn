🔥 Examen Final CSS — SaaSPro

Contexto: Landing page completa para un SaaS de productividad. 4 secciones + formulario + header/footer. Este examen cubre todo lo trabajado: Flexbox, Grid, BEM, Mobile First, :has(), Container Queries, variables, clamp(), formularios, :focus-visible, transiciones y prefers-reduced-motion.

Tiempo estimado: 50–60 min.

Reglas: const por defecto, let solo si reasignas. Nada de var. Early returns. Sin IA, sin copiar.

Archivos: saaspro.html + saaspro.css + root.css (variables). Todo desde cero.

🔥 4 secciones + formulario ⏱ 50–60 min 🎯 Todas las secciones para aprobar 📁 saaspro.html + saaspro.css

1 — Header Flexbox BEM

Header fijo con logo, navegación y CTA.
  • Logo a la izquierda, nav centrado, botón CTA a la derecha con display: flex; justify-content: space-between; align-items: center;.
  • Header con position: sticky; top: 0; y z-index para que flote sobre el contenido.
  • Fondo semi-transparente con backdrop-filter: blur() o color sólido con opacidad.
  • Enlaces del nav con :focus-visible.
  • Mobile: nav se oculta, solo quedan logo + CTA + un ☰ (hamburguesa puramente visual, sin JS).
  • Desktop (≥ 768px): nav visible completo.
  • BEM estricto: todo bajo bloque .header.

2 — Hero Flexbox clamp()

Sección principal con llamado a la acción.
  • min-height: 80vh (en mobile que ocupe al menos 70vh).
  • Flexbox centrado en ambos ejes.
  • Fondo con gradiente (linear-gradient), que se vea bien en mobile y desktop.
  • Título con clamp() para tamaño fluido.
  • Descripción con max-width para que no sea demasiado ancha en desktop.
  • CTA con transition en hover (cambio de color, escala o sombra).
  • prefers-reduced-motion para desactivar transiciones si el usuario lo prefiere.

3 — Features Grid :has()

Cuadrícula de 6 tarjetas con efecto hover.
  • Grid responsive con repeat(auto-fit, minmax(280px, 1fr)).
  • 6 <article class="feature-card"> con icono, título y descripción.
  • Efecto :has(): al hacer hover sobre una card, las demás se atenúan: 
    .features:has(.feature-card:hover) .feature-card:not(:hover) {
  opacity: 0.6;
  filter: grayscale(0.3);
}
  • Cada card con transition suave en opacity y filter.
  • BEM consistente: todo bajo bloque .feature-card.
  • Sin media queries para el grid (el auto-fit ya lo hace responsive).

4 — Pricing Grid areas CQ :has()

Tres planes en grid con plan destacado y Container Queries.
  • grid-template-areas para los 3 planes.
  • Mobile: los 3 planes en una columna (stacked).
  • Desktop (≥ 768px): 3 columnas, el plan del medio (Popular) un poco más grande o elevado (transform: scale(1.05)).
  • El plan "Popular" se detecta con :has(.pricing__badge) para darle estilo diferenciado (borde de otro color, sombra más grande).
  • Container Queries: cada .pricing__card tiene container-type: inline-size. Dentro, un breakpoint a 250px cambia el padding o layout interno de la card.
  • Transiciones en hover de las cards.
  • :focus-visible en los botones CTA de cada plan.
  • BEM estricto: todo bajo bloque .pricing.

5 — Contacto Formulario :has()

Formulario de contacto completo con validación visual.
  • Campos: Nombre (text), Email (email), Asunto (select con 3 opciones), Mensaje (textarea).
  • Todos los campos requeridos (required).
  • Labels sobre los inputs (no placeholder como label).
  • Inputs y textarea con :focus-visible y transition en el borde.
  • :has() para validación (opcional pero suma): si un campo :invalid está dentro del form, mostrar un mensaje o borde rojo: 
    .contact__form:has(:invalid) .contact__error {
  display: block;
}
  • Botón "Enviar" con hover transition.
  • Form responsive: en mobile los campos apilados, en desktop el nombre y email pueden ir en una fila con grid de 2 columnas.

6 — Footer Flexbox

Footer simple con enlaces y copyright.
  • Flexbox o grid simple.
  • Enlaces de navegación (4) + copyright.
  • Mobile: centrado, apilado.
  • Desktop: enlaces en fila, copyright a la derecha o segunda línea.
